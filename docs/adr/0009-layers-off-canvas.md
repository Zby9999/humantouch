# 挪出画布的图层跨轮次保留

设计师可以把图层从画布里拖到画布之外的空白处，像在 Framer、Figma 中那样把元素"放一边"，想清楚再放回。这些图层不属于任何一轮：落地、刷新、重新冻结都不会清掉它们，只有设计师手动删除或运行 `remove` 时才清除。这是 ADR 0001"一轮只对应一张画布"的例外。

挪出画布在页面上等于删除：Agent 落地时从源码中删掉它。为了日后能原样放回，挪出时保存两样东西：固化了全部样式的外观（原来的类和样式规则之后可能已不存在），以及它当时的源码片段与位置。拖回画布时是一次插入，改动说明附上源码片段，由 Agent 放回。图层在画布外时可以照常编辑，但不产生改动；拖回时这些编辑作为插入的一部分写进改动单。画布外的图层不单独命名，在图层树中与画布并列显示，与 Framer 一致。

同一轮内挪出、在画布外没有编辑过的图层是例外：它的代码还在，原图层也还在画布上（隐藏），拖回时撤掉那条删除——拖回原位置时两条改动相互抵消，拖到别处则记成一次移动，Agent 移动代码比删掉再按片段重写更不易出错。在画布外编辑过、上一轮挪出、或按住 ⌥ 挪出的副本，拖回时都是插入：画布上用固化的外观（原来的类不恢复），所见即画布外所见；同一轮内的那条删除保留，改动说明让 Agent 移动代码而不是删掉重写。

在空白处按 F、T 新建的 Frame 和文字图层也是画布外的图层（ticket 106，2026-11-08）：没有来处，不产生改动，拖回时等于在那里新建，和直接在画布上新建一样。它们不是新页面，画布仍是一轮一张。做法（ticket 106 开线时代定）：它由自己的编辑器新建，自己的改动从这条新建开始；拖回时把这些改动按第一次做的顺序、用现在的值在画布上再做一遍，所以改动单和改动说明就是直接在画布上画出来的那些，不写成拖回、不附外观和源码片段。新建那条改动记着它在画布外的样子（Agent 看不到），撤掉这条或放弃一轮时它回到画布外，和拖回的挪出图层一样。往画布外的图层里拖进拖出（ticket 108，规则开线时代定，待设计师确认）：每个画布外的图层是一张单独的小页面，图层在页面之间搬动，来处跟着它走。画布上的图层拖进画布外的 Frame 等于挪出画布，页面上是删除；在那张小页面里记成一个「从别处来」的图层（它自己的改动里一条 `putBack`，带着来处），⌥ 是复制。原则是：凡是这一轮里代码还在源码中的（这一轮从画布上挪出、没再编辑过），拖回时 Agent 拿到的是移动这段代码，不是删掉重写；其余照上一段，是插入，附源码片段和固化的外观。具体是：空白处新建的 Frame 拖回时照它自己的改动在画布上重新新建，里面这一轮从画布拖进来、没编辑过的图层先撤掉删除、回到原处，再移进新建的 Frame（改动单是新建和一次移动，好像设计师在页面上画 Frame 时它还在）；挪出的图层里拖进了别的图层，它算编辑过，拖回是插入，拖进来的在「Edited off the canvas」里逐条写出，代码这一轮还在的让 Agent 挪进来；从这一轮挪出的图层里拖出一部分拖回，这部分是插入并记着写在哪个图层的代码里（`origin.inside`），说明让 Agent 先把它的代码挪过来再删外面那层，外面那层算编辑过；之前在别处做的编辑跟着它走（`origin.edits`），拖回时一起列出；拖进来的图层里又有图层被挪出来、留在外面那层里的，它和拖出的一部分一样，记着写在拖进来那层的代码里，跟着外面那层一起拖回或搬走，拖进来那层算编辑过。拖进别的图层、随那层插回页面的图层，页面核对它的删除只看它原来的位置：代码挪进那层的新代码里不算没删。在改动列表里撤掉空白处新建的 Frame 的新建时，跟着它撤掉删除、回到原处的那些图层不再留在回到画布外的 Frame 里。拖到空白处、在画布外的图层之间搬动都不产生改动。

## Considered Options

- **挪出画布不影响代码，画布外只放副本**：与"挪出"的直觉不符，设计师还得再删一次原图层。已否决。
- **画布外的图层随一轮结束清除**：设计师放一边的东西会在落地后消失，失去"暂存"的意义。已否决。
