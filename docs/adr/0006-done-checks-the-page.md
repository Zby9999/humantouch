# `done` 时在真实页面上核对这一条改动

Agent 每运行一次 `done <编号>`，编辑层就撤下这条改动的预览，在真实页面上读出这个图层这项属性的值，与改后值比较，结果回到 `done` 的输出里。没显示出来时，Agent 当场就知道，可以去查是什么盖住了它的修改（例如不在 CSS layer 里的规则压过 Tailwind 的类），而不是在报告里写下一个错的 ✓。这修改了 ADR 0004 中"不做落地后自动核对"的决定：当初认为 Agent 自己报告就够了，但 Agent 看不到页面，没生效的修改它根本不知道；改动预览又用 `!important` 显示改动，会在落地前盖住这类问题。

核对只读改动单里这一条属性，不重新测量整页，也不在编辑层界面上标出不一致。没有打开页面时 `done` 照常记进度，只说明没能核对。

## Considered Options

- **维持 ADR 0004，只靠 Agent 报告**：Agent 无从得知修改被别的样式盖住，报告不可信，而"✓ 已落地"正是一轮交付给设计师的东西。已否决。
- **`finish` 时一次性核对所有改动**：发现问题时 Agent 已经离开那条改动的上下文，也不清楚是哪一步出的问题。已否决。
- **编辑层在界面上标出不一致的改动**：设计师撤下预览后本来就能看到真实页面，多一套标记是 ADR 0004 所说的冗余。已否决。

## Consequences

- ADR 0013 起，认领之后代码一变页面就核对，不再只在 `done` 时核对；`done` 是 Agent 拿结果的地方，可以一次报多条。
- ticket 77 起，「只改这一处」的样式改动还要看组件在当前页面上的其他使用处：认领时页面记下它们这项属性的值，之后变了，这条改动就算没落地，`done` 说出改到了哪个使用处、从多少变成了多少。核对仍只读改动单里这一条属性，不比其他样式。
