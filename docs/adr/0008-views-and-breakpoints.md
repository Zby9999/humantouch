# 视图复用冻结副本，断点编辑按 Framer 的方式进入第一版

编辑模式中并排显示桌面、平板、手机三个视图，让设计师改一处时立刻看到其他宽度有没有被挤坏，并直接在小屏视图里做断点改动。三个视图复用同一份冻结副本，分别放进不同宽度的 iframe：写在 CSS 里的响应式规则（媒体查询、Tailwind 断点）自动生效，冻结时的页面状态（例如打开的弹窗）保留，视图瞬间出现。代价是靠 JS 判断窗口宽度的响应式不会重新运行，视图上标注"仅反映 CSS 响应式"。

断点编辑沿用 Framer 的模型：桌面视图是主视图，在其中的改动作用于所有断点，除非某个断点已经单独改过该属性；在平板或手机视图中的样式与布局改动只在该断点生效，属性面板标出被单独改过的属性并可重置。结构性改动（换容器、合成或解散 Stack、新建、删除、复制、挪出或拖回画布）始终作用于所有视图；某个断点不需要的图层用"在此断点隐藏"表达。改动单记录每条改动的断点（宽度范围），Agent 按项目已有的断点写法落地。

桌面视图就是画布，编辑命令都改在它上面；其他视图是跟随它的逐节点副本，视图之间的差异只来自 iframe 宽度与 CSS。样式与布局改动因此不写在元素上，而是写进画布上的一张样式表：桌面视图里的改动是基础规则，作用于所有断点；平板、手机等视图里的改动放进该视图宽度范围对应的 `@media` 规则，排在基础规则之后，压过它。这些规则在编辑层自己的 CSS layer 里，这个 layer 排在页面所有 layer 之前，规则都带 `!important`，所以压过页面原有的任何样式。每个视图按自己的宽度、播放按窗口宽度，都由浏览器的媒体查询自然显示该显示的改动，和 Agent 落地后的代码是同一种生效方式。

## Considered Options

- **第一版只看不改，断点编辑留到以后**：成本更低，但设计师发现手机版被挤坏后仍要回到对话框描述。为第一版的雄心目标否决。
- **在对应宽度下重新加载页面再冻结**：JS 响应式正确，但冻结时的页面状态丢失、进入编辑模式变慢。已否决。
- **允许按断点做结构性改动**：CSS 无法单独表达，Agent 只能为每个断点写不同的结构，代码会膨胀且容易出错。已否决。
- **每个视图贴一层覆盖，断点改动只写在该视图的副本上**：视图副本逐节点跟随画布，画布一变就会冲掉副本上的覆盖；播放画布时又得手工模拟媒体查询，判断哪些覆盖在当前宽度生效；而且与 Agent 落地后的代码靠媒体查询生效的机制不一致，看到的和落地的可能不同。已否决。

## Consequences

- 进入编辑模式、拖拽和改数值时，旁边的视图比正在工作的视图晚一些跟上，最终一致（ADR 0011，2026-10-30 起）。
- `done` 核对断点改动时，需要在该断点宽度下的真实页面上读取（例如在对应宽度的隐藏 iframe 中加载同一页面）；读不到时结果为"没能核对"。
- 视图的宽度范围尽量对齐项目已有的断点（例如 Tailwind 的 md、lg），使 Agent 能直接用项目的断点写法落地。读不到项目断点时按视图宽度划分：每个视图代表从它的宽度到下一个更宽视图之前的范围，最窄的视图从 0 起；与桌面视图同宽的视图就是桌面视图。
- 改动记录在它所在的断点上，记下的是当时的宽度范围；之后增删视图或桌面宽度变了，都不会改写已有改动的范围。
- 读到项目断点时，视图的范围按项目断点取整，和 Framer 一样：项目断点把宽度切成若干段，落在桌面视图所在段里（或与桌面同宽）的视图就是桌面视图；其他视图代表自己宽度所在的段（同段的视图共享），并向上延伸，覆盖没有视图的段，直到下一个更宽视图所在段的下沿。桌面段以下，最宽的视图延伸到桌面段的下沿，最窄的向下延伸到 0，所以这些宽度都归它下面最近的视图，不会只拿到桌面改动。桌面段以上，比桌面更宽的视图同样代表自己所在的段并向上延伸，最宽的没有上界；桌面段与第一个更宽视图之间没有视图的段归桌面视图（基础样式）。例如默认 Tailwind、桌面 1440 时，1920 的视图是 `2xl:`。范围随视图集合和桌面宽度变化。（2026-10-29 起；此前每个视图只代表自己所在的那一段，默认 Tailwind 下 640–767、1024–1279 没有视图代表。）
- 已有的断点改动在任何宽度落在其范围内的视图中都被认出、标出、可重置；在那里改同一属性时，改动在视图范围之内就更新这条改动，不新建；超出视图范围时拆分：旧改动只保留视图范围以外的部分（原值，一段或两段），视图范围内记新值，一次撤销恢复原样；在视图里重置同理，只清掉视图范围内的部分。新建的范围会让开该属性已有的其他断点范围，所以同一属性的断点范围不重叠。桌面视图里的改动仍是基础样式，不受拆分影响。
- 在平板或手机视图中，把 Frame 流式布局里的图层拖到同一个 Frame 的空白处或微移，是在该断点把它变成自由定位（定位方式、X / Y 与当时的尺寸都只写进该断点的规则），记为一条只在该断点生效的样式改动，可重置回流式；之后在该断点改它的 X / Y 也更新这一条。Frame 在该断点没有定位时，也只在该断点成为它的定位参照（`position: relative`）。换容器仍是结构性改动，作用于所有视图：图层在断点上的自由定位随之去掉，在新容器里按落点在所有宽度放置。
