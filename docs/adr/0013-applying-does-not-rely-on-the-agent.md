# 落地不靠 Agent 守流程：以页面为准，没落地的改动不丢

Agent 不由我们控制：它可能不加载 Skill、跳过或攒着 `done`、中途停下，也可能没认领就改代码。所以一轮的结果不再依赖 Agent 照流程走：

- **以页面为准**：认领之后，代码一变，页面就核对还没显示的改动。进度环和一轮的结果按页面核对算；`done` 是 Agent 拿核对结果的地方，可以一次报多条。页面看不出来的改动（复制、换容器、生成说明等）仍按 `done` 算；同一轮新建的图层，ticket 76 起页面按位置找到并核对；改现有图层的字，ticket 90 起页面按源码标记找到图层、比它读出来的字。
- **Skill 只是入口**：流程和每种改动的写法都在命令的输出里，只跑了 `claim` 的 Agent 也能走对。
- **没认领就改代码**：编辑模式中代码在变、却没有 Agent 认领时，页面看到画布上的某条改动显示了出来，就当作 Agent 认领了，照常锁定、核对；不是在落地设计师的改动，就不打断编辑：页面看起来没变什么都不做，页面变了就重新冻结或用 toast 提醒（ticket 78，取代原来的「先暂停编辑，提示设计师」）。
- **Agent 停住时**：切换按钮直接提示设计师。设计师结束一轮时，没落地的改动留到下一轮，不再随画布丢掉。

这修改了 ADR 0005（进度环靠 Agent 每条报一次；手动解锁丢弃画布）和 ADR 0006（只在 `done` 时核对）。每一项都要用测量台测出前后数字（docs/goals.md 的 Robust 一节）：Agent 少走一步省下的时间，不能被编辑层多出来的负担吃掉。

## Considered Options

- **维持「每条改完立刻 `done`」，靠 Skill 约束**：每条多一次工具调用；Agent 不照做时，进度环停住、改动没有核对，设计师看不出来。已否决。
- **`finish` 时一次性核对**（ADR 0006 否决过）：仍不采用。页面在代码变化时就核对，Agent 什么时候问都拿到当时的结果；攒到最后再问只是晚知道，不是没核对。
- **用 Agent 专属的 hooks 强制流程**（例如 Agent 结束前检查是否跑了 `finish`）：要往项目里写一份只对一家 Agent 有效的配置，换一家就失效。先看测量台的数据，哪家确实不守流程，再针对它加。
- **设计师结束一轮时丢掉画布**（原来的做法）：Agent 中断的代价全落在设计师身上，没落地的改动要重做。已否决。
- **留下的改动重新应用到按新代码冻结的画布上**（ticket 68 原来的做法）：要为每种改动写一遍在新画布上重做的逻辑，还要处理找不到图层的改动；换来的只是画布反映代码现状，而预览模式本来就显示代码现状。设计师 2026-11-01 否决，改为回到同一张画布。

## Consequences

- 认领期间，页面每次热更新都要核对还没显示的改动，并在页面窗口的宽度上再看一遍已经显示的（ticket 64 起：之后的改动可能把它弄掉，进度环不能多算）。这是加在设计师自己页面上的负担，要在大页面上测，不能出现 long task。
- `finish` 前页面把能核对的改动按最后一次改动再看一遍（ticket 64）。这不是上面否决的「`finish` 时一次性核对」：一轮当中照样随代码变化核对，`finish` 只是补看最后一眼。
- 进度环可能比 Agent 的 `done` 走得快：页面先看到了改动。
- 留到下一轮的改动回到同一张画布上（设计师 2026-11-01 定，ticket 68；取代原来的「重新应用到按新代码冻结的画布上，找不到对应图层的在改动列表里标出来」）。设计师结束一轮、或 Agent `finish` 时还有没落地的改动，画布不丢（ADR 0019 起只限没有 `finish` 就结束的一轮：Agent `finish` 的一轮全部归档，下次重新冻结）：已落地的改动照常归档，留在画布上当底，撤销和改动列表都撤不了它们（要退回代码用 `last`）；没落地的留在改动单里，按原来的顺序从 1 重新编号，新改的接在后面；它们都落地或都放弃之后，进入编辑模式才按新代码重新冻结。「改前」由页面在认领时按代码现状重新读，页面已经显示的算已落地；页面替 Agent 认领时（ticket 78）不重读，保留上一轮的改前，因为那时 Agent 的代码已经在页面上，还没显示的改动，页面分不出显示的是改前的值还是 Agent 改到一半的值。理由：Agent 是在源码里找图层，不靠画布；重新冻结只是为了让画布反映代码现状，这一点预览模式已经能看到，不值得为它写一个按每种改动重做画布的模块，再处理一串「找不到图层」的情况。代价是画布上看到的是上一轮冻结时的页面加上已落地的改动，不是代码现状（ticket 141 起，之后有人只手改了样式的，回到画布时换上页面现在的样式表；结构也改了的，画布不动，提示设计师；ADR 0018）；上一轮 Agent 新建的图层在页面上还找不到，核对说没能核对。
- 页面看到一条改动在没认领时显示了出来，就当作 Agent 认领了，照常锁定、走进度环：ADR 0005 的锁不再只靠 `claim` 触发（设计师 2026-11-01 定，ticket 78）。编辑时代码变了、但不是在落地设计师的改动，不暂停编辑：页面看起来没变就什么都不做；页面变了，画布上还没有改动就自动重新冻结，有改动就用 toast 提醒，由设计师选择放弃改动、更新画布。
- 「只改这一处」的改动漏到组件的其他使用处，原来只靠 `claim` 说明里的一句话让 Agent 自觉，页面不兜底；ticket 77 起页面也看（设计师 2026-11-01 定，只做简单的版本）：认领时记下同一组件在当前页面上其他使用处这项属性的值，代码一变就比，变了算没落地，放 ⚠️，进度环不算。不在当前页面上的使用处、这一轮自己也改了这项属性的使用处、组件本身这一轮也改了这项属性时，不查。认领期间每次热更新多读的这些元素同样不能出现 long task。ticket 82 起，记下的值连同认领一起存进 `.03kind/`，认领期间刷新页面、认领后才打开页面接着用；页面替 Agent 认领时，用代码开始改动之前页面上的值。只属于这一轮，一轮结束就删。只写在某个断点上的漏改仍只在窗口宽度看（设计师 2026-11-02 定）。
