# 改动只在画布上看，不再叠到真实页面上

去掉改动预览。回到预览模式，页面就是代码现在的样子；要看改动后的样子，在编辑模式中点播放，画布按真实大小单独显示，不显示面板与选中框，也不能交互。这取代了 25、26、27 中"在真实页面上显示还没落地的改动"的做法，并简化 ADR 0006 的核对：页面上本来就没有预览，核对时不必先撤下。

改动预览只能叠样式、加标记，不能新建或挪动 React 管理的元素（ADR 0001），所以新建、复制、合成或解散 Stack、跨容器移动、改文字都显示不了，只能提示"落地后才能看到"。设计师看到的是一半改动，另一半要自己想象；又要分清页面上显示的是代码还是预览，落地期间还得逐条撤下预览。画布是冻结的副本，所有改动都在上面，按真实大小显示它就能看到全部改动，而真实页面始终只显示代码。

播放时画布不动、不能点：冻结时页面的脚本已经停了，动效也已跳到结束状态。要看某个界面状态（例如打开的弹窗）的改动，就先在预览模式中把页面操作到那个状态，再进入编辑模式。

## Considered Options

- **保留改动预览，补上改文字的预览，并列出看不到的改动**：结构类改动仍然看不到，页面上显示的是代码还是预览仍要分清，落地时撤下预览的机制也还在。已否决。
- **在真实页面上用编辑层自己画的覆盖层模拟新建的图层**：覆盖层不参与页面排版，其他图层不会让位，看到的效果是错的。已否决。
- **播放时保留交互（悬停、点击）**：画布上的脚本已停，点击不会有任何反应，只有 CSS 的悬停效果能生效，看起来像坏了。已否决。
