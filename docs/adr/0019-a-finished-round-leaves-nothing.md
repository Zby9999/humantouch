# Agent 交了报告的一轮，什么都不留

设计师 2026-11-13 定（ticket 164）。修订 ADR 0013。

## 背景

ADR 0013 定的是：一轮结束时，只要还有没落地的改动，画布就不丢。已落地的归档；没落地的留在改动单里，切换按钮上显示数字；下一轮回到同一张画布，等它们都落地或被放弃，才按新代码重新冻结。当时怕的是 Agent 中途停下，设计师的改动白做。

真实使用里，Agent 多半能把一轮走完：每条都看过，⚠️ 的也写了 Why 和 Instead，大多已按设计师的意思近似做了。留下的改动成了负担：设计师要单独清一轮，下一轮看到的还是上一轮冻结的页面，不是 Agent 改完的样子。

## 决定

按一轮怎么结束来分：

- **Agent 跑了 `finish`（交了报告）：** 这一轮的改动全部归档，✓ Applied、↪ Done differently、⚠️ Not shown 都一样，改动单清空，切换按钮上不留数字。下次进入编辑模式，按新代码重新冻结。⚠️ 的改动没有丢：报告里有，`npx humantouch last` 也列得出来，要退回代码照旧用 `last`。设计师想再试，就在新画布上重做，或在对话里让 Agent 再改。
- **一轮没有 `finish` 就结束了**（设计师点 End this round 或按住切换按钮，Agent 中途停下时）：照 ADR 0013，没落地的改动留到下一轮，回到同一张画布。

## 否决的做法

- **照旧，`finish` 之后也把 ⚠️ 留到下一轮：** 设计师多清一轮，画布还是旧页面。
- **不管怎么结束都清空：** Agent 中途停下时，没轮到的改动白做，正是 ADR 0013 要避免的。
- **`finish` 时只留 Instead 写「left as it was」的：** 要从 Agent 写的字判断它做没做，靠不住；设计师在报告里看得到这几条，自己决定要不要重做。

## 后果

- 同一张画布（ADR 0013 的「回到同一张画布」，ADR 0018 的样式跟上代码、结构不跟）只在一轮没有 `finish` 就结束时才有。
- Agent 真没做的 ⚠️ 改动（Instead 是「left as it was」），设计师要在新画布上重做一遍。
- Agent 跑了 `finish`、却跳过了几条改动的，这几条也随这一轮归档，只在报告的 ⚠️ 里。
