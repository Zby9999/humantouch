# 不做 MCP、没有发送按钮：改动单自动存进项目，Agent 靠 Skill 自己去取

编辑层不提供 MCP 服务，界面上也没有发送或复制按钮。改动单随编辑自动保存在项目目录中。设计师只需对 Agent 说一句"把我的设计改动落地"，Agent 通过项目里安装的 Skill 知道去哪里读改动单、怎么落地。目标是像 DialKit 一样极简，同时避免"复制粘贴"这种廉价的交互：没有需要配置的服务，也没有 Agent 兼容性差异，任何能读文件、改代码的 Agent 都能用。

同样出于极简，编辑层不做"落地后自动核对"：改动无法 1:1 落地时，由 Agent 在回复中按固定格式向设计师报告。（已由 ADR 0006 修改：`done` 时在真实页面上核对这一条改动，结果告诉 Agent。）

## Considered Options

- **MCP 拉取 + Agent 等待模式**：调研中多数同类工具采用的做法，可以自动开始落地，但需要每种 Agent 各自配置 MCP，违背"装得快、任何 Agent 都能用"的目标。已否决。
- **Send / Copy 按钮 + 剪贴板**（DialKit 的做法）：交互廉价、不够优雅，剪贴板也放不下截图。已否决。
- **编辑层逐条核对落地结果**：重新测量真实页面、标出不一致的改动。功能冗余，已否决。后来 ADR 0006 采用了其中一部分：只核对 `done` 的那一条，结果告诉 Agent，不在界面上标出。
