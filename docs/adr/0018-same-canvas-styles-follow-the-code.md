# 回到同一张画布时，样式跟上代码，结构不跟

设计师 2026-11-11 定（ticket 141），规划会话 2026-11-12 记成 ADR。修订 ADR 0001 和 0013。

## 背景

一轮还有改动没落地时，编辑模式会回到同一张画布（ADR 0001、0013）。这段时间里有人手改了代码，画布就和代码对不上，设计师又不知道为什么。

## 决定

先看代码，再看页面。指纹连同打指纹时代码的 git tree 一起记下；回到画布时代码还是那份（本地服务算一次 tree 对比，dev server 重启也算数），页面就当没变，不再比指纹，不提示，也不换样式。代码变了，或者看不出来（不在 git 仓库里、还没问到），才按页面指纹判断改了什么。指纹分两部分：结构（元素、类名、文字）和样式。

- **只改了样式：** 画布换上页面现在的样式表，留下的改动照旧。
- **结构也改了：** 画布不动，提示设计师先让 Agent 落地，或者放弃留下的改动。
- **Agent 落地这一轮带来的代码变化不算：** 一轮结束时有改动留下，就以那时的页面为准。

这样，ADR 0001 里「画布反映冻结时的页面」只对结构成立，样式跟着代码走。ADR 0013 说回到同一张画布的代价，有一部分就此解决。

## 否决的做法

- **结构变了也换样式：** 旧的 DOM 配新的 CSS，在 Tailwind 项目里会坏。
- **每次都重新冻结，再把改动重放上去：** ADR 0013 已经否决过。
- **从源码判断改了什么：** 分不出 JSX 里只改了样式的情况，也照顾不到 Next.js。代码只用来判断「变没变」，变了改了什么仍然看页面。
- **只看页面指纹：** 页面按时间画东西（几秒后出现的元素、按时间切换的内容），代码没变也会误报结构变了。

## 后果

- 代码没变时不看指纹，所以页面按时间画什么都不会误报。代码变了时指纹仍须稳定：时间、计数（连续数字和 AM/PM）、CSS Modules 和 next/font 类名里的 hash、元素顺序、动画写的属性都不算；交互状态、随机内容仍可能误报。
- 指纹存在 `.humantouch/page.json` 里，带着打指纹时代码的 git tree；一轮有改动留下结束时（Agent 落地的代码就此算进来）和放弃这一轮时删掉。文件读不出来就当没有，这一轮照旧。
- 有几种代码改动从指纹看不出来，画布既不提示，也不换样式（ticket 141 的风险）。
