# 改尺寸和移动都保留图层原来的定位方式

页面里自由定位的图层，有的按父容器的右边、下边摆（`right`、`bottom`），有的用 `translate(-50%)` 居中。编辑层改它们的尺寸、移动它们时，都保留原来的定位方式（GLOSSARY「定位方式」），不改成按左边、上边定位：按右边定位的改 `right` 的值，按下边定位的改 `bottom` 的值，居中的保持居中，只改大小或偏离中心多少，相当于 Figma 的 Right、Bottom、Center 约束。原因是画布同时显示三个宽度（ADR 0008）：在桌面视图里改一下右上角的标签，若悄悄改成按左边定位，平板、手机视图里它立刻离开右上角，而设计师并没有做这个决定。改尺寸由设计师 2026-11-01 定（ticket 75，已做），移动由设计师 2026-11-02 定（ticket 79）。

## Considered Options

- **一律改成按左边、上边定位**（75、79 之前的做法）：最简单，编辑层和改动单只认 `left` / `top`。但它改掉了页面原来的约束，窗口宽度一变，图层的位置就和原来不同，三个视图里马上看得出来。没有采用。
- **改成按左边、上边定位，但在改动说明里写明定位方式变了**：设计师和 Agent 都知道变了，图层在旁边的视图里仍然跑位。另外，改尺寸保留、移动不保留时，同一个图层先拖大再挪一下，就变回按左边定位，前后不一致。没有采用。
- **不改，只在 spec 里写明**：按右边定位的图层拖右边控制点时往左长，和指针方向相反。没有采用。

## Consequences

- 编辑层、改动单、改动说明和 `done` 都要认识 `right` / `bottom` 和居中，不只认 `left` / `top`。改动单里宽、高等改动记下图层的定位方式（`placedFrom`）。
- 定位方式按正在工作的那个视图读，写进那个视图对应的断点规则。`done` 在页面不按这条边定位的宽度不看 `right` / `bottom`（`placedOtherwiseAt`），否则会把和画布一样的结果报成「没有显示」。
- 75 定下的边界（设计师 2026-11-02 确认）：同时按左右两边定位的图层（`inset-x-0`，即 Figma 的 Left & Right）按左边处理；钉在窗口上的固定图层，上下方向按上边处理；原来是百分比的 `right` / `bottom` 改后写成 px，和 X / Y 一样。
- 移动居中的图层时，定位它的那一边保留它的百分比，只改多出来的 px（`left: calc(50% + 20px)`），`done` 在每个宽度按百分比算出该在的位置核对（ticket 79）。拖进另一个 Frame、在那里仍是自由定位，或复制时，定位方式跟着图层，按新的 Frame 算，和 Figma 一样（设计师 2026-11-02 定）；改动单的位置记下它（`Place.absolute.placed`）。
- 编辑层不提供设定约束的界面；父容器改尺寸时，子图层也不按约束跟着移动。这里只保留页面已有的定位方式。
