# 简单改动由编辑层直接写进源码，设计师按一下才写

第一版之后（ticket 115、116），改动列表里有一个按钮，把这一轮里「简单」的改动由编辑层直接写进源码，不等 Agent；其余的照旧留在改动单里交给 Agent。这推翻 ADR 0002 里「编辑层不直接改源码」的一部分。当时否决直接改源码，理由是要为每种技术栈写改写器、往源码里注入标记；现在源码标记、Tailwind 与 CSS 来源的识别都已经有了，只写最窄的一类改动，代价可控，省下的是简单改动也要等 Agent 几十秒。

简单改动只算写死在这个图层自己身上的值：图层自己的 JSX 里，className 字符串字面量中的 Tailwind 类（含断点前缀）；JSX 里写死的一段文字；只有这个图层在用的一条 CSS / CSS Modules 规则里的声明。值从变量、props、数据或 `cn()` 这类表达式里来的，结构性改动，实例上只作用于这个使用处的改动，都交给 Agent。拿不准时交给 Agent。

只在设计师按下按钮时写，不在每次改动时写。写入时不能有 Agent 正在落地（ADR 0005）。写进去的改动和 Agent 落地的一样，要在页面上核对（ADR 0006），照样归档，也能撤回；撤回的办法和 Agent 落地的一轮一致（`last`），细节由 ticket 115 定。

## Considered Options

- **每次改动都立刻写进源码**（Onlook 的做法）：连续拖数值时文件不停地改、页面不停地刷新，和冻结的画布、撤销都打架。设计师 2026-11-09 否决。
- **不做，全部交给 Agent**（ADR 0002 原来的做法）：简单改动也要等 Agent，路线图里已承诺要做。

## Consequences

- 一轮里的改动分两路：按钮写掉的那些归档，剩下的照 ADR 0013 留在同一张画布上交给 Agent，改动说明里不再有写掉的那些。
- 编辑层写源码只做最小的文字替换，不重新格式化文件；写法照 Agent 的写法规则（设计变量优先），写出来和一个守规矩的 Agent 写的一样。
- 认不出该写在哪里（文件在冻结后被改过、源码标记对不上）时不写，留给 Agent。
