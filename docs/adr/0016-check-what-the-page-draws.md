# 核对比页面画出来的样子：改动所在的宽度严格，其他宽度允许适配、不许破版

设计师 2026-11-11 定：唯一的真源是视觉，不是值怎么写。

## 依据

官网当天 10 轮、64 条改动，核对判「没显示」的有 19 条：

- 4 条画出来和画布一样，只是值的写法不同。0 的字间距读成 0%（ticket 142）；spread evenly 时主轴上的点 CSS 写不出来（ticket 145）。
- 15 条确实不一样，但都是设计师要的：
  - 7 条是设计师在对话里改了颜色；
  - 7 条是 Agent 在手机宽度上为了不撑破而保留原样；
  - 1 条是改的范围和本意不同。

问题有两面：

- 按值核对，会把「换一种写法、看起来一样」判成错。Agent 想用更合理的写法也会被罚，比如用 gap 代替 margin。
- 所有宽度都严格，能力弱一点的 Agent 照字面执行，会越改越差。比如照写 `w-[500px]`，手机上就出现横向滚动。

## 决定

**一、比画出来的效果。** 页面上读到的值和改后值对得上，照旧直接算显示了。对不上时，再比这条改动在页面上画出来的效果，一样就算显示了。

- 效果包括：图层和它里面各层的位置与尺寸、画出来的颜色、文字的宽度等，按属性取。
- Agent 写成什么样不管，只要画出来一样。
- 比的是这条改动的效果，不是整页截图。

**二、宽度分三档。**

1. **改动所在的宽度：严格。**
   - 桌面视图里的改动，看桌面视图的宽度，也就是页面窗口的宽度。
   - 断点上的改动，看它范围内的视图宽度。
   - 这里画出来必须一样。
2. **其他视图的宽度：允许适配。**
   - 桌面视图里的改动，默认在其他宽度也照改，但 Agent 可以为那个宽度做合理的适配。
   - 不一样时，核对说出那里画的是什么，不算没显示。`finish` 把它列在「有意不同」一栏，Agent 写明原因。
   - 断点上的改动，范围外照 ticket 104 要求不变。这一条照旧严格：Agent 漏了断点前缀、把桌面也改了，是改坏了设计师看过的地方，不是适配。
3. **任何宽度：不许破版。**
   - 破版指这一轮之前没有、现在有了的问题：页面出现横向滚动、图层被截断、图层比它的容器宽。
   - 出现了就算没显示。核对说出是哪条改动、在哪个宽度、怎么修，比如「只在 md 以上用 500，或者不超过容器」。

**三、报告分三栏。**

- ✓ 已落地。
- ↪ 有意不同：写原因。比如设计师在对话里改了主意，或者在其他宽度上做了适配。
- ⚠️ 没显示出来：写原因和做了什么。

严格的部分只有一个宽度，要求具体，能力弱的 Agent 也能照做。放开的部分有底线兜着，出了问题，给的是能照着改的说法。

## Considered Options

- **逐个修误报**（ticket 142、145 那样一个个加特例）：修一个冒一个，写法不同、看起来一样的情况没有尽头。否决。
- **整页截图逐像素比**：字体、图片、动画、实时数据都会带来噪声，而且说不出是哪条改动出的问题，Agent 无从下手。否决。
- **所有宽度都严格**（ADR 0008、ticket 64 以来的做法）：能力弱的 Agent 照字面写，越改越差。否决。
- **其他宽度完全不查**：Agent 把手机改坏了，没人知道。否决。

## Consequences

- 修订 ADR 0006：核对比的不再只是这项属性的值，值对不上时比画出来的效果。
- 修订 ADR 0008 的「桌面视图中的改动也在每个视图的宽度核对」：在其他视图宽度上只说出不同、守住不破版。
- ticket 104（断点改动的范围外不许变）不变。
- 现在看起来一样，不保证内容变了以后还一样。比如用 `justify-end` 代替很大的底部内边距，文字多一行时两者就不同。设计师接受这个代价：不在意代码怎么写（2026-11-11）。
- Skill 和 `finish` 的报告改成三栏，Skill 的用词保持英文。
- ticket 142、145 的特例，由「比画出来的效果」吸收。保不保留由实现决定。
- 以后（发布后）：设计师在桌面改完，如果某个视图在画布上已经被撑破，编辑时就在那个视图上提醒，让设计师当场决定那个宽度怎么改。这样 Agent 就不用猜。
