# 编辑发生在冻结的画布上，而不是活页面

页面中的元素由 React 管理，直接移动、重新嵌套真实元素会在下一次渲染时报错或被覆盖。因此编辑层分为预览模式和编辑模式：进入编辑模式时，把当前页面状态冻结为静态画布，所有拖拽、合成或解散 Stack、属性调整都在画布上进行，期间页面交互暂停。这与 Framer 的预览/画布切换一致。

## Considered Options

- **直接改活页面**：样式调整可行，但结构性改动（移动、重新嵌套、合成或解散 Stack）需要大量兼容处理，且页面重新渲染时改动会丢失。已否决。

## Consequences

- 一轮只对应一张画布：这一轮里来回切换预览和编辑，回到的始终是同一张画布；只有在没有未落地改动时，进入编辑模式才会重新冻结。一轮结束时还有没落地的改动，下一轮接着用这张画布，直到它们都落地或都放弃（ADR 0013，2026-11-01 起）。回到这张画布时，画布反映冻结时的页面只对结构成立：之后有人只手改了样式的，画布换上页面现在的样式表（ADR 0018）。这样避免了"跨页面"和"同一页面不同状态"的改动错位，代价是设计师若冻结前忘了把页面操作到目标状态，需要放弃本轮改动后重新冻结。画布保存在项目中，刷新浏览器可恢复。

- 画布上看不到悬停、动画等动态效果；设计师需先在预览模式中把页面操作到目标状态，再进入编辑模式。
