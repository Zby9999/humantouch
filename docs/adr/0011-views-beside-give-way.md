# 旁边的视图让正在工作的视图先跟手

大页面上（约 5000 个元素，三个视图并排）每个视图都要各自算样式、排版、绘制，三个视图在同一帧里跟上同一个变化，就达不到 docs/goals.md 的 Flex 指标。所以在三种交互里，旁边的视图让正在工作的视图先出画面，晚一些再跟上，最终三个视图一致。ADR 0008 中"其他视图是跟随画布的逐节点副本"仍然成立，只是在这三种情况下跟得晚；拖拽中的让位是每个视图各自显示的临时样式，不经过画布。三条都是设计师在 ticket 22 中定的（2026-10-29、2026-10-30）。

- **进入编辑模式**：桌面视图出现、进场动画开始的那一帧就算进入。平板、手机视图在 240ms 的进场动画期间复制和排版，这期间它们本来就隐藏；动画结束的那一帧三个视图都已显示。
- **拖拽**（设计师 2026-10-30 定，取代原来"拖拽中让位的图层在三个视图里都直接到位"）：在拖拽所在的视图里，让位的图层下一帧直接到位，不播滑开过渡，和减少动态效果时一样。另外两个视图里的让位等指针停下约 100ms（和连续改值同一个 `CATCH_UP_AFTER_MS`）后才到位，也是直接到位；指针一直在动时，它们不跟着放置位置变化，停下或松手后追上拖拽所在的视图。通常在桌面视图里拖，等的就是平板、手机视图；在平板或手机视图里拖时，等的是另外两个，桌面视图也在其中。
  - 被拖的图层本身仍在三个视图里跟着指针走，和原来一样；设计师定的只是让位。
  - 让位不是画布上的变化：每个视图各自显示，旁边的视图不随画布跟上，拖拽结束时三个视图一起放回原样。
  - 松手时三个视图一起到位：让位放回、图层移到放下的地方（画布上的结构变化，每个视图都在下一次绘制前跟上）。按 Esc 取消也是三个视图一起放回。拖到画布外时放置位置没有了，拖拽所在的视图里让位的图层当场回去，旁边的视图停下后回去。
  - 代码要读旁边某个视图时，那个视图先追上（`views.sync(view)`），和改数值一样。悬停框和 ⌥ 量距离在拖拽中不显示。
  - 松手后的结果、撤销、改动单都不变。
  - 拖拽还没松手时，撤销和重做的快捷键（⌘Z、⇧⌘Z，其他系统上的 Ctrl+Z、Ctrl+⇧Z、Ctrl+Y）不起作用；松手或按 Esc 取消之后照常可用（设计师 2026-10-30 定，ticket 61）。否则撤销在拖拽中改了某个让位元素的 style，松手或取消时让位放回会把整条 style 属性还原成拖拽开始时的样子，盖掉撤销的结果。
- **改数值**：正在工作的视图在下一帧显示新值。旁边的视图跟得晚，晚多少看是哪种改值：
  - **连续改值**（按住或连按方向键，包括在画布上微移图层；在数值图标或渐变色标上拖动）：旁边的视图不随每一步更新，停手约 100ms 后一次追上最新值。
  - **单次改值**（输入后回车或离开输入框、切换开关、选下拉项或按钮组、取色、选设计变量、添加或删除填充/描边/效果等一次提交的改值）：旁边的视图在画出正在工作的视图的那一帧之后跟上，即晚一帧（第三轮的做法），不等停手。单次改值紧跟在连续改值之后、旁边的视图还在等停手时，也是这样，一并追上到最新值。
  - 属性面板的输入告诉编辑器是哪一种（`SetOptions.step`），不确定的入口按单次。
  - 改值本身对画布做的一切都随这个值一起让路，包括一个图层第一次改值时给它的各实例加上编辑样式。这是第五轮（2026-10-30）在上面规则之内的实现调整，不是设计师新定的规则；原来这一步算"其他变化"，旁边的视图当场追上。
  - 画布上有其他变化，或者代码要读某个视图时，那个视图立即追上。

## Considered Options

- **改数值时旁边的视图每一步晚一帧跟上**：第三轮做过。按住方向键时，旁边视图追上的那一帧（Gap 约 54ms）和下一步挤在一起，正在工作的视图也被拖慢。改为连续改值停手后追上，单次改值仍晚一帧。
- **单次改值也等停手约 100ms 后追上**：第四轮做过，所有改值一样处理。设计师决定只有连续改值等停手，单次改值改回晚一帧（2026-10-30）。代价是单次改值后的第二帧和第三轮一样重。
- **旁边两个视图分两帧追上（平板一帧、手机下一帧）**：每帧的负担减半，但按住方向键时仍每一步都要重画旁边的视图，手机视图还要晚两帧。没有采用。
- **改数值期间降低画面细节，或属性面板的数值晚一帧刷新**：会改变设计师看到的东西。没有采用，改数值的目标改为 ≤ 2 帧（33ms）。
- **只在拖拽的视图里播放滑开过渡**：headless 下多数次达不到 60fps，退到三个视图都直接到位。
- **拖拽中三个视图的让位都直接到位**（第三轮到第五轮的做法）：放置位置每变一次，三个视图里让位的图层同时得到或去掉 `translate`，三个视图整片重画，有窗口 Chrome 下帧间隔 p95 两次都是 25ms，没过 20.8ms。设计师改为旁边的视图等指针停下（2026-10-30）。
- **拖拽开始时给兄弟图层设 `translate: 0 0`，让它们各自成层**：会改变层叠上下文，带 z-index 的子元素在拖拽中的遮挡关系可能变。已否决。

## Consequences

- 约 100ms 是对着 macOS 默认的按键重复间隔（约 83ms）选的：按住方向键时旁边的视图在中途不更新，松手后才跟上。按键重复调得比 100ms 还慢时，旁边的视图每一步都会追上一次。
- "晚一帧"是在画完那一帧之后的任务里追上；浏览器有时在这个任务之前先画下一帧，这时旁边的视图在再下一帧才显示，也就是改值后第三帧。
- 属性面板加新的改值入口时，按连续或单次分类：连续的要用 `asStep` 交出值，最后调 `editor.batch` 的地方要传 `stepOptions(continues)`，两处缺一处都按单次处理。
- 画布上用方向键微移（`editor.nudge`）每一次都算连续改值，和第四轮一样：微移自由摆放的图层时，旁边的视图停手后跟上。
- 代码要读旁边某个视图（例如写改动单的 before 值，或在某个视图里按下时找按到的图层）时，先让那个视图追上，不能假定它已显示最新一步。
- 选中框在改值时隐藏约 200ms，比追上的 100ms 长，所以它重新出现时旁边的视图已经追上。改这两个时长时要保持这个先后。
- 拖拽中旁边的视图追上让位时，画在视图上面的标记（例如简报标记）重新画一次，跟上让位后的位置。
