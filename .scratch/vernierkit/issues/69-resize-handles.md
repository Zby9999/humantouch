# 69: 在画布上拖控制点改尺寸

**What to build:** 选中一个图层时，选中框的四角和四边出现控制点，像 Figma 一样直接拖着改尺寸：拖角同时改宽和高，拖边只改一个方向；按住 ⇧ 保持宽高比例，按住 ⌥ 从中心向四周改。拖哪个方向，那个方向就变成 Fixed（原来是 Hug 或 Fill 的也一样）；自由定位的图层拖左边或上边时，X / Y 跟着变，对边留在原处；文字图层拖宽度后变成固定宽度、高度随文字。拖的时候吸附到旁边图层和容器的边缘、中线，旁边显示 W × H，按住 ⌘ 暂时不吸附。一次拖拽是一步撤销，进改动单的是设计语言的尺寸，和在属性面板里改宽高一样。

参考本功能的 spec.md（同目录上一级），目标与指标以 docs/goals.md 为准，用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（视图与断点见 ADR 0008，旁边视图的跟随见 ADR 0011，按着鼠标时的按键见 ADR 0012）。

**Blocked by:** 22，以及编辑层线的 61、62（按着鼠标时撤销和按键不改画布）

## Comments

**实现记录（2026-10-31）**

*结论*

选中单个图层时，选中框四角和四边有控制点，可以像 Figma 一样拖着改尺寸。验收项都做到了。在约 5000 个元素、三个视图的大页面上拖商品卡片的右下角（96 张卡片一起变），有窗口 Chrome 两次帧间隔 p95 都是 17.2ms，迟到的帧 2/626 和 1/637，达到 22 的拖拽标准（≤ 20.8ms、< 5%）。原有六项性能测试照旧达标；进入编辑模式时间和切换按钮体积没有变差。

*做了什么*

- **控制点**（GLOSSARY 新词，英文 Handle）。单独选中画布上的一个图层时，它在每个视图里都有控制点：
  - 四角是白色小方块，颜色随选中框（普通蓝、实例紫、锁定灰）。
  - 四边看不见，指针移上去变成改尺寸的光标。四边沿整条边，伸出图层 4px，伸进图层最多 4px、且不超过图层大小的四分之一，所以小图层仍能从中间拖动。
  - 多选、页面本身、没有自己元素的文字、行内显示的图层、画布外的图层没有控制点。
- **拖角改宽高，拖边改一个方向**。⇧ 保持比例：按变化较大的那个方向缩放；拖边时另一个方向绕中线变。⌥ 从中心改：对边反向移动同样距离。⌘、⇧、⌥ 在拖的途中按下或松开，不动指针也立即重算。
- **改的是设计语言的尺寸**，和属性面板改 W / H 是同一条编辑命令（`Editor.resize`，内部就是改 width、height、X、Y）：
  - 拖过的方向变成 Fixed，原来是 Hug 或 Fill 也一样；没拖的方向不变。属性面板当场显示 Fixed 和新数值。
  - 自由定位的图层拖左边或上边时，X / Y 一起变，对边不动。
  - 尺寸取整到 1px（吸附时精确到 0.01px）。停在最小、最大尺寸上（锁定图层按它自己样式里的最小、最大尺寸），也不会小于自己的内边距加边框。
- **文字图层**：拖宽度后是固定宽度，高度仍是 Hug，随文字换行变高变矮。**锁定图层**：照样能拖，改的是它外部的尺寸。
- **吸附与参考线**：拖动的边（⌥ 时两条边）在屏幕上 5px 以内对齐容器内框的边缘、中线；自由定位的图层还对齐兄弟图层的边缘、中线。
  - 对齐处画红色参考线，和 16 一样 1px、只画在拖的那个视图里。参考线按图层实际排出来的位置画，只画拖动的边。
  - 选中框下方显示 W × H。按住 ⌘ 不吸附。
- **断点**：在平板、手机或其他视图里拖，那个视图成为工作的视图，尺寸只写进它的断点，属性面板 Width / Height 行出现断点标记（57）。在桌面视图里拖作用于所有断点。
- **视图跟上**：拖的视图当场显示，旁边的视图在指针停下约 100ms 后追上，按连续改值处理（ADR 0011）。拖的时候选中框不隐藏。旁边视图里的选中框在它们追上后重画一次。
- **撤销与按键**：
  - 一次拖拽是一步撤销（undo 里一种有名字的连续步，和方向键微移的连续步分开，紧接着的微移不会并进来）。
  - 按 Esc 回到按下前，这次拖拽不留作重做（`Editor.takeBack`）。指针被取消（pointercancel）也一样。
  - 从按下控制点起就登记为"按着"（`holdPointer`），⌘Z、Delete 等键不起作用（62 / ADR 0012）。
- **改动单**：记为尺寸改动（width、height 的 Fixed 值，自由定位时还有 X、Y），和面板里改的一样。e2e 里让"Agent"按改动写 `w-[…px]`，`done` 核对为"页面上显示了这条改动"。
- **性能**：鼠标报告的移动比帧多（有窗口约 83 次/秒、headless 约 70–80 次/秒），改尺寸每帧最多做一步，按帧开始时指针的位置。不这样做时，headless 下帧间隔 p95 退到 33ms、迟到帧 35–60/400。
- spec 补了用户故事 52a–52e，和"控制点（拖着改尺寸）"一节交互说明；架构一节的"手柄"改成"控制点"。ADR 0011、0012 的 Consequences 各补一行。

*代定的交互（待设计师确认）*

1. **四边的控制点看不见，只有光标变**。照 Figma：Figma 只画四角的方块，四边整条都能拖。ticket 写"四边出现控制点"，如果要像 Framer 那样在边的中点也画小方块，加样式即可。
2. **控制点的大小与命中范围**：
   - 四角的方块 8px（屏幕上），按的范围比看到的大 3px。
   - 四边伸出 4px、伸进最多 4px 且不超过图层的四分之一。
   - 照 Figma 的手感定的数，Figma 没有公开具体值。
3. **图层很小时**：
   - 图层在屏幕上小于 24px 时，四角只按看得见的方块大小响应。
   - 边比 24px 短时，边中间三分之一盖在四角上面，所以缩小看时也能只拖一个方向。
   - 照 Figma 小图层也能拖边的做法，具体规则是自定的。
4. **按住 ⌘ 按在控制点上不改尺寸，而是照常选中最深处的图层**。原因是 ⌘ 单击是本项目已有的"选最深处"（spec 用户故事 35）；控制点伸进图层 4px，不这样，选中框边上的 ⌘ 单击就选不到里面的图层。性能测试的选中步骤正是在边内 3px 处 ⌘ 单击，就是被这个问题拦下才发现的。拖动途中再按 ⌘ 仍是"不吸附"。Figma 里按住 ⌘ 再按控制点是另一种手势，本项目不做。
5. **拖过对边不翻转，停在 0**（或最小尺寸、内边距加边框）。Figma 会翻转图层，网页上翻转要用 transform，不是设计语言里的属性，Agent 也难落地，所以选最稳妥的停住。
6. **从按下起移动满 3px 才开始改**，和拖动图层一样（`DRAG_THRESHOLD`）。原因是单击控制点不该把 Hug 变成 Fixed。Figma 是立即开始的。
7. **只拖宽度时，文字的高度不动**。原来是 Hug 就仍是 Hug（随文字），原来设成 Fixed 的仍是 Fixed，和 Figma 的"固定大小"文字拖边时一样。ticket 写的"高度随文字"对常见的 Hug 高度文字成立。
8. **吸附目标**：
   - 自由定位的图层：吸到兄弟图层和容器内框的边缘、中线，和 16 一致。
   - Stack、Grid 或流式布局里的图层：只吸到容器内框。兄弟图层会随它变大而移动，吸上去会追着跑。
   - 不吸等间距：ticket 只写了边缘、中线；16 的等间距是给拖动位置用的。
9. **Stack 或流式布局里的图层位置由布局决定**。例如居中的 Stack 里拖下边，图层上下一起长；拖左边，宽度变大，但左边是否跟着动由布局决定。Figma 的 auto layout 也是这样。所以这类图层的控制点不一定跟着指针，参考线按实际边的位置画。
10. **⇧ 在角上按变化较大的方向缩放**，在边上另一个方向绕中线变，照 Figma。⇧ 与 ⌥ 可以同时用。
11. **Hug / Fill 的父容器**照 CSS 自然跟着变：父容器 Hug 就随之长大，Fill 的兄弟让出空间。和 Figma 一样，没有另外处理。
12. **拖拽中旁边视图何时跟上**：按 ADR 0011 的"连续改值"，指针停下约 100ms 后追上。按 Esc 取消时三个视图同一帧回去，和撤销一样。
13. **指针被取消（系统打断、拖出窗口等）时撤回这次改尺寸**，和拖动图层被取消时放回原处一致。
14. **画布外的图层不显示控制点**。它们在自己的小 iframe 里，改尺寸还要连带改那个 iframe 的大小，留待需要时另做。
15. **W × H 只在拖的时候显示**，在选中框正下方，蓝底白字。ticket 写的是"拖的时候显示"。Figma 平时选中也显示尺寸，没有照做。

*遗留风险*

1. **页面原本用 `right` / `bottom` 定位的自由图层**（例如 Tailwind 的 `absolute right-2`），拖右边或下边时只写了宽或高，CSS 仍按右边、下边定位，图层会向左、向上长，对边反而动了。拖左边、上边和用 ⌥ 时正常，因为那时会写 X / Y，同时把定位改成按左、上。用 `translate(-50%)` 居中的图层同理。修法：自由定位的图层改尺寸时总是写下对边的位置，需要编辑命令能"值没变也写定位"，并在改动说明里让 Agent 把右侧定位改成左侧定位。建议另开一张 ticket。
2. **Stack 或流式布局里的图层**由布局摆放，控制点不一定跟着指针（例如居中的 Stack 里拖下边，图层上下一起长；⌥ 时变化是指针的两倍，再由布局摆）。和 Figma 的 auto layout 一样，但设计师可能觉得"不跟手"。
3. **大量实例一起变时**一帧较重。卡片网格这种 96 个实例一起改尺寸的情况，有窗口约 83fps（120Hz 屏），帧间隔 p95 17.2ms，离 20.8ms 还有余量但不多。实例更多、或在更慢的电脑上可能达不到。
4. **只量了在桌面视图里拖**。在平板、手机视图里拖时，桌面视图是"旁边的视图"，晚一些追上，没有单独量。
5. **小图层上的命中范围是自定的**（代定第 2、3 条）。极小的图层（屏幕上几 px）四边的控制点只有 1–2px 宽，要放大画布才好按。

*需要开的新 ticket*：建议一张。自由定位图层按右边、下边定位时，拖右边、下边改尺寸让对边不动（遗留风险第 1 条），需要设计师 triage。
