# 25: 改动预览：样式改动显示在真实页面上，并可开关对比

**What to build:** 在预览模式中，真实页面按原比例显示改动单里的样式改动（目前是填充与圆角），页面照常可点、可悬停、动效照常播放，设计师在 Agent 落地前就能试用改动后的效果。切换按钮旁有"改动后 / 现在"开关，用来对比现在的网站。在真实页面上找不到对应元素的改动，提示"N 处改动落地后才能看到"。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。编辑仍发生在画布上（ADR 0001），改动仍由 Agent 落地（ADR 0002）；改动预览只影响显示，不改源码。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 有未落地改动时，预览模式中的真实页面显示这些样式改动，悬停、点击、动效照常可用
- [x] 改动只作用于对应使用处的实例，同一组件的其他使用处不变
- [x] React 重新渲染、页面内跳转、新打开的弹窗等新出现的元素上，改动同样生效，不闪现改动前的样子
- [x] 刷新浏览器后，改动预览照样生效
- [x] "改动后 / 现在"开关可随时切换，开关状态在刷新后保留
- [x] 没有源码标记、在真实页面上找不到对应元素的改动，计入"N 处改动落地后才能看到"的提示
- [x] 改动预览打开时，离开编辑模式不再淡出，直接撤下编辑层；开关停在"现在"时保留淡出
- [x] 主接缝：在示例项目中编辑后回到预览模式，断言真实页面的计算样式、使用处范围、开关对比与刷新后的表现

## Comments

**实现记录（2026-10-23）**

- 模块：
  - `client/change-preview.ts`：改动预览，`startChangePreview(document)`，返回 `show(changes) / stop()`；`canPreview(change)` 判断一条改动能否在真实页面上显示。
    - 按改动的元素位置和使用链在真实页面上找图层：对带 `data-vk-loc` 或 `data-vk-usage` 的元素读一次使用链，用和画布相同的规则（`layers.ts` 导出的 `originOf`、`usageKey`）算出来源，相同就打上 `data-vk-preview="<图层 id>"`。
    - 一张注入的样式表（`<style data-vk-preview-styles>`）按 `[data-vk-preview~="id"]` 写出改动的样式，带 `!important`，选择器再加 `:not(#vk-no-id)` 提高到 id 级优先级，压过页面自己带 id 的 important 规则。
    - `MutationObserver` 盯住整页的增删。它的回调在浏览器绘制前运行，React 重新渲染、新打开的弹窗、页面内跳转出现的元素，第一帧就带着改动。
    - 只有改动涉及的图层集合变了才重新打标记；只改数值时只换样式表的文字，连续调值不必反复读使用链。
    - 不移动、不新建页面元素，只加一个属性和一张样式表。
  - `client/host.ts`：放编辑层写在真实页面上的东西（宿主标签、预览属性、预览样式表标记）。冻结器跳过预览样式表、去掉预览属性，画布里不会带进预览。
  - `client/PreviewSwitch.tsx`：切换按钮旁的 "Changed / Now" 单选组（`role="radiogroup"`，名称 "Change Preview"，方向键切换），只在预览模式且本轮有改动时出现。开关状态存在 localStorage（`vernierkit:change-preview`），和切换按钮的位置一样只是每个浏览器自己的偏好。显示不了的改动在开关旁提示 "N changes show once applied"，开关在 Now 时不提示。界面文字用英文，中文界面不在第一版范围内。
  - `Toggle.tsx`：按钮和角标包进 `.vk-toggle-wrap`，角标始终贴着按钮；开关作为 children 放在按钮旁。
  - `changeset.ts`：每条改动多了 `style`，即参考样式（画布上显示改后值的 CSS）。改动预览直接用它，06 的改动说明也会用它。
- 离开编辑模式：画布上的改动页面都能显示时（改动预览打开，且没有显示不了的改动）不再淡出，画布放大回原位后直接撤下编辑层；开关在 Now，或有显示不了的改动时，照旧淡出。后一条比 ticket 多想了一步：淡出本来就是为了避免切到一个没有改动的页面时画面跳动，只要还有改动显示不了，就仍然会跳。
- 编辑模式中也会更新真实页面上的预览（页面被编辑层盖着），离开时保存一次，预览在同一帧前（`useLayoutEffect`）就位。
- 判定"显示不了"：目前只有没有源码标记、在真实页面上找不到的"未定位"改动。有标记但此刻不在页面上的图层（例如关掉的弹窗）不算，它出现时改动就会显示。
- 测试：`e2e/tests/change-preview.spec.ts`（使用处范围、新出现元素的第一帧、开关与刷新、未定位提示）；`motion.spec.ts` 中离开编辑模式的两种情况。

**已知限制**

- 刷新后，改动预览要等本轮从本机服务读回来才生效，页面加载时会先闪一下没有改动的样子。编辑层挂载本来就在页面首次绘制之后。
- 页面自己用 `@layer` 写的 important 规则（如 Tailwind v4 的 `!bg-*`）优先级高于不在 layer 里的 important，改动预览盖不过它们。
- 元素带着颜色过渡（如 `transition-colors`），又在插入后、标记前被读了样式（组件的 layout effect 量尺寸），会从改前的颜色过渡到改后的颜色。
