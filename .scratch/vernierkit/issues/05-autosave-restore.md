# 05: 自动保存与恢复

**What to build:** 设计师的改动随编辑自动保存进项目：开发服务器进程中的本机服务把画布副本和改动单写入 `.vernier/`。刷新浏览器或回到同一轮时，画布与改动原样恢复；一轮中来回切换预览与编辑，始终回到同一张画布，没有未落地改动时才重新冻结。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

**Blocked by:** 04

**Status:** ready-for-agent

- [x] 停止编辑约半秒后自动保存画布副本与改动单，无需任何保存动作
- [x] 刷新浏览器后进入编辑模式，画布与改动原样恢复
- [x] 有未落地改动时，在预览模式中跳转页面后再进入编辑模式，回到的仍是同一张画布
- [x] 没有未落地改动时进入编辑模式会重新冻结当前页面
- [x] 本机服务只监听 127.0.0.1，并校验每次启动生成的随机口令；不带口令的请求被拒绝（有测试覆盖）
- [x] 切换按钮角标显示未落地改动数量

## Comments

**实现记录（2026-10-23）**

- 模块：
  - `src/service.ts`：本机服务，`startService({ root })`。它在开发服务器进程里另开一个 HTTP 服务，监听 `127.0.0.1` 的随机端口，每次启动生成 32 字节的随机口令。请求头 `X-Vernier-Token` 不对就返回 401。只有 `/round` 一个地址：`GET` 取回本轮（没有时返回 204），`PUT` 保存，`DELETE` 丢弃。
    - 请求一个接一个处理，后发的保存不会被先发的覆盖。请求体先完整读完再排队，慢请求不会挡住别人。
    - 文件先写到临时文件再改名，读的一方不会读到半个文件。
    - CORS 只放行本机来源（`localhost`、`*.localhost`、`127.0.0.1`、`[::1]`）。预检请求不带口令，只拿到许可，拿不到数据。
  - `src/service-protocol.ts`：两边共用的约定，包括全局变量名、口令请求头、`/round` 路径和 `SavedRound`。
  - `src/vite.ts`：在 `configureServer` 里启动本机服务，开发服务器关闭时一起关掉。用 `transformIndexHtml` 往页面 head 最前面注入 `window.__VERNIERKIT__ = { url, token }`。Next.js（09）需要另找注入方式，客户端只认这个全局变量。
  - `client/service.ts`：编辑层这一侧，`connectRoundStore()`。页面上没有全局变量时返回 null，这时一轮只保存在内存里。
  - `client/freezer.ts`：
    - 新增 `serializeCanvas(canvas)` 和 `restore(html, iframe)`。冻结和恢复最后都走 `present()`：加画布样式、重开顶层元素、让动画停在结束状态、设定尺寸、等待加载、恢复滚动。
    - 冻结时会把滚动位置和顶层元素（模态框、popover）记成画布上的属性（`data-vk-scroll`、`data-vk-top-layer`），所以恢复后的画布也能重现。
    - 序列化时一并带上 markup 之外的东西：
      - 经 CSSOM 改过的规则，包括视口单位换算和 CSS-in-JS 规则，从 `cssRules` 重新写出；
      - 静态画面的像素，存成 data URL；
      - 表单的值。
    - 画布自己的样式不存，恢复时再加。
  - `client/changeset.ts`：
    - 每条改动多了 `layer`（图层 id），恢复时靠它合并改动。
    - 新增 `save()`，可以从 `createChangeSet(saved)` 恢复。保存的数据里带 `lastId`，恢复后的编号不会重复。
  - `client/Shell.tsx`：最后一次编辑 500ms 后保存一次。离开编辑模式时立刻保存，这时画布还在。改动清零时丢弃这一轮（`DELETE`）。
  - `client/EditorLayer.tsx`：页面加载时读取一次本轮，之后保存在内存里，每次保存都会更新它。
    - 进入编辑模式时，如果有本轮就恢复，没有就冻结。
    - 在本轮读取完成之前，编辑模式会先等它读完。
  - `client/Toggle.tsx`：切换按钮右上角显示蓝色角标，数字是未落地的改动数，0 时不显示。角标的 `role="status"`，读屏软件会读出 "N changes not applied yet"。
- `.vernier/` 里的文件：`canvas.html`（带 `data-vk-layout` 记录宽、高和滚动位置）和 `changeset.json`。先写画布再写改动单，`GET` 以改动单为准。状态文件和归档留给 06。
- 测试：
  - 主接缝在 `e2e/tests/autosave.spec.ts`，真实写入示例项目的 `.vernier/`，因此串行执行。覆盖以下几项：
    - 口令与 `127.0.0.1`；
    - 约 0.5 秒后自动保存；
    - 刷新后恢复（包括冻结时打开的对话框）；
    - 在预览模式里操作页面、跳转页面后，回到的仍是同一张画布；
    - 改动清零后重新冻结；
    - 角标。
  - 其他 e2e 测试改为从 `e2e/tests/fixtures.ts` 引入 `test`。这个 fixture 把 `/round` 换成每个测试各自的内存实现，因为各测试共用同一个开发服务器，也就共用同一个 `.vernier/`，不换的话会互相串改动。
- 仓库根目录的 `.gitignore` 加了 `.vernier/`。给用户项目加忽略规则仍然由 08 的 `init` 负责。

**已知限制（留给后续 ticket）**

- 最后一次编辑后不到 0.5 秒就刷新或跳转，这次编辑会丢失。`keepalive` 请求的上限是 64KB，存不下画布，所以没有在 `pagehide` 时补存。
- 两个标签页同时编辑同一个项目时，后保存的会覆盖先保存的。本轮只在页面加载时读取一次。如果要在进入编辑模式时重新读取，冻结就得等一次网络往返，而冻结必须在点击的同一任务里开始。
- 无法回读的静态画面，例如画着跨域视频的 canvas，恢复后是空白。`indeterminate` 状态的复选框不会恢复。
- 用局域网 IP 打开开发服务器时，本机服务连不上，只会在控制台给出警告（符合 ADR 0003）。
