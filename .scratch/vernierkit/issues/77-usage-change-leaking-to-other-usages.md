# 77: done 查不出「只改这一处」的改动漏到了别的使用处

**What to build:** 设计师只改一个使用处（没有推广到组件本身）的改动，Agent 可能写进组件本身，让组件的其他使用处也跟着变。现在 `done` 查不出来，照样说页面显示了这条改动，报告里它在 ✓ 下。要让这种情况被发现，具体查什么、查出来怎么说，由设计师在分诊时定（见待定问题）。

- 现在页面怎么查：「只改这一处」的改动，`client/check.ts` 只看这个使用处的实例（spec.md 核对一节：「每个实例都看，只看这个图层」），组件的其他使用处不看。
- spec 和 ADR 0013 都没有要求查组件的其他使用处。docs/goals.md 对虚假 ✓ 的定义是「报告已落地但页面上未生效」，改动漏到别处不在这个定义里。
- 65 补修五（c39f839）已经在 `claim` 的「How the page checks」里告诉 Agent：只看这个图层，改到作用范围外的元素，即使 `done` 说显示了也不行。这是说明，页面并不查。

参考本功能的 spec.md（同目录上一级），目标与指标以 docs/goals.md 为准，用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（ADR 0006、0013）。

## 背景

- 实例：ticket 67 Comments 里 Claude 的 fill-gap-brief #3。改动 2 是循环里 3 张卡片（一个使用处）的 gap 改成 12px。Agent 改了 `Card` 组件本身：`<article>` 加 `flex flex-col ${gap}`，默认 `gap-2`，去掉 `<p>` 的 `mt-2`，这 3 张传 `gap="gap-3"`。第 4 张卡片（另一个使用处）因此也成了 flex，靠 `gap-2` 看起来和原来一样，但不再是 `display: block`。页面核对只看这一处的 3 张，`done` 说显示了；场景的页面预期「the fourth card is as it was」不成立，测量台按页面预期把它算作一次虚假的 ✓。
- 之后 65 补修五（c39f839）在 `claim` 里加了「改到范围外的元素即使 `done` 说显示了也不行」；c39f839 复测两家各 30 次（ticket 65 Comments），60 次都没有改到范围外的元素，fill-gap-brief 6 次都只把 `flex flex-col gap-3` 传给这 3 张。所以现在靠的是 Agent 读了说明照做，页面不兜底。
- 真实 Agent 上这种情况少见，量真实 Agent 的数字很难看出前后差别；主要靠剧本测机制。
- 相关：ticket 64（页面核对随代码变化）、65（「How the page checks」和 `checkable.ts` 同源，补修五）、67（实例出处）；ADR 0006（`done` 核对页面）、ADR 0013（以页面为准）。

## 待定问题（等设计师定）

1. 要不要做？还是维持现在只靠 `claim` 里的说明，只在 spec 里写明页面不查其他使用处？
2. 查什么？审查给过一个思路：「只改这一处」的改动，也查组件的其他使用处，在参考样式的那几个 CSS 属性上仍是「改前」的值。要定的细节：
   - 只看参考样式的属性，还是也看改动没提到、但被连带改掉的属性（#3 那次第 4 张的 `display` 从 block 变成 flex）？只看参考样式的属性时，#3 那次第 4 张的 gap 也变了（从 `normal` 到 `gap-2` 的 8px），应能查出；但连带改掉的若只有参考样式以外的属性，就查不出。
   - 「改前」按什么算：冻结时画布上的值，还是认领时活页面上的值（68 之后改前会在认领时重读）？
   - 其他使用处不在当前页面上时算什么（页面看不到，不算错？）
   - 其他使用处这一轮也有自己的改动、或组件本身也有改动时，怎么分开？
3. 查出来之后怎么说：`done` 说这条改动没显示（算不 1:1），还是另一种结果（例如「显示了，但也改到了别处」）？`finish` 的报告把它放在 ⚠️ 下吗？进度环算不算它落地？
4. docs/goals.md 的虚假 ✓ 要不要改定义，把「改到作用范围外」算进去？
5. 只查「只改这一处」的改动，还是也查别的作用范围（例如只改一个实例的数据改动）？
