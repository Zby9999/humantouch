# 94: 从右往左、两边都写了值的图层，属性面板的 X 显示它画在哪里

**What to build:** 从右往左的页面上（`direction: rtl`），自由定位的图层左右两边都写了值、宽度又定死时，浏览器按 `right` 摆它（ticket 89），属性面板的 X 却显示写的 `left`，不是图层画出来的位置。拖拽、微移按差值改 `right`，结果是对的；在面板里直接输一个 X，图层会落到差出很远的地方。例如容器 400px 宽，图层 `left: 10px; right: 30px; width: 50px`，画在 320 处，面板显示 X = 10；输 X = 300，`right` 被减去 290，图层被甩出容器。不报虚假的 ✓（画布上在哪里，改动就记成哪里），但和 Figma 不一样，设计师会困惑。要做到：面板的 X 显示图层画出来的位置，输一个 X，图层就落在那里。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（ADR 0014，以及 ticket 89 在它里面补的从右往左的例外）。

**Blocked by:** 90（设计师定的排期：等它合进 main 再开线，不是代码上的依赖）

**Status:** ready-for-agent

- [x] 先复现，用单元测试或剧本（脚本扮演 Agent，不跑真实 Agent）：上面那个例子，在桌面视图选中图层，面板 X 显示 10；在面板输 X，图层没落在输的位置
- [x] 面板的 X 显示图层画出来的位置（照 Figma：离父容器左边多远），算法和 ticket 89 在页面核对里用的一样（两边都写了值、排出来对不上空间时，按浏览器把它摆在哪里算），不另起一套
- [x] 在面板里输 X：图层落在输的位置，改动照 ADR 0014 和 89 记成 `right`，和在画布上移动它时写的一样
- [x] 面板上别处显示这类图层位置的地方（如果有）一起看；Y 照理不受影响（`top` 总是说了算），确认一下
- [x] 不报虚假的 ✓；从左往右的页面上面板的读数，以及 `claim`、`done`、`finish` 的输出逐字不变；切换按钮的包逐字节不变

## 背景

- ticket 89 的遗留风险第 1 条（2026-11-04）。89 让画布上移动、改尺寸这类图层时按右边处理（代定第 3 条，设计师 2026-11-04 确认），但面板的 X 仍读写的 `left`。
- 这种写法少见：从右往左的页面一般只写 `right-*` 或 `start-*`，不会两边都写还定死宽度。

## Comments

**实现记录（2026-11-04）**

*结论*

验收项都做到了。从右往左、左右两边都写了值、排出来对不上空间（宽度定死）的自由定位图层，属性面板的 X 现在显示它画在哪里（离定位参照左边多远，照 Figma）；在面板输 X、方向键微移、在画布上拖动，图层都落在那里，照 ADR 0014 和 89 的代定第 3 条记成 `right`。读法用的就是 89 页面核对的那条（`offsetPlacing`：`edgeGoneBy` 加 `overConstrained` / `roomPlacing`），没有另起一套。从左往右的页面，`offsetPlacing` 对 `left` 总是直接给算出来的值，和原来读的一样，面板读数、`claim` / `done` / `finish` 都不变；上下方向 `top` 总是说了算，Y 不变。切换按钮的包逐字节相同。

另外发现 ticket 说的「拖拽按差值改 `right`，结果是对的」不完全对：方向键微移是按差值，结果对；但在画布上拖动时，拖放给的是图层画出来的位置（`findDrop`），编辑命令再拿它和面板的 X（写的 `left`）相减，和在面板输 X 一样错。这次一起修好了，见「先复现」。

*先复现*

`edits.browser.test.ts` 新加一条（从左往右、从右往左各一）：ticket 的例子，容器 400px 宽，图层 `left: 10px; right: 30px; width: 50px`，桌面视图里读 X、Y 和 `absolute`，再分别在面板输 X = 300、微移 -20、拖到 300，每次都看改动单、图层画在哪里、X 读多少，然后撤销。先在没改的代码（cef746d）上跑，从右往左那条失败：

```
AssertionError: expected [ 10, 8, { x: 10, y: 8 } ] to deeply equal [ 320, 8, { x: 320, y: 8 } ]
```

把断言临时改成 soft 再跑一遍，看全了改前的样子（没留在仓库里）：

- 面板 X 读 10，图层画在 320。
- 输 X = 300：改动单 `right` 30 → -260，图层画到 610，甩出容器。
- 微移 -20：`right` 30 → 50，画在 300，是对的；但之后 X 仍读 10。
- 拖到 300：和输 X 一样，`right` 30 → -260，画到 610。

从左往右那条改前就过（护栏）。

*面板的 X，前后*

ticket 的例子：改前 X = 10，改后 X = 320（图层画在 320）。Y 前后都是 8。`absolute` 的读数（在断点上改为自由定位时用的位置）同样 `{ x: 10 }` → `{ x: 320 }`。

*输一个 X 写什么*

输 X = 300：改后写 `right` 30 → 50（改动单 `property: "right"`，`before: 30`，`after: 50`，样式 `right: 50px`），图层画在 300，X 读 300。微移 -20、拖到 300 记的完全一样（`right` 30 → 50），和在画布上移动它一致。`right` 的改前值本来就读算出来的 `right`（30，说了算的那一边），没改。

*别处看了的*

- **Y**：`top` 总是说了算（`edgeGoneBy` 上下总答 `start`），`offsetPlacing` 对 Y 直接给算出来的 `top`，读数不变；测试里 Y 前后都是 8。
- **`absolute` 的读数**：和 X 共用 `offsetOf`，一起改了（同一个毛病）。
- **移动的改前位置**（`structure-edits.ts` 的 `placeOf`）：读 `definitionOf("x")`，跟着改了；原来从右往左这种图层记的改前 `right` 是 400 - 10 - 50 = 340，现在是 30，对了。只影响从右往左这种图层。
- **微移的起点**（`freePlaceOf`）：原来读算出来的 `left`，改后 X 读画出来的位置，两者不再一致，微移就会错，所以改成同样按 `offsetPlacing` 读（审查后两个方向都这样读，Y 照旧是 `top`）。
- **拖动**（`drag.ts` 的 `findDrop`）：给的是画出来的位置，本来就对；错在编辑命令拿它和 X 相减，X 改了就对了。
- **改尺寸**（`canvas-resize.ts`）：按右边定位时用 `right`，不用 X，不受影响。
- **LayerInfo**：不显示位置。**按 ⌥ 量距离**：按画出来的框量，本来就对。
- **页面核对**（`check.ts` 的 `placedOn`）：89 已经用 `offsetPlacing`，和面板现在读的是同一个式子。
- **冻结时钉住**（`freezer.ts` 的 `pinToViewport`）：页面横向滚过时把固定图层的 `left` 钉成算出来的 `left` 加滚动量，从右往左两边都写、宽度定死时钉的是写的 `left`，不是画出来的位置。不是面板的读数，没改，记进遗留风险。

*做了什么*

- `client/property-table.ts`：`offsetOf` 改按 `offsetPlacing(el, axis, "start")` 读，再减去钉住时的滚动量；X、Y、`absolute` 三处都经它读。`position` 的边从 `SIDES` 取（审查后）。
- `client/structure-edits.ts`：`freePlaceOf` 两个方向都按 `offsetPlacing` 读。
- 写法没改：`setValue` 照旧按 `placedFrom` 定改 `right` 还是 X，用新读到的 X 算差值。
- spec「移动」一节「属性面板的 X / Y 照旧显示图层的 `left` / `top`」后补了从右往左的例外。ADR 0014 没有说面板 X 读 `left` 的句子，没改。
- 读法的选择（规则第 2 条）：面板读的是正在工作的视图，那里已经排好版，面板本来就量图层的框，所以选页面核对那一套几何的读法（`offsetPlacing`），不选画布那边按声明的 `endWins`。几何的读法给的就是画出来的位置，这正是 X 要显示的；按声明读会在 `max-width` 卡住宽度时仍显示写的 `left`。写的那一边仍按 `placedFrom`（声明的），见代定第 2 条。

*代定的事（待设计师确认）*

1. **面板的 X 按几何读，和页面核对同一条**：理由见上。从左往右、上下方向读数都不变，只有从右往左、两边都写、排出来对不上空间时变成画出来的位置。
2. **`max-width` 卡住宽度时，X 显示画出来的位置，但输 X 写成 X（`left`，`right` 设成 `auto`），不写 `right`**：画布那边判断「宽度定死」照 89 的代定第 2 条按声明读（已确认），没写 `width` 的就当成两边都摆它、按左边处理；读数按几何，所以两者在这种图层上不一致。结果仍然落在输的位置（测试钉住：画在 320，X 读 320，输 300 记 X 320 → 300，画在 300），只是改动单里是 X 不是 `right`。要改得让 `placedFrom` 也按几何读，会碰 ADR 0011 和 89 已确认的代定，没做。
3. **拖动也一起修了**：ticket 说拖拽本来是对的，实际上拖动给的是画出来的位置，和输 X 一样错；读数改了它就对了，没另做。

*遗留风险*

1. 代定第 2 条那种（`max-width` 卡住宽度、从右往左两边都写）改动单记 X 而不是 `right`，Agent 会写 `left` 并去掉 `right`，图层在别的宽度可能就不再按右边摆了。和 89 的遗留风险第 3 条同一个根源（画布那边按声明判断「定死」）。
2. 冻结时横向滚过的页面上，从右往左两边都写、宽度定死的固定图层，钉住的是写的 `left`（见「别处看了的」）。很少见。
3. 读一次的记录会过时；一个视图代表一整段宽度；没跑真实 Agent（同 75、83、84、89）。
