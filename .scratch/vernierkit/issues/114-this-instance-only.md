# 114: 循环里的一个实例不跟随其他实例

**What to build:** 一个使用处循环渲染出几个实例时（例如一组卡片），现在改其中一个实例、或实例里的图层，就是改这个使用处的全部实例（GLOSSARY「实例」，spec 76）；删除、复制、移动、改文字已经能只作用于某一个实例（ticket 65 第 6 条），样式改动还不能。设计师想像 Figma 的 Detach 那样：选中一个实例，在选中工具条上选一下，它就不跟随其他实例，之后对它的样式改动只作用于它，并在画布和 Layers 上标出来。默认仍是改一个就改这组。Agent 落地时用数据上的一个字段或一个条件区分这个实例（不按下标硬写，数据有 id 时用 id）。

「不跟随」是只有改过的那几项不跟随（Figma 的 override）：例如第二张卡片单独改了填色，之后改这组卡片的内边距，它的内边距照样跟着变，只有填色保持单独改的。不是整个脱离（Figma 的 Detach：之后改这组卡片它都不变，代码里等于把它从循环里拿出来单独写一份，代码重复，以后改这组也容易漏掉它）。按钮不叫 Detach，免得 Figma 用户以为是整个断开。

参考本功能的 spec.md（同目录上一级，「组件、实例与推广」），用词以 GLOSSARY.md 为准（实例、使用处、推广），并遵守 docs/adr/ 中的决策（ADR 0006、0013）和 ticket 77 的核对（其他使用处有没有跟着变）。

**Blocked by:** 无（发布以后做，见 111 的「设计师决定」：排在定位方式之后）

**Status:** ready-for-agent

- [ ] 选中循环里的一个实例（或实例里的图层），选中工具条上有一个按钮让它不跟随其他实例；按下后它在画布和 Layers 上有标记，可以撤回（回到跟随）；按钮叫什么、放在推广旁边哪里作为代定
- [ ] 不跟随的实例上改样式，只有它变，其他实例不变；跟随的实例上改，照旧整组一起变，不跟随的那个也跟着变，只有它单独改过的那几项不变；在任一视图改，断点规则照 ADR 0008
- [ ] 推广（Promote）和不跟随一起出现时怎么办作为代定
- [ ] 改动说明写明是第几个实例、它的文字（照 ticket 65 第 6 条的写法），让 Agent 用数据上的字段或条件区分它，不按下标硬写；Skill 若要改，措辞用英文
- [ ] `done` 核对这个实例显示了改动，其他实例没跟着变（变了不算显示，照 ticket 77 的思路）
- [ ] 脚本扮演 Agent（`apply`）走一遍「一组卡片里第二张单独改填色、落地、`done`」，核对是 ✓
- [ ] 原来的改动说明逐字不变：`--dry` 24/24、`--scripted` 全过；切换按钮的包逐字节不变
- [ ] 性能 headless 前后对比（`HT_PERF_HEADLESS=1`）：96 个实例的大页面上进入编辑模式、改数值、撤销（ticket 60、73）不变差
- [ ] e2e 全过；GLOSSARY「实例」补上不跟随的例外（需要新词时一并定）；spec 76、docs/roadmap.md、spec 的 Out of Scope 相应更新

## 背景

- docs/roadmap.md「第一版之后（已承诺）」的「单个实例的覆盖（Override）」。设计师 2026-11-09：「可以像 Figma detach 一样，在工具栏选择一下不跟随其他实例」。

## 设计师决定（2026-11-09，分诊）

- 默认不变；在选中工具条上选一下，这个实例就不跟随其他实例。
- 不跟随是只有单独改过的那几项不跟随（Figma 的 override），不是整个脱离（Figma 的 Detach）；按钮不叫 Detach，叫什么开线时作为代定（设计师 2026-11-09 同意）。
- 发布以后做，排在定位方式（113）之后；都用 effort medium。
