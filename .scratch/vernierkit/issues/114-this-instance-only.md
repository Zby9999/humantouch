# 114: 循环里的一个实例不跟随其他实例

**What to build:** 一个使用处循环渲染出几个实例时（例如一组卡片），现在改其中一个实例、或实例里的图层，就是改这个使用处的全部实例（GLOSSARY「实例」，spec 76）；删除、复制、移动、改文字已经能只作用于某一个实例（ticket 65 第 6 条），样式改动还不能。设计师想像 Figma 的 Detach 那样：选中一个实例，在选中工具条上选一下，它就不跟随其他实例，之后对它的样式改动只作用于它，并在画布和 Layers 上标出来。默认仍是改一个就改这组。Agent 落地时用数据上的一个字段或一个条件区分这个实例（不按下标硬写，数据有 id 时用 id）。

「不跟随」是只有改过的那几项不跟随（Figma 的 override）：例如第二张卡片单独改了填色，之后改这组卡片的内边距，它的内边距照样跟着变，只有填色保持单独改的。不是整个脱离（Figma 的 Detach：之后改这组卡片它都不变，代码里等于把它从循环里拿出来单独写一份，代码重复，以后改这组也容易漏掉它）。按钮不叫 Detach，免得 Figma 用户以为是整个断开。

参考本功能的 spec.md（同目录上一级，「组件、实例与推广」），用词以 GLOSSARY.md 为准（实例、使用处、推广），并遵守 docs/adr/ 中的决策（ADR 0006、0013）和 ticket 77 的核对（其他使用处有没有跟着变）。

**Blocked by:** 无。提到发布前做（设计师 2026-11-11，在官网的主题切换按钮上碰到：`CHOICES.map` 循环出的三个按钮只想改深色那个）。不再排在 111–113 之后。

## Comments

### 开线时的现状（2026-11-11，main 7535c54d）

- 循环里的实例共用一个图层 id（`data-ht-layer`），样式改动写进同一组规则（ticket 60），所以改一个就改这组；删除、复制、移动、改字已经能只作用于一个实例，记成数据改动（`data`、`instance`，ticket 65 第 6 条），`done` 不核对它们。
- 选中工具条只有 Promote，没有 Promote 时整个工具条不显示。

### 做了什么

- **按钮叫 Edit alone**（代定 1），在选中工具条上，选中循环渲染出的一个实例或它里面的图层时出现，放在 Promote 左边；是一个开关（`aria-pressed`），按下后这个实例不跟随其他实例，再按一下回到跟随。悬停提示用编辑层自己的深色提示。按下、回到跟随都是一步，⌘Z 撤回。
- **标记**：画布上，这个实例和它里面的图层的选中框、悬停框是虚线；Layers 里它那一行右边有一个紫色的小标记（两个方块，一个虚线），行描述带「· Edits alone」；改动列表那一条写「Fill · Card · 2nd alone」。标记就是画布元素上的 `data-ht-alone="<编号>"`，保存的一轮、重新打开、撤掉一条改动后都还在。
- **怎么记**（`client/alone.ts` 新、`edits.ts`）：在它上面改样式，改动的 `layer` 记为 `<图层 id> alone <编号>`，带 `alone: true` 和 `instance`（第几个实例、它的文字，和 ticket 65 第 6 条一样数，画布上删掉的也算）。只写在这个实例的元素上，进规则里新的一层 `alone`，压在实例共用的 `edits` 之上（`canvas-style.ts`）。其他实例上的改动照旧写到全部实例，包括它；同一项属性它单独改过的，它保持自己的值。它单独改的是所有断点的值时，共用的改动在某个断点上的值也压不过它（Figma override 的意思：改过的这一项就是它自己的）。
- **回到跟随**：它单独改过的改动全部撤掉（从新到旧），和按下是同一步。
- **只记样式**。删除、复制、移动、改字照原来的做法（本来就是数据改动）。实例里面再有一个循环（每张卡片里一组标签）、或只在部分实例里有的图层，在这个实例里改，只改它里面的那几个。
- **改动说明**：Scope 一行写「It renders 3 instances: this change is for one of them alone (**One instance alone**)」；多一行 **One instance alone**：是循环的第几个实例、它读到的字，要用数据上的字段（有 `id` 用 `id`）或条件区分，不按下标，其他实例不动。How to write them 多一条「One instance alone」规则（按字段区分，例子 `choice.id === "dark"`；同一属性同时有共用的改动时，共用的值给全部、它保持自己的，写成它的值压过共用的值）。Skill 没改：它没讲实例，规则在改动说明里。
- **`done` 的核对**（`check.ts` 改动约 30 行、`other-usages.ts`）：单独的改动只看第几个实例上的那个图层（按页面顺序）；认领时记下循环里其他实例这一项的值（和 ticket 77 记其他使用处一起记、一起存进 `.humantouch/other-usages.json`），之后有一个变了就算没显示，`done` 说「on another instance the loop renders too: the 1st instance, its fill from … to …」，并说要按数据字段只给这一个。共用的改动不看在这一宽度有单独值的实例。页面上这个图层不是每个实例一个（实例里另有循环）时答没能核对，说明原因。有意不同的报告一栏（148）还没合进来，照决定，设计师在对话里交代的单独改动照旧放在 ⚠️。
- **Promote 和不跟随一起**（代定 3）：Promote 只推广这一处共用的改动，单独的改动留在这个实例上，不推到组件。实例上只有单独的改动时不出现 Promote。
- **上一轮应用过的单独改动**（ticket 68 的一轮带到下一轮）：收进规则里的 `takenAlone`，仍压在共用的改动之上。
- 复制一个不跟随的实例：副本跟随其他实例（去掉标记）。
- 文档：GLOSSARY「实例」加了例外「单独改 (Edit alone)」；spec 76 和「选中工具条」一节写了 Edit alone；Out of Scope 和 docs/roadmap.md「第一版之后」去掉了这一项，roadmap 第一版范围里记上。

### 代定

1. 按钮名 **Edit alone**，放在选中工具条 Promote 的左边；图标两个方块、一个虚线。
2. 回到跟随时，它单独改过的改动全部撤掉（和按下同一步，⌘Z 能回来），不是保留成共用的改动。
3. Promote 只推广共用的改动，单独的改动留在这个实例上；实例上只有单独改动时不出现 Promote。
4. 单独改的是所有断点的值时，共用改动在某个断点上的值也压不过它。
5. 只有样式改动记成单独的；删除、复制、移动、改字照原来的数据改动。
6. 标记：改动列表写「· 2nd alone」，画布上选中框、悬停框是虚线，Layers 行有紫色小标记、描述带「· Edits alone」；复制出来的副本跟随其他实例。

### 风险

1. 第几个实例按页面顺序认：Agent 改了数据顺序（排序、插入一项），`done` 看的是新的第 n 个，会报错位。
2. 上一轮应用过单独改动的那一项，这一轮又有共用的改动时，`done` 仍不看那个实例（因为它有单独值），实际上代码里共用值可能也盖到了它。
3. 实例里另有循环、或图层不是每个实例一个时，单独改动答没能核对。
4. 单独改 Stack 间距时不像共用改动那样去掉子元素的外边距（只动这一个实例的子元素会和共用规则打架），看起来可能和共用改动不一样。
5. 真正的场景（官网 `ThemeSwitch.tsx`）没在官网上试过（本票不改 `website/`），bench 的 `card-alone` 是同样的形状；真 Agent 的 bench 没跑（用设计师额度）。
6. 性能那几项未达标的报告值没有 main 的同机对比。
