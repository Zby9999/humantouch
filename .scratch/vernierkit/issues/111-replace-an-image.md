# 111: 替换图片

**What to build:** 第一版要换图，只能用 Frame 加生成说明交给 Agent（docs/roadmap.md）。要做到：选中一个图片图层（`img`、`picture`；内联的 `svg` 是代码，不算），属性面板里有一节图片，显示缩略图和一个 Replace，点了从本机选一个图片文件；也可以从 Finder 把文件直接拖到这个图层上。画布上三个视图马上换成新图，换上比例不同的图时照原来的缩放方式显示，这一节里能改缩放方式（Fill / Fit，对应 `object-fit: cover` / `contain`）。换图作用于所有视图，和改文字一样。

文件落地前存在 `.humantouch/` 里（被 git 忽略、不提交）。落地时 Agent 照项目的习惯把它放进资源目录（`public/`、`src/assets/` 等），改这个图层的引用；Next.js 用 `next/image` 的，照它的写法。核对比较的是图片内容，不看文件名和路径。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（ADR 0003、0006、0013）。

**Blocked by:** 无（发布以后做，见「设计师决定」）

**Status:** ready-for-agent

- [ ] 选中图片图层，面板里有图片一节：缩略图、Replace、缩放方式；Replace 打开选文件，从 Finder 拖文件到选中的图片图层上也能换；png、jpg、webp、gif、avif、svg 文件都行
- [ ] 换上后三个视图马上显示新图，一次替换是改动列表里的一条，⌘Z 一步撤回；改缩放方式是一条样式改动，照常可以按断点改
- [ ] 文件经本机服务存进 `.humantouch/`，同一个文件只存一份；这一轮放弃或落地归档后不再需要的文件清掉；`remove` 清掉；刷新后画布上还是新图
- [ ] 改动说明写明：换的是哪个图层（源码位置）、新文件在 `.humantouch/` 的哪里、放进项目资源目录、保留原来的 `alt` 等属性；Vite 和 Next.js（`next/image`）两种写法都有说明，Skill 若要改，措辞用英文
- [ ] `done` 比较页面上这张图的内容和文件是否一样（例如取页面实际加载的图片算哈希）；`next/image` 的优化地址要追到原始文件，追不到时说没核对，不报 ✓
- [ ] 脚本扮演 Agent（`apply`）在 Vite 和 Next.js 示例上各走一遍「换图、落地、`done`」，核对是 ✓
- [ ] 原来的改动说明逐字不变：`--dry` 24/24、`--scripted` 全过；切换按钮的包逐字节不变
- [ ] 性能 headless 前后对比（`HT_PERF_HEADLESS=1`）：进入编辑模式、改数值不变差
- [ ] e2e 全过；GLOSSARY 若需要「图片图层」一词就补上；docs/roadmap.md、spec 的 Out of Scope 相应更新
