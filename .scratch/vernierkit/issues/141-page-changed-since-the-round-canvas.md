# 141: 留下改动的一轮，页面代码后来改了，画布上看不到

**What to build:** 设计师改官网时发现（2026-11-11，官网线报来）：

- 设计师在这一轮里给页面的 CSS 加了字重（改的是代码，不是在画布上改）。
- 然后进入编辑模式，画布上还是旧的样式和旧的 `@font-face`。刷新页面也没用。
- 在设计师看来就是：代码改了，Human Touch 里还是旧的。

原因：这一轮有没落地的改动时，进入编辑模式会恢复保存下来的画布，不重新冻结。这是 ticket 68 的规定（设计师 2026-11-01 定）：回到同一张画布接着改，留下的改动都落地或都放弃之后，才按新代码重新冻结。保存的画布带着它自己的样式表，样式表停在这一轮开始时的样子。

所以「画布不跟代码走」是有意的，问题在于设计师不知道为什么，也不知道怎么让它跟上。

可选的做法（等设计师定）：

- **A. 只说清楚。** 进入编辑模式时，如果页面的样式表和保存画布时不一样，提示一句：页面在这一轮开始之后改过，画布还是这一轮开始时的样子；要看新代码，先让 Agent 落地，或者放弃留下的改动。行为不变。
- **B. 样式表跟上。** 恢复画布时，把页面现在的样式表（包括 `@font-face`）换进去，图层结构和画布上的改动照旧。这次的例子（只加了字重）能直接看到。风险：代码同时改了结构或类名时，旧的图层配上新的样式，画布可能和页面、和改动都对不上。
- **C. 提示 + 重新冻结。** 像 A 一样提示，并给一个按钮：按现在的页面重新冻结，把留下的改动在新画布上重做一遍。重做不了的改动要有说法。工作量最大。

用词以 GLOSSARY.md 为准；涉及 ADR 0001、0013 和 ticket 68 的规定，选 B 或 C 时要更新 ticket 68 的说法，可能要写 ADR，编号向规划会话要。
