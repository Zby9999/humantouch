# 141: 留下改动的一轮，页面代码后来改了，画布上看不到

**What to build:** 设计师改官网时发现（2026-11-11，官网线报来）：

- 设计师在这一轮里给页面的 CSS 加了字重（改的是代码，不是在画布上改）。
- 然后进入编辑模式，画布上还是旧的样式和旧的 `@font-face`。刷新页面也没用。
- 在设计师看来就是：代码改了，Human Touch 里还是旧的。

原因：这一轮有没落地的改动时，进入编辑模式会恢复保存下来的画布，不重新冻结。这是 ticket 68 的规定（设计师 2026-11-01 定）：回到同一张画布接着改，留下的改动都落地或都放弃之后，才按新代码重新冻结。保存的画布带着它自己的样式表，样式表停在这一轮开始时的样子。

所以「画布不跟代码走」是有意的，问题在于设计师不知道为什么，也不知道怎么让它跟上。

设计师定的做法（2026-11-11）：分情况，由产品自己判断。比较的是「画布反映的页面」和「页面现在的样子」。

- **画布反映的页面**：这一轮的画布冻结时的页面；上一轮结束时有改动落地了的，就是那时的页面，也就是落地后的代码。Agent 落地这一轮的改动带来的代码变化，ticket 68 已经让它们留在画布上当底，不算「页面改过」。
- 设计师在编辑模式外手改代码，或者别的工具改了代码，才算。

分三种情况：

1. **代码没变**：和现在一样，恢复保存的画布，不提示。
2. **只有样式变了**（样式表、`@font-face`、主题变量这类，页面上的元素、类名、文字都没变）：恢复画布时换上页面现在的样式表，图层、画布上的改动、断点上的改动、画布外的图层都照旧。不提示。这次官网加字重就是这种。
   - 换掉的只是页面自己的样式。Human Touch 写在画布上的改动样式、断点规则不动。
   - 新样式表里的 `@font-face` 在画布和各视图里照常加载。
   - 换上以后照常保存。下次进入时这就是「画布反映的页面」，不再重复换。
3. **页面结构也变了**（元素、类名、文字有不同）：画布不动，和现在一样恢复。提示一句，说清楚三件事：页面在这一轮开始以后改过；画布还是那时的样子；要看新代码，先让 Agent 落地，或者放弃留下的改动。
   - 提示的英文措辞是代定，交设计师确认。
   - 用 Tailwind 的项目，改样式大多是改 JSX 里的类名，属于这一种。

判断要稳：动画、时间、随机内容这类每次加载都不同的东西，不能让提示每次都出现。指纹取什么、去掉什么，是代定，写进 Comments。

用词以 GLOSSARY.md 为准。

- ticket 68 的「下次进入编辑模式回到同一张画布，不重新冻结」不变，补一句样式跟上的规定。
- GLOSSARY「一轮」「画布」需要时随之更新。
- 涉及 ADR 0001、0013。觉得需要 ADR 的话，编号向规划会话要。

   - 去掉：`style` 属性和类名以外的所有属性、文字里的一串串数字和跟着的 AM/PM、构建工具加在类名里的 hash（代定 9）、源码标记、编辑层自己。

3. 情况 3 不更新「画布反映的页面」：只要画布还是旧的，每次进入都提示一次。

5. 只换页面 head 里的样式表、根元素下直接挂的样式表、document 上 adopted 的样式表。body 和 shadow root 里的 `<style>`、shadow root 上 adopted 的样式表算结构：它们变了走情况 3。
6. 画布冻结时的页面和现在打开的不是同一个地址（路径加查询参数）：不比较，也不提示。
7. 新加的示例页 `motion.html`（含 3 秒后出现的文字和 12 小时制时钟），以及 bench 复制示例时把它的编辑层拿掉。
8. 先看代码：代码的 git tree 和存指纹时一样，就当页面没变，不比指纹。代码之外的东西变了（接口数据、CDN 上的样式表、`.gitignore` 掉的文件）不算。不在 git 仓库里的项目只比指纹。
9. 类名里认作 hash 的只有三种写法：Vite CSS Modules、webpack CSS Modules、next/font。其他构建工具（Turbopack、styled-components、Emotion 等）的 hash 照旧算类名。

**风险**

1. 代码变了以后，页面状态也会被算成结构（代码没变时有「先看代码」挡着）。设计师冻结前打开了菜单、切了标签、滚动触发了某个类，之后回到同一张画布时页面是默认状态，就会出提示，哪怕代码没变。只要还原那个状态，或者落地、放弃，提示就会消失。随机抽取的文字（不只是打乱顺序）同样会触发提示。
2. 换样式时，改动单里记的「改前」还是旧样式下的值。没有留到下一轮的改动，`claim` 不重读改前，所以 Agent 可能看到「从 400 改到 700」，而代码里已经是 600。这只影响说明，画布上显示的是对的。
3. 代定 2 里看不出来的那几种代码改动，画布既不提示也不换样式，设计师可能以为代码没变。
4. shadow root 里的样式（里面的 `<style>`、`<link>`，以及 adopted 的样式表）不会被换掉，变了只会触发情况 3。
6. 先看代码的回答可能是旧的：Next 项目没有 `CODE_EVENT`，设计师一直停在浏览器里、Agent 或别的进程在后台改了代码，回答还是 true，回到画布时当作没变。离开编辑模式、切回标签页时会重新问，所以只在「离开编辑模式之后、再进入之前，页面一直在前台，代码又被改了」时才会错。
7. 代码之外的东西也会让 git tree 变：仓库里任何没被忽略的文件变了（不只是这个项目的源码），都算代码变了，于是回到比指纹。这只会让「先看代码」少挡一些，不会漏报。
8. 代码变了、而页面又按时间画东西（几秒后才出现的元素、按日期切换的内容）：指纹会把它算成结构变了，出提示。数字和类名 hash 已经去掉，剩下的就是这类。Turbopack 的 CSS Modules / next/font 类名格式没有核对过，网站（Next 16，Turbopack）上手改了 CSS Module 时，可能被算成结构变了。
9. `restyle()` 按当前窗口高度判断高度类的媒体查询（`min-height` 之类），而 `vh` 按存下来的窗口高度换算。冻结之后窗口高度变了，两者可能对不上。没改，只记下。
5. 新的 `@font-face` 要在画布里加载。情况 2 那一次进入最多多等 500ms（`settle` 的上限）。

原话：我认为需要一个。「画布回到同一张时，样式跟着代码走，结构不跟」改变了 ADR 0001（一轮只对应一张画布、画布反映冻结时的页面）和 0013（回到同一张画布的代价）的结论，还带出了指纹这个新概念。我没有编号，草稿如下：

> **回到同一张画布时，样式跟上代码，结构不跟（ticket 141）**
> 一轮还有改动没落地，编辑模式回到同一张画布（ADR 0001、0013）。这段时间里有人手改了代码，画布就和代码对不上，设计师又不知道为什么。现在按页面指纹判断：只改了样式，画布换上页面现在的样式表，改动照旧；结构（元素、类名、文字）也改了，画布不动，提示设计师先让 Agent 落地，或者放弃留下的改动。Agent 落地这一轮带来的代码变化不算：一轮结束时有改动留下，就以那时的页面为准。
> 否决的做法：结构变了也换样式（旧的 DOM 配新的 CSS，Tailwind 项目里会坏）；每次都重新冻结、把改动重放上去（ADR 0013 已经否决过）；从源码判断（分不出 JSX 里只改样式的情况，也没法照顾 Next.js）。
> 后果：指纹必须在重新加载时保持稳定，交互状态、随机内容会导致误报；指纹存在 `.humantouch/page.json`，一轮结束时删掉。
