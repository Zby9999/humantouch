# 75: 按右边或下边定位的自由图层，拖控制点改尺寸时对边也不动

**What to build:** 页面里有些自由定位的图层是按右边或下边摆的（例如 Tailwind 的 `absolute right-2`、`bottom-4`），或者用 `translate(-50%)` 居中。拖它们的右边或下边控制点改尺寸时，现在只写了宽或高，页面仍按右边、下边摆，图层会往左、往上长：拖的边没跟着指针，本该不动的对边反而动了。改后，这类图层和按左边、上边摆的图层一样：拖哪条边，哪条边跟着指针，对边留在原处；改动单写清楚位置，Agent 落地后页面上也是这样。

参考本功能的 spec.md（同目录上一级），目标与指标以 docs/goals.md 为准，用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

## 背景

- 来自 ticket 69 的实现记录（2026-10-31，遗留风险第 1 条）。69 里自由定位的图层拖左边或上边时会同时写 X / Y，这时定位方式也改成按左、上，所以没有问题；只拖右边或下边时 X / Y 的值没变，编辑命令不写它们，页面就仍按原来的右边、下边摆。
- 修法的方向（69 的子 agent 建议）：自由定位的图层改尺寸时，总是写下对边的位置，所以编辑命令要能在值没变时也改定位方式；改动说明里让 Agent 把 `right` / `bottom` 定位改成 `left` / `top`。
- 可选做法：
  1. 改尺寸时一律改成按左边、上边定位（最简单，但会改掉页面原来的定位方式，窗口变宽时图层的位置可能和原来不同）。
  2. 保留原来的定位方式，按右边定位的就改 `right` 的值（窗口变宽时行为不变，但要让编辑层和改动单认识 `right` / `bottom`）。
  3. 不改，只在 spec 里写明这类图层拖右边、下边时会往反方向长。
- 这会改变 Agent 落地后页面的 CSS，以及在属性面板改 W / H 时的结果。画布线指挥在 69 之后开出（2026-10-31），等设计师定要不要做、选哪一种。

## 设计师决定（2026-11-01，分诊）

- 选做法 2：保留原来的定位方式。按右边、下边、居中定位，就是 Figma 里的 Right、Bottom、Center 约束。改成按左边、上边定位会悄悄改掉约束，而画布同时显示三个宽度，桌面视图里改一个右上角标签的尺寸，平板、手机视图里它就会离开右上角。
- 在属性面板改 W / H 时，和 Figma 一样，X / Y 不变。
- 居中的图层拖一条边时，两侧对称地长，保持居中。

*结论*

验收项都做到了。按右边、下边定位和用 `translate(-50%)` 居中的自由图层，拖控制点或在属性面板改 W / H 时保留原来的定位方式：拖的边跟着指针，对边不动；改的是 `right`、`bottom` 的值，或只改宽、高。改动说明写明保留定位方式、改的是哪个值，`done` 能核对 `right` / `bottom`。切换按钮的包没有变。

*做了什么*

- **认出定位方式**（新模块 `anchors.ts`）：在改尺寸所在的视图里读。
  - 页面或编辑层写了 `right`、没写 `left`，就是按右边定位；下边同理。
  - 左右（或上下）都写了、都没写，照旧当作按左边、上边。
  - 用 `transform`（Tailwind v3）或 `translate` 属性（Tailwind v4）往回挪了自身一半大小的，就是居中。两种写法都在示例项目里实际跑过。
- **拖控制点**：
  - 按右边定位的，拖右边时改 `right`，拖左边只改宽度，右边留在原处。下边同理。拖角、按住 ⇧ 或 ⌥ 也一样。
  - 居中的，那个方向总是从中间改（相当于按着 ⌥），只改尺寸，一直居中。只在一个方向居中时，另一个方向按它自己的定位方式。
  - 一次拖拽仍是一步撤销，Esc 回到按下前。
- **属性面板改 W / H**：和 Figma 一样，左边、上边不动。
  - 按右边、下边定位的，同时改 `right` / `bottom`，一步撤销。
  - 居中的只改尺寸，照样居中。
  - X / Y 显示改后的位置。
  - 在平板、手机视图里改时，尺寸行的断点标记同时管 `right` / `bottom`，重置时一起回去。
- **改动单**：
  - 多两种改动：`right`、`bottom`（标题 Right、Bottom，单位 px）。
  - 宽、高改动记下图层的定位方式（`anchor`：按右边或下边是 `end`，居中是 `center`），按第一次改时的样子记。
- **改动说明**：
  - Right / Bottom 改动的设计意图写明：这是右边离容器右边的距离，CSS 的 `right`，保持按这条边定位，不要改成按 `left`。
  - 宽、高改动多一行「Placement」，写明按哪条边定位或居中，保持不变。
  - 「How to write them」只在这一轮有这种改动时，才多「Placed from the right or bottom」和「Centered」两条。
  - 「How the page checks」多一句，说 `right` / `bottom` 怎么核对。
- **核对（`done`）**：
  - `right` / `bottom` 和 `left` / `top` 一样，按画出来的位置核对：页面上的 `right` 加右外边距，等于画布上的值加画布上的右外边距。
  - 没显示时，`done` 给出页面上的 `right` 和外边距。
  - 在窗口以外的宽度，页面在那里不按这条边定位（例如手机上按左边定位）时，不看那个宽度。原因见代定的事第 5 条。
- spec 的「控制点」「改动说明」「核对」三节各补了一条。

*代定的事（待设计师确认）*

指挥代定的（照做）：

1. 同时按左右两边（或上下两边）定位的图层（例如 `inset-x-0`、`left-0 right-0`，相当于 Figma 的 Left & Right）不在本 ticket 范围：照现在的做法，按左边处理。
2. 拖图层本身、方向键微移、在属性面板改 X / Y 不在本 ticket 范围：照现在的做法。现在移动这类图层时，定位方式**会被改掉**，在 e2e 里看过：
   - 按右边定位的：三种移动都写成 `left: …px; right: auto`，之后按左边定位。
   - 居中的：`translate` 保留，但 `left: 50%` 变成固定的 px，窗口变宽时不再居中。
   - 另外，拖动居中的图层，松手后它落在放下位置往左半个自身宽度的地方（拖 100 px，实际移了 140 px）。这是原来就有的问题，不是本 ticket 带来的。
3. 只在一个方向居中时，两个方向分开处理：居中的方向对称地长，另一个方向按它自己的定位方式。
4. 原来的 `right` / `bottom` 是百分比或别的单位时，改后的值写成 px，和 X / Y 一样。
5. 某个断点上定位方式不同时，按改尺寸所在视图的定位方式，写在那个视图对应的断点规则里。e2e 里看了一种情况：桌面、平板按右边定位，手机按左边定位（`max-md` 写 `left: 8px; right: auto`），在桌面视图把右边往里拖 30 px。
   - 结果：`right` 改为 70 px，作用于所有断点。
   - 桌面、平板视图里，图层仍贴着右边，离右边 70 px。
   - 手机视图里，`right` 和 `left` 都有值，浏览器按左边摆，图层仍离左边 8 px，宽度跟着变成 50 px。
   - 页面上照这样落地后，手机宽度上 `right` 并不决定图层的位置。所以 `done` 在不按这条边定位的宽度不看 `right`，否则会把画布上一样的结果报成「没有显示」。

我按「最贴近设计师决定」代定的：

6. 固定在窗口上、冻结时被钉住的图层（例如 `fixed bottom-4`），上下方向照旧按上边处理。画布把它们钉在设计师当时看到的位置，没有窗口的下边可以对。
7. 居中按「实际往回挪了自身一半」认。用 px 写的一半（例如宽 80 时写 `-translate-x-[40px]`）也会被当作居中，改宽后在页面上就不再居中了。这种写法很少见。
8. 尺寸行的断点标记同时管 `right` / `bottom`：它们只会跟着尺寸一起变，重置尺寸时一起回去，图层才回到原来的位置。标记的提示文字会写成「Width and Right」。
