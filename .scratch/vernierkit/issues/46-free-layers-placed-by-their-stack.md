# 46: Frame 里自由摆放的图层，合成后由 Stack 摆放

**What to build:** 设计师验收时，在新建的 Frame 里放了一段文字，然后把 Frame 合成 Stack，再把对齐改成居中，文字却一动不动。原因是合成时内边距取了外框到文字的全部距离（T 24 / R 24.48 / B 30.2 / L 90），Frame 里没有剩下空间，对齐就不起作用。Frame 里的图层是自由摆放的，Frame 的尺寸跟它们无关，所以剩余空间应该交给对齐。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] Frame 里全部是自由摆放的图层时，合成后每个方向的内边距两侧相同，取较近一侧的距离
- [x] 两个方向的对齐都取离图层现在位置最近的一种，合成时画面不动
- [x] 合成后改对齐，图层会在 Frame 里跟着动
- [x] 图层不是自由摆放的 Frame（跟着内容排版的）照旧：内边距取外框到图层的距离

## Comments

**实现记录（2026-10-28）**

- `stacks.ts` 的 `inferStack` 新增参数 `free`。为 true 时，内边距在每个方向上取两侧中较小的距离，两侧相同；顺排方向和交叉方向的对齐，都在扣掉内边距后的空间里取偏差最小的起点、居中或末端，相同时取起点。`nearest` 是两处共用的取法。
- `edits.ts` 的 `stack`：Frame 的子图层全部是绝对定位时传 `free`。
- 单元测试：原来的 Frame 合成用例，内边距从 `[30, 360, 330, 20]` 变为 `[30, 20, 30, 20]`；新增一例，单个图层靠右放，推断为右对齐，画面不动，改成居中后移到正中。
- 在预览里，把验收那一轮的 Stack 解散后再合成：内边距约 24 / 24.5，对齐为右侧居中，画面不动；改成居中后文字移到 Frame 正中。之后把那一轮恢复了原样。

**已知限制**

- Frame 是 `box-sizing: content-box` 且宽高写死时，加上内边距会让它变大（以前推断出的内边距更大，问题也更明显）。Tailwind 等多数页面用 border-box，不受影响。
- 验收那一轮里，那个 Stack 是改之前合成的，内边距仍是旧的。撤回那次合成再重新合成一次即可。
