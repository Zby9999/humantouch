# 112: 插入图片

**What to build:** 在 111 能替换图片的基础上，设计师可以把新图片放进页面：从 Finder 把一个或几个图片文件拖进任一视图，或者 ⌘V 粘贴剪贴板里的图片（例如截图）。拖进来的图按拖拽规则落下：落在 Stack 里就占一个位置，落在 Frame 的空白处就是自由定位（spec 68）；拖到三个视图之外的空白处，成为画布外的图层（ticket 106）。粘贴照 ⌘V 的规则，放进选中的 Stack 或 Frame，或选中图层之后。在页面上是插入一个图片图层，Agent 照项目的写法写 `<img>` 或 `next/image`。

参考本功能的 spec.md（同目录上一级，「拖拽与布局」「新建与删除」「合成与解散 Stack」里 ⌘V 的规则），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（ADR 0006、0009、0011、0013）。

**Blocked by:** 111（文件怎么存、改动说明、核对）；106（拖到空白处那一项）

**Status:** ready-for-agent

- [ ] 从 Finder 拖图片文件进视图：拖的过程里显示落点框和插入线，松手按拖拽规则插入；几个文件一起拖，按顺序插入几个图层；不是图片的文件不收
- [ ] 拖到空白处成为画布外的图层，和 106 新建的一样；⌘V 粘贴剪贴板里的图片照 ⌘V 的规则放
- [ ] 插入的图默认多大（原始尺寸、放不下时按容器缩小）、`alt` 默认写什么（例如文件名）作为代定
- [ ] 一次插入是改动列表里的一条，⌘Z 一步撤回；拖的过程里 ⌘Z、⇧⌘Z、Delete 不起作用（ticket 61、62）
- [ ] 改动说明写成插入一个图片图层：位置、尺寸、文件在 `.03kind/` 的哪里、放进项目资源目录；`done` 核对图层在、图片内容一样（照 111）
- [ ] 脚本扮演 Agent（`apply`）在 Vite 和 Next.js 示例上各走一遍「拖进一张图、落地、`done`」，核对是 ✓
- [ ] 原来的改动说明逐字不变：`--dry` 24/24、`--scripted` 全过；切换按钮的包逐字节不变
- [ ] 性能 headless 前后对比（`TK_PERF_HEADLESS=1`）：进入编辑模式、拖动不变差
- [ ] e2e 全过；docs/roadmap.md、spec 相应更新
