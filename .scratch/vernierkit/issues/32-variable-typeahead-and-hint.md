# 32: 设计变量：边输入边找

**What to build:** 设计师在属性面板的输入框里打字时，下拉列表实时过滤出匹配的设计变量（例如输入 pri 出现 primary-500、primary-600），可用键盘选中；输入具体数值且接近某个设计变量时，输入框内安静地提示这个变量，点击即换成变量，不弹窗、不阻止输入。改动说明仍只按精确相等判断变量（见 14 的 Comments）。

参考本功能的 spec.md（同目录上一级），目标与指标以 docs/goals.md 为准，用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

## Comments

**实现记录（2026-10-29）**

- 接近与按名称找（`client/variables.ts`，`Catalog` 多两个方法）：
  - `near(group, drawn)`：同组里最接近的一个变量，只在"接近但不相等"时给出。组里有变量恰好相等时不给（那是 14 的精确匹配）。
  - 项目自己的优先（2026-10-29 修正）：阈值内有项目自己定义的变量时，只在它们里面取最接近的一个，哪怕 Tailwind 自带的默认值在数学上更近；阈值内没有项目自己的变量时，才在 Tailwind 自带的默认值里取最接近的。"项目自己的 / Tailwind 自带的"即 14 的 `Variable.own`。阈值内本来看不出差别，项目自己的变量更符合设计系统的意图。几个一样近时仍取排在前面的。精确相等（`match`）与按名称找的排序不变。
  - 阈值都在 `NEAR = { color: 0.02, opacity: 0.005, px: 2, ratio: 0.1 }`：
    - 颜色：两个 8 位 sRGB 换到 OKLab 后的距离 ΔE ≤ 0.02，且不透明度相差 ≤ 0.005（选用变量会带上变量自己的不透明度，所以不透明度不同的不提示）。
    - 长度：相差 ≤ 2px，且 ≤ 变量自身值的 10%。两条都要满足。
    - 阴影：没有输入框，不提示。
  - `named(group, text)`：同组里名字包含这段文字的变量，不区分大小写，按列表顺序。没有文字时为空。颜色选择器与变量按钮的搜索也改用它。
  - 改动说明与改动单仍只用 `match`（精确相等），`edits.ts`、`variable-notes.ts` 没有改。
- 面板（`VariablePicker.tsx` 新增 `TypingProvider`、`useTypeahead`、下拉列表 `Matches`；`Properties.tsx` 的 `TextField` 接入）：
  - 能用变量的数值框（`VariableSlot` 里的宽高、最小 / 最大宽高、间距、四边内边距、圆角与四角、字号），以及有颜色变量时颜色字段的 hex 框（填充、渐变色标、描边、文字颜色）。
  - 按名称找：
    - 数值框里，开头不是数字、正负号或小数点的文字算名称；hex 框里，含有 0-9、a-f、`#` 以外字符的文字算名称。
    - 输入名称时，输入框下方出现 "Matching variables" 列表，列出同组名称含这段文字的变量（色块、名称、数值）。第一个预先选中；↑ / ↓ 循环选择，鼠标移过也会选中；回车或点击选用，输入框变为变量名标签。
    - Esc 关闭列表并恢复原值，焦点留在输入框，事件不往上传，所以选中不会被取消。没有匹配项时不显示列表。焦点一直在输入框里。
  - 接近提示：
    - 输入的值（还在输入，或刚输入并应用）接近同组某个变量时，输入框内右端显示这个变量的名字：淡色小标签，带细边框，悬停时变深。
    - 点击即选用：按下时不让输入框失焦，所以还没应用的输入不会先作为一步编辑应用，选用只算一步。不弹窗，不抢焦点，不挡输入。
    - 应用后，提示在这个字段对这几个选中图层显示该值期间一直保留，方便点击。换了图层、撤销或输入了别的值后消失。
  - 不采用提示时，改动单记录精确值，改动说明沿用 14 的写法："no Variable has … use the exact value"。
- 顺带修复：`TextField` 按 Esc 时先清空草稿再失焦，但失焦时提交读到的是旧的草稿，于是 Esc 反而把输入的值应用了。现在草稿同时记在一个 ref 里，Esc 后失焦不会再提交。
- 测试：
  - `edits.browser.test.ts`：长度的接近，包括 2px 与 10% 的边界、只在同组内、相等的不算；颜色的接近，包括相近、明显不同、不透明度不同；取最近的、一样近时取前面的；阈值内同时有项目变量与更近的 Tailwind 默认值时取项目变量（颜色 #EEF3FF 在 brand-50 与 indigo-50 之间，列表顺序颠倒也一样；长度同理），阈值内只有默认值时取最近的默认值；按名称找。
  - e2e `variables.spec.ts`：
    - 按名称找：hex 框输入 BRA，↑↓ 后回车；内边距输入 sec 后点击；Esc 恢复原值；输入数字不出列表，↑ 照常加一。
    - 接近提示：71px 提示 section，回车后仍在，点击后选用；24px 和 52px 不提示；字号 43px 提示 display，Esc 后不应用；颜色边输入边点提示，只算一步撤销。
  - e2e `react18-round.spec.ts`：输入 #EEF3FF（离项目的 brand-50 与 Tailwind 的 indigo-50 几乎一样近，indigo-50 略近），看到 brand-50 的提示、没有 indigo-50 的提示，不点；改动单记精确值，改动说明写 `bg-[#EEF3FF]` 和没有对应变量。

**已知限制**

- hex 框里，只由 a-f 组成的名称片段（如 `accent` 的前四个字母 `acce`、`fade`）按 hex 处理，要输入到第一个 a-f 以外的字母才出现列表。
- 半透明颜色只提示不透明度相同的颜色变量。
- "接近"按画布读成 8 位 sRGB 后的颜色计算。阈值内项目自己的变量总是优先于 Tailwind 自带的默认值，所以一个明显更近的默认值也会让位于阈值边缘的项目变量。
- 提示与列表只在可以选用变量的字段里有：行高、字间距、描边粗细、不透明度、阴影的各项数值都没有（与 14 相同）。
- 下拉列表按打开时的位置固定在输入框下方，面板在列表打开时滚动，列表不跟着移动，直到匹配项的数目变化或列表关闭。
- 输入框的角色仍是文本框，只加了 `aria-controls`、`aria-activedescendant` 与 `aria-autocomplete`，没有改成 `combobox`（现有测试和读屏都按文本框找它）。
- 提示是一个可用 Tab 到达的按钮，在颜色字段里会在 hex 与不透明度之间多一个 Tab 停靠点。
