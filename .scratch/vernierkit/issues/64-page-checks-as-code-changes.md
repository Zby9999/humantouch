# 64: 页面自己核对，进度按页面算

**What to build:** 认领之后，代码一变，页面就核对还没显示的改动，进度环按页面上真的显示了几条来长，不再等 Agent 一条条报。`done` 可以一次报多条（如 `done 1 2 3`），每条照样给出核对结果；页面已经核对过的直接返回结果，不用再等。页面看不出来的改动（新建、换容器、改文字、生成说明等）仍按 `done` 算。Skill 里「每条改完立刻 `done`」放宽为「改完一条或一组相关改动后 `done`，`finish` 前至少一次」。`finish` 和手动结束一轮时记下的结果以页面核对为准。

## 背景

- ADR 0006 让 Agent 每条改完立刻 `done`，好在改动还在上下文里时就知道有没有被别的样式盖住。代价是每条多一次工具调用，而且 Agent 不照做时，进度环停住、改动没有核对。
- 页面在代码变化时就核对，Agent 什么时候问都能拿到当时的结果，所以可以放开批量报。
- 编辑层线合并时（2026-10-30）报告：手机宽度的核对最多只等 3 秒，开发服务器 3 秒内没送来新 CSS，就会读到旧值，报「没显示」。e2e 里那条测试因此偶尔失败。误报会让 Agent 去查一个不存在的问题。用户决定在本 ticket 里一并处理。
- 编辑层线修测试素材时（2026-10-30）又发现「认领时还没保存的编辑不进这一轮」那条 e2e 在机器忙时会偶尔失败。它和上一条在同一处测试、同属落地流程，用户（2026-10-31）决定一起交给本 ticket 跑稳。

- 认领之后，页面在代码变化时核对还没显示的改动，结果交给本机服务。

- 进度环和一轮的结果按页面算：
  - 页面显示了的改动算已落地，不论 Agent 是否 `done`；
  - 页面看不出来或没能核对的改动，`done` 后算；
  - `done` 过但页面没显示的不算。
  - 归档的 `result.json` 多了 `applied`，`last` 按它标 Applied。
- `done` 可以一次报多条，每条给出核对结果。页面已显示的，页面当场再看一眼就回答，不再等；其余的，页面先等这次代码真的到了页面再下结论，具体是：
  - `done` 带上 git 看到的最后修改时间；
  - 页面等到有一次热更新不早于这个时间，且开发服务器静了 0.5 秒；
  - 有热更新在途就一直等，整个回答最多 20 秒；
  - 再给 1.5 秒让新样式显示出来。
  - 读不到热更新时，仍是原来的 3 秒。
- 桌面视图的改动在页面窗口宽度和每个视图宽度（默认 768、390）都要显示才算显示。本轮在某个断点单独改过同一图层同一属性的，该断点范围里的宽度不看。不显示时，`done` 说是在哪个宽度、值是多少，提示去查那个宽度上的断点写法。
- 窗口以外的宽度不再重新加载页面，改为在页面的一份逐节点副本上看：
  - 副本放在那个宽度的隐藏 iframe 里，和视图一样只反映 CSS 响应式，不跑页面脚本；
  - 副本随页面同步；
  - 副本的建立、同步和排版各占一个任务，核对按 12ms 分片。
- `finish` 先请页面把能核对的改动按最后一次改动再看一遍（和 `done` 一样等代码到页面），再归档。所以 Agent 不跑 `done`、改完立刻 `finish`，也不会少记。设计师手动结束一轮时用页面当时的结果。
- 两条在机器忙时会失败的 e2e：
  - 「手机视图里做的改动按手机宽度核对」：副本跟着页面的 CSS 走，加上等热更新到达，不再读到旧 CSS；

**4. 进度环在一轮中途不多算（7fcb5fe，review 后 fd1f5ff）**

  - 页面此刻看不了（例如图层不在当前页面上，换了路由）不算弄掉。

**5. e2e 时连着的「第二个页面」（bab6ea7）**

- 来源是我们自己的本机服务，不是外部的东西。
- 查法：临时让本机服务把每个 `/events` 连接的开和关记到文件里（端口、来源、User-Agent），跑了一遍全套 e2e。
  - 示例项目的服务上共开了 99 次、关了 98 次。
  - 没关的那一次在 `autosave.spec.ts`「a round saved before the instances of a layer shared their edit styles opens as it was in every view…」里，00:11:48.868 开的，对方端口已经是 `undefined`。
  - 从那以后，示例项目上每个测试都多算一个页面：bench-scenarios、claim、round、off-canvas-round 等。
- 原因：
  - 示例项目用 React 的 StrictMode，开发时 effect 会挂上、马上卸下、再挂上。所以页面开始听 `/events`，几毫秒后就断开，再重新连。
  - 本机服务收到 `/events` 后，先 `await` 读这一轮的状态，再登记这个页面并挂上「断开」的处理。
  - 页面恰好在这次 `await` 期间断开时，「断开」事件已经过去了，这个连接就永远留在页面名单里，直到开发服务器重启。
  - 这是时序问题，所以只是「偶尔」。
- 影响：`checks.json` 的 `pages` 多 1。`done` 以为还有一个页面会回答。9704022 之前，连页面看不出来的改动也要等满超时；9704022 之后影响已经小了，但 `pages` 仍然不对。设计师自己开发时，每次刷新页面都有同样的机会多算一个。
- 修法：读完状态后先看连接是否已经断开；断开了就不登记。
- 单测：40 次「刚连上就断开」之后，`pages` 是 0；修之前是 10。
- 修好后又跑了全套 e2e，309 个通过、1 个跳过。这一遍没有再记连接。
- 测量台（5620–5649）、残留的开发服务器（5624）、Playwright 复用的服务器都和这件事无关：
  - 测量台和残留服务器服务的是临时目录里的副本，有各自的本机服务；
  - 记录里所有连接都来自 5600 上的示例项目页面。

- 所以进度环要等下一次热更新，或 `done`、`finish`，才会长。一轮的结果不受影响，`done` 和 `finish` 都会重新看。机器忙时 20 次里出现 1 次。

修法（`page-checks.ts`）：
- 页面开始核对时（认领、重新读这一轮、认领期间打开页面），也和收到热更新一样，在接下来约 3 秒里跟着页面自己的变化再看。热更新可能就在开始之前到的，页面要等开始以后才画出来。
- 3 秒是原来每次热更新之后就有的那个窗，没有改长；窗里的每一眼照旧分片。只改了窗从什么时候开始算，等 `done` 的规矩（代码到了没有、开发服务器静了没有）没变。
- 和 66 的「没认领就改代码」提示不相干：提示只在编辑模式、没认领时由 `code-changes.ts` 看热更新，这里只在认领后。改动没碰提示的代码。
- 不影响「进度环中途不多算」：窗里的每一眼和热更新之后一样，显示过的改动也在窗口宽度上再看一遍，被弄掉了照样减少。
- spec「核对」一节第一条写明了：每次热更新之后、以及页面开始核对时，约 3 秒里跟着页面自身的变化再看。

**`done` 按问题的标记认回答，不再按毫秒时间（2026-10-31，提交 2f035d6 和本条，起点 4d57d39）**

上一节「跑全套时发现的」那条，总调度定在 65 之前修：65 两家各复测 30 次，碰上一次就会给 Agent 一个假的「没显示」。

问题：
- `done`、`finish` 问页面时，问题里带 `at`（当时的毫秒时间）。页面回答时带回这个 `at`，CLI 和本机服务按 `at` 相等认出回答。
- 页面在代码变化时自己看的结果，`at` 也是当时的毫秒时间。两者落在同一毫秒时，页面自己看的结果就被当成了回答。
- CLI：`done` 当场收下页面自己看的「没显示、12px」，不再等真正的回答（66 那次就是这样，`done` 不到 30ms 就退出）。
- 本机服务也按 `at` 判断「这是被问到的」：同一毫秒里一个落后页面没被问到的「没显示」，会被当成回答收下，盖掉别的页面看到的「显示了」，进度环少算。

修法（协议，`service-protocol.ts`）：
- 问题（`CheckAsk`）多了 `key`：CLI 每问一次（`done`、`finish` 各一次）用 `randomUUID()` 生成一个。`at` 保留，只表示什么时候问的（测量台按它记 `done` 的时间）。
- 页面的结果（`CheckReport`）多了 `answers`：回答某个问题时带上那个问题的 `key`；页面在代码变化时自己看的结果不带。`at` 统一表示页面什么时候看的（回答也用页面看的时间，不再抄问题的 `at`）。
- CLI 只收 `answers` 等于这次 `key` 的结果；本机服务只把带着当前 `check` 或 `closing` 的 `key` 的结果当作被问到的。「两个页面回答同一个问题时，能核对的那个说了算」也改为按 `answers` 判断。
- 页面每个问题只答一次，也改为按 `key` 记；编辑层按 `key` 的变化去答新的问题。
- 64 原有的行为没有变：页面已显示的当场再看一眼就回答；`done 1 2 3` 一次问多条；等 Agent 最后一次改动到达页面再下结论；有第二个页面连着时，没有页面能核对的改动不白等。没有打开的页面时，用这一轮页面看到的「显示了」，照旧按 `at` 不早于认领。
- 66 的提示没有碰：提示的代码（`code-changes.ts`、`CodeChangeNotice.tsx`）没改。
