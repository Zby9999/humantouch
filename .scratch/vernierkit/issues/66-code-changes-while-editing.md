# 66: 编辑中代码在变时先暂停

**What to build:** 编辑模式中，没有 Agent 认领改动单，页面却因为项目源码变化而热更新时（例如 Agent 没走 Skill、凭对话直接改了代码），编辑层暂停编辑，提示设计师「代码在变，但没有 Agent 认领改动」，给两个选择：继续编辑（这次变化与我的改动无关），或回到预览模式（改动保留，下次进入编辑模式回到同一张画布）。不影响页面的文件变化、编辑层自己的保存都不触发提示。

参考本功能的 spec.md（同目录上一级），目标与指标以 docs/goals.md 为准，用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（ADR 0005、0012）。

## 背景

- ADR 0005 靠认领避免画布和代码冲突，但前提是 Agent 走了 Skill。没认领就改代码时，画布已过期，设计师接着改会和代码冲突。

## Comments

**做了什么（提交 03d8a7a、b25e582、74de8ea、eca42fe、c351f83 和本条，起点 6259622）**

- 编辑模式中、这一轮没被认领时，开发服务器给页面送来热更新（复用 64 的 Vite 热更新通知 `CodeUpdates`），编辑层就暂停编辑，盖一层提示「The code is changing, but no Agent has claimed your changes」，两个选择：
  - **Keep editing**：照常编辑，焦点回到提示出现前的地方。
  - **Back to preview mode**：回到预览模式，改动立即保存；下次进入编辑模式回到同一张画布。
- 暂停的做法：
  - 外壳设成 `inert`，上面盖一层全屏的底，指针、焦点都进不去。
  - 编辑层自己的快捷键都在 window 上监听。提示的模块加载时，先在 window 上加一个捕获阶段的监听，提示在的时候拦下所有按键；按键的默认动作照常，所以提示的按钮仍能用回车、空格，Tab 在两个按钮之间转。
  - 正在输入的文字、输入框里没提交的值，随焦点移到提示上而提交，算暂停前的改动。
  - 鼠标正按着（ADR 0012 的几种操作）时，等松手、这次操作做完再暂停。
- 什么算代码在变：先实测过示例项目，哪些文件变化会送到页面：
  - 改 `notes.md`、没被引用的 `.ts`（里面写了 Tailwind 类名也一样）、`.vernier/` 里的 JSON：不送任何消息。
  - 改 `.vernier/canvas.html`：Vite 送一条带这个路径的 full-reload，不是当前页面，客户端不刷新；我们只听热更新，不听 full-reload。
  - 改 `Card.tsx`、`index.css`：送 update。
  - 所以定为「开发服务器给这个页面送来了热更新」：页面用到的文件才算，不用另列文件类型。前后相隔不到 1 秒的热更新算同一次变化（一次保存几个文件、一次编辑的 CSS 和模块先后到）。
- 和 64 的「认领后核对」怎么分：
  - 已认领时编辑模式已经收起（ADR 0005），代码变化归 64 的核对，不提示。
  - 但 Agent 可能认领后马上改代码，热更新比本机服务推送的认领先到。所以编辑层看到热更新时，先问本机服务现在的状态：新加 `GET /status`，当场读状态文件。已认领就不提示。
  - 提示出现后 Agent 才认领：提示随编辑模式一起收起，照常进入落地。
  - 67 的「Agent 好像停了」只在认领后、在切换按钮上出现；这个提示只在没认领时出现，两者不会同时出现（spec 写明了）。
- spec 加了用户故事 91a、架构决策里一句，以及「编辑中代码在变（ticket 66）」一节；「状态」一节写了 `GET /status`。GLOSSARY 没有加新词：「暂停编辑」「提示」都是普通用语，「认领」等已有的词照原义用。

**跑测试时发现的（64 的机制，不是 66 的，没改）**

- 「认领后马上改」那条测试原来不跑 `done`，等进度环自己到 1，在机器忙时 20 次里失败 1 次。
- 从 trace 看，经过是这样：
  1. 认领后，页面重新读这一轮；
  2. 64 的核对在 Vite 的 afterUpdate 之后才开始，第一次看在 React Fast Refresh 重画卡片之前，报了「没显示」；
  3. 接着页面重画了，但这个核对没收到那次热更新，按 `AFTER_CODE_MS` 的规矩不理页面自己的变化；
  4. 直到下一次代码变化才看到。
- 所以 Agent 认领后几十毫秒内就改代码、又不跑 `done` 时，进度环会晚到下一次热更新（或 `done` / `finish`）才长。`done`、`finish` 都会重新看，结果不受影响。
- 测试改成照正常的 Agent 跑 `done`（eca42fe），只测提示。要不要修 64 的这一处，请总调度决定。
