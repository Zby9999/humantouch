# 34: 切换按钮先加载，编辑层按需加载

**What to build:** 页面加载时只加载切换按钮（≤ 10KB），编辑层其余部分在第一次进入编辑模式时才加载，且进入编辑模式不因按需加载而明显变慢。

参考本功能的 spec.md（同目录上一级），目标与指标以 docs/goals.md 为准，用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

## Comments

**实现记录（2026-10-29）**

- 拆分：`vernierkit/react` 的开发版（`dist/react.dev.js`）现在只挂载 `LazyEditorLayer`。它渲染切换按钮（同一个 `Toggle` 组件），其余部分是 `dist/editor.dev.js`，用动态 `import()` 加载。Preact、`Toggle`、切换按钮样式和读写本轮所需的最少服务代码，由 tsup（esbuild 的 code splitting）放进两边共用的 `chunk-*.js`。`editor.dev` 单独作为一个入口，这样动态 import 指向的文件名固定，测试能认出来。
- 什么时候加载其余部分：
  - 第一次点切换按钮：先打 `vernierkit:enter-edit-mode` 标记，再加载，然后编辑层直接以编辑模式挂载（`EditorLayer` 新增 `enter`、`saved` 两个初始 props）。
  - 页面加载时已有保存的一轮：立刻加载，以预览模式挂载。角标、改动列表、锁定都要靠其余部分。
  - 切换按钮在等待期间监视本轮状态，一旦被认领就立刻加载，锁上按钮并在页面上核对。
  - 指针移到切换按钮上或按钮获得焦点时预取（只取模块，不挂载）。
- 加载中：切换按钮带 `aria-busy="true"`，沿用锁定时的变暗样式（`.vk-toggle:is([aria-disabled], [aria-busy])`），这期间再按不会切回去。`EditorLayer` 等待画布所需数据期间也用同一个状态。
- 体积：
  - 浏览器端构建改为压缩，并带 source map。
  - tsup 插件 `compactCss` 在构建时去掉 `styles.ts` / `toggle-styles.ts` 里 CSS 的注释和多余空白，`${…}` 占位原样保留。
  - 样式拆成 `toggle-styles.ts`（页面加载时就要的部分）和 `styles.ts`（其余部分加载时插进 Shadow DOM，排在切换按钮样式之后）。角标和进度环的样式归入后者，因为它们只在其余部分加载后才出现。
  - 客户端服务拆出 `round-watch.ts`（加载和监视本轮），`service.ts` 在其上补齐其余接口。
  - `ENTER_MARK` 移到 `host.ts`。
- Vite 插件在开发时把 `vernierkit` 加进 `optimizeDeps.exclude`。不加的话，Vite 的依赖预构建会把切换按钮重新打一遍，不压缩，代码约 11.4KB（gzip），而且会把其余部分合进同一组 chunk。加了之后按发布时的文件原样提供，`editor.dev.js` 只在需要时请求。
- 测试：
  - `e2e/tests/toggle-first.spec.ts`
    - Vite 示例：页面加载时请求的包内文件（按发布时的文件计）gzip 后 ≤ 10 KiB，进入编辑模式后才请求其余文件，且其余部分至少是前者的 4 倍。
    - Next 示例（Turbopack）：加载时的脚本里有切换按钮、没有返回预览模式的按钮文字，进入编辑模式后才有。
    - 加载被拖住时，切换按钮显示忙碌，再按不会切回去。
  - `install.spec.ts`：用打包安装的副本，按 Vite 实际提供的代码（去掉 Vite 内联的 source map）计 ≤ 10 KiB，其余部分在第一次进入编辑模式时加载。
  - `next-install.spec.ts`：webpack 模式下同样只在进入编辑模式时加载其余部分。
  - `production-build.spec.ts`：残留检查加上只在其余部分里的文字（返回预览模式的按钮文字），覆盖两部分都不进正式构建。
  - Next 的正式构建仍由 `doctor` 检查。

**第一次进入编辑模式的耗时（Comments 要求的对比）**

- 方法：一次性脚本（放在仓库外的临时目录，没有保留）。
  - 用 Playwright 自带的 chromium headless shell，视口 1280×800，`reducedMotion: reduce`，接本机真实服务。
  - 每次运行用新的浏览器上下文（无缓存），先热身一次，再测 15 次，取中位数。
  - 操作：指针移到切换按钮上，停留 0ms 或 150ms，然后按下、松开。
  - 读的是 `vernierkit:enter-edit-mode` 这个 measure：从切换按钮的点击处理到画布画在屏幕上，和 ticket 22 用的是同一个量。前后两个版本都在点击时打标记。
  - 按下到松开之间，测量工具自身的间隔有约 40ms 抖动，两个版本都有，所以不用"从按下算起"的数字。
  - 之前的版本是 e1ae938 的构建：仓库示例上临时换入它的 `dist`；打包安装的副本则从 e1ae938 `git archive` 出来打包。

| 毫秒，中位数 | 停留 0ms：之前 → 之后 | 停留 150ms：之前 → 之后 |
|---|---|---|
| 仓库内 Vite 示例 | 56 → 76（另一轮 58） | 36 → 35（另一轮 47） |
| 打包安装的 Vite 副本（前后交替各测两轮） | 57 / 58 → 80 / 59 | 42 / 43 → 53 / 50 |
| Next 示例（Turbopack） | 29 → 37（另一轮 39） | 32 → 44（另一轮 47） |

- 只按需加载、不预取时（测法相同，计时从按下算起）：Vite 示例 56 → 89，Next 示例 48 → 68，多出 20–35ms。多出来的是点击后才取、才编译 `editor.dev.js` 的时间。
- 为什么预取，在哪预取：
  - 指针移到切换按钮上或按钮获得焦点（键盘 Tab）时预取。人点按钮前，指针一般会在目标上停一下；用键盘时，焦点总在 Enter 之前到。
  - 停留 150ms 时，Vite 的差距基本消失；停留 0ms 是最坏情况，仍多 0–25ms。
  - 剩下的几毫秒到十毫秒，是编辑层挂载后才去向本机服务取 breakpoints、off-canvas 和状态（之前在页面加载时就取了）。
  - 所有情况都远低于 goals 的 150ms。
  - 不在浏览器空闲时预取：那样每次页面加载都会把其余部分取下来，等于没有按需加载。

**已知限制**

- 体积：
  - 10KB 按 10 KiB（10,240 B）计。现在 10,014 B，按十进制的 10,000 B 算多了 14 B；余量很小，切换按钮再加东西就会超出预算，测试会失败。
  - Vite 开发服务器给它提供的每个模块都内联一份 source map（我们的 source map 也会并进去），所以页面实际下载的字节远多于代码本身：打包安装时约 89KB gzip，之前是 410KB。这部分是注释，不会执行。
  - 仓库内的示例通过 workspace 链接这个包，`@vitejs/plugin-react` 会给它加上 React Refresh 代码，提供的代码约 11.2KB。正常安装（在 node_modules 里）不会这样，所以示例上的测试按发布的文件计。
  - Next（Turbopack 和 webpack）把切换按钮和页面自己的代码打在同一组 chunk 里，没法单独计字节。测试只检查其余部分加载的时机，体积以发布的文件为准。
- 什么时候其余部分会随页面一起加载：
  - 有保存的一轮（还没落地的改动）时，页面加载就会加载其余部分。角标点开是改动列表，锁定和核对也都在其余部分里。所以"页面加载 ≤ 10KB"只在没有进行中的一轮时成立。
  - 让切换按钮自己显示角标数、点角标时再加载，可以把这种情况也挡住。但角标和进度环的样式要放回切换按钮样式，预算放不下。
  - 已有一轮或被认领时，其余部分加载完会换掉切换按钮的 DOM。如果这一瞬间正在拖动、按住或聚焦切换按钮，这些状态会丢失。这只发生在页面刚加载后的几十毫秒内。
  - 页面加载时取本轮失败（例如服务没起）不会加载其余部分，第一次进入编辑模式时由编辑层重新加载本轮并报错。
  - 点击时如果本轮还没取回来，编辑层会自己再取一次。
- 测试：Playwright 的 `click()` 会先移动指针，所以测试分不清其余部分是因指针移上去而预取，还是因点击而加载。测试断言的是"页面加载并空闲后没有请求，进入编辑模式时才请求"。React 18 示例没有单独的加载时机测试，它的现有 e2e（进入编辑模式、一轮落地）照常通过。
- 构建：
  - 浏览器端构建现在是压缩过的，附 source map，包里因此多了约 1.3MB 的 `.map` 文件。
  - `compactCss` 假定这两个样式文件的 CSS 里没有含注释、冒号或逗号的字符串。
