# 54: 核对描边粗细时先比较样式里写的值

**What to build:** Agent 运行 `done` 时，描边粗细的核对先比较设定它的样式里写的粗细（与面板显示粗细所用的是同一个来源），读不到时才退回 51 的做法，按浏览器画出来的值比较；这样 1x 屏上 1px 与 1.5px 也能分开，不再出现虚假的 ✓。

参考本功能的 spec.md（同目录上一级，"核对"一节），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策，尤其是 ADR 0006。

**Blocked by:** 51（已完成）

**Status:** ready-for-agent

- [ ] 1x 屏上，设计师把粗细从 1px 改为 1.5px、Agent 没改源码时，`done` 说明页面没有显示；源码改为 1.5px 后，说明页面显示了这条改动
- [ ] 源码里写的值与改后值不同时（例如源码写 1.25px、改后值是 1px），`done` 说明页面没有显示
- [ ] 粗细经 `var()` 的简写写入时（例如 `border: var(--w) solid`），不把另一条优先级更低、写了 px 的规则当成来源，而是退回按画出来的值比较；面板显示的粗细也随之修正
- [ ] 已有属性的核对结果不变

## 背景

- 51 让核对两边都由浏览器画一遍再比较，避免了小数粗细的误报；但 1x 屏上画出来相同的粗细（1px 与 1.5px 都画成 1px）比不出区别：设计师改成 1.5px、Agent 什么都没改，`done` 也会说明页面显示了这条改动，这正是 ADR 0006 要避免的虚假的 ✓。2x 屏上没有这个问题。
- 51 的已知限制里记录了样式来源可能找错：经 `var()` 的简写会让浏览器把各条长写属性读成空，这条规则不参与比较，于是另一条优先级更低的规则可能被当成来源。"Currently set by" 也有同样的问题。
