# 79: 移动按右边、下边定位或居中的自由图层时，保留原来的定位方式

**What to build:** 页面里有些自由定位的图层按右边、下边摆（例如 Tailwind 的 `absolute right-2`、`bottom-4`），或者用 `translate(-50%)` 居中（`left-1/2 -translate-x-1/2`）。ticket 75 让它们在改尺寸时保留原来的定位方式，但移动它们（在画布上拖动、方向键微移、在属性面板改 X / Y）时，定位方式仍会被悄悄改掉：按右边定位的改成按左边，居中的 `left: 50%` 变成固定的 px。画布同时显示三个宽度，桌面视图里挪一下右上角的标签，平板、手机视图里它就离开了右上角。另外，拖动居中的图层，松手后它落在放下位置往左半个自身宽度的地方（拖 100 px，实际移了 140 px），这是原来就有的毛病。

参考本功能的 spec.md（同目录上一级），目标与指标以 docs/goals.md 为准，用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

**Blocked by:** 75

**Status:** needs-triage

- [ ] 拖动居中的自由图层，松手后图层落在放下的位置，不偏半个宽度
- [ ] 移动按右边、下边定位或居中的自由图层（拖动、微移、改 X / Y）时，定位方式照设计师选的做法处理（见下面可选做法）
- [ ] 改动单和改动说明写明要改的是哪个值；`done` 核对通过
- [ ] e2e 覆盖：按右边定位、按下边定位、居中三种图层，各拖动一次、微移一次、在属性面板改一次 X 或 Y

## 背景

- 来自 ticket 75 的实现记录（2026-11-02，代定的事第 2 条、遗留风险第 1 条）和画布线的整线审查。75 只管改尺寸；移动不在它的范围，照原来的做法，e2e 里看过：
  - 按右边定位的：拖动、微移、改 X 都写成 `left: …px; right: auto`，之后按左边定位。
  - 居中的：`translate` 保留，但 `left: 50%` 变成固定的 px，窗口变宽时不再居中。
  - 拖动居中的图层，松手后偏半个宽度（原来就有，和定位方式无关，应当修）。
- 同一轮里先改尺寸（记下了 `right`）再移动，改动单里会同时有 `right` 和 X 两条，这种组合没有专门测过。
- 可选做法（定位方式部分；拖动偏半个宽度的毛病不管选哪种都修）：
  1. 移动时也保留定位方式，和 Figma 的 Right、Bottom、Center 约束一样：按右边定位的改 `right` 的值；居中的保留居中，只改它居中所在的位置。
  2. 移动时改成按左边、上边定位（现在的做法），但在改动说明里写明「从按右边定位改为按左边定位」，让设计师和 Agent 都知道定位方式变了。
  3. 只修拖动偏半个宽度，定位方式照现在。
- 这会改变 Agent 落地后页面的 CSS，以及三个视图里移动后图层贴着哪条边。画布线指挥在 75 之后开出（2026-11-02），等设计师定要不要做、选哪一种。
