# 79: 移动按右边、下边定位或居中的自由图层时，保留原来的定位方式

**What to build:** 页面里有些自由定位的图层按右边、下边摆（例如 Tailwind 的 `absolute right-2`、`bottom-4`），或者用 `translate(-50%)` 居中（`left-1/2 -translate-x-1/2`）。ticket 75 让它们在改尺寸时保留原来的定位方式，但移动它们（在画布上拖动、方向键微移、在属性面板改 X / Y）时，定位方式仍会被悄悄改掉：按右边定位的改成按左边，居中的 `left: 50%` 变成固定的 px。画布同时显示三个宽度，桌面视图里挪一下右上角的标签，平板、手机视图里它就离开了右上角。另外，拖动居中的图层，松手后它落在放下位置往左半个自身宽度的地方（拖 100 px，实际移了 140 px），这是原来就有的毛病。

参考本功能的 spec.md（同目录上一级），目标与指标以 docs/goals.md 为准，用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（尤其是 ADR 0014）。

**Status:** done

- [x] 移动按右边、下边定位或居中的自由图层（在画布上拖动、方向键微移、在属性面板改 X / Y）时，保留原来的定位方式（ADR 0014）：按右边定位的改 `right` 的值，按下边定位的改 `bottom` 的值；居中的保持居中，只改它偏离中心多少（例如 `left: calc(50% + 20px)`，具体写法由实现定，改动说明要讲清楚）。三个视图里，图层贴着的那条边都不变。

## 背景

- 来自 ticket 75 的实现记录（2026-11-02，代定的事第 2 条、遗留风险第 1 条）和画布线的整线审查。75 只管改尺寸；移动不在它的范围，照原来的做法，e2e 里看过：
  - 按右边定位的：拖动、微移、改 X 都写成 `left: …px; right: auto`，之后按左边定位。
  - 居中的：`translate` 保留，但 `left: 50%` 变成固定的 px，窗口变宽时不再居中。
  - 拖动居中的图层，松手后偏半个宽度（原来就有，和定位方式无关，应当修）。
- 同一轮里先改尺寸（记下了 `right`）再移动，改动单里会同时有 `right` 和 X 两条，这种组合没有专门测过。
- 可选做法（定位方式部分；拖动偏半个宽度的毛病不管选哪种都修）：
  1. 移动时也保留定位方式，和 Figma 的 Right、Bottom、Center 约束一样：按右边定位的改 `right` 的值；居中的保留居中，只改它居中所在的位置。
  2. 移动时改成按左边、上边定位（现在的做法），但在改动说明里写明「从按右边定位改为按左边定位」，让设计师和 Agent 都知道定位方式变了。
  3. 只修拖动偏半个宽度，定位方式照现在。
- 这会改变 Agent 落地后页面的 CSS，以及三个视图里移动后图层贴着哪条边。画布线指挥在 75 之后开出（2026-11-02），等设计师定要不要做、选哪一种。

## 设计师决定（2026-11-02，分诊）

- 选做法 1：移动时也保留定位方式，和 Figma 的约束一样。理由和 75 选做法 2 相同：画布同时显示三个宽度，定位方式被悄悄改掉，旁边的视图里图层马上跑位；而且改尺寸保留、移动不保留，同一个图层先拖大再挪一下就变回按左边定位，前后不一致。
- 拖动居中的图层偏半个宽度的毛病一并修。
- 原则记为 ADR 0014。
- （2026-11-02，指挥问设计师）**拖进另一个 Frame**：按右边定位（或居中）的自由图层被拖进另一个 Frame、在那里仍是自由定位时，保留原来的定位方式，按新 Frame 算（和 Figma 一样，约束跟着图层走）：原来按右边定位的，进了新 Frame 仍按新 Frame 的右边摆、改 `right` 的值；居中的仍居中。
- （2026-11-02，指挥问设计师）**副本**：用 ⌥ 加拖动、⌘D 或复制粘贴复制一个按右边定位（或居中）的自由图层时，副本也保留原图层的定位方式（和 Figma 一样）。

## Comments

**实现记录（2026-11-02）**

*结论*

验收项都做到了。按右边、下边定位和用 `translate(-50%)` 居中的自由图层，在画布上拖动、方向键微移、在属性面板改 X / Y 时都保留原来的定位方式：按右边定位的改 `right`，按下边定位的改 `bottom`，居中的仍居中，只改它偏离中心多少（`left: calc(50% + 20px)`）。三个视图里，图层贴着的那条边都不变。拖动居中图层松手后偏半个宽度的毛病修好了，拖动途中它也一直在指针下。拖进另一个 Frame 和复制时也保留定位方式，按新的 Frame 算（设计师 2026-11-02 定）。改动说明写明保留定位方式、改的是哪个值，`done` 能在每个视图的宽度核对居中图层的位置。切换按钮的包没有变，拖动的帧率没有变。

*做了什么*

- **移动时按定位方式改值**（`edits.ts`，拖动、微移、改 X / Y 都走这里）：
  - 按右边定位的：往右移多少，`right` 就减多少；改动单里是一条 Right 改动，没有 X。下边同理。
  - 居中的：定位它的那一边（`left`，从右边居中的是 `right`）保留百分比，只改多出来的 px。例如 `left: 50%` 往右移 20px，写成 `left: calc(50% + 20px)`；从右边居中的 `right: 50%` 往右移 20px，写成 `right: calc(50% - 20px)`。改动单里仍是 X（或 Right）改动，另记下百分比和前后多出来的 px（`centeredOn`），并记下居中（`placedFrom`）。
  - 百分比从页面写的值里读出，Tailwind v4 的 `left-1/2`（`calc(1/2 * 100%)`）、v3 的 `50%` 都认得。
  - 属性面板的 X / Y 照旧是图层的 `left` / `top`，居中图层的 X 仍是它的中点（75 遗留风险第 2 条，没改）。
  - 定位方式按移动所在的视图读；同时按两边定位的照旧按左边，钉在窗口上的固定图层上下方向照旧按上边。
- **拖动居中图层不再偏**（`canvas-drag.ts`、`structure-edits.ts`）：
  - 原来拖动时，编辑层用行内的 `translate` 移动图层，盖掉了图层自己的 `translate: -50%`（Tailwind v4 的写法），拖动途中图层显示在指针右边半个宽度处。现在拖动的位移加在图层自己的 translate 上。
  - 放下的位置按图层画出来的边框算，原来直接当作 `left`，居中图层就落在往左半个宽度处（v3、v4 都是）。现在减去图层自己的 translate 再当作 `left`。微移、粘贴、解散 Frame 的位置也按同样的算法。
- **拖进另一个 Frame、复制**（设计师 2026-11-02 定）：
  - 按右边定位的，进了新 Frame 仍按新 Frame 的右边摆，`right` 按放下的位置和新 Frame 的宽度算；居中的仍居中，百分比不变，多出来的 px 按放下的位置算。
  - ⌥ 加拖动、复制粘贴的副本同样；⌘D 的副本原地复制，本来就带着原图层的样式。
  - 改动单的位置记下这个方向怎样定位、那一边的值（`Place.absolute.placed`）。
- **改动说明**：
  - 居中图层移动的设计意图：从 `50%` 改到 `calc(50% + 20px)`，即容器宽度的 50% 再多 20px，附 Tailwind 写法 `left-[calc(50%+20px)]`；说明写 px 值不对，容器变宽变窄时要仍多出这么多。Placement 一行写明保持居中，只改多出来的部分。
  - 按右边、下边定位的移动用 75 的 Right / Bottom 设计意图（保持按这条边定位，不要改成按 `left`）。
  - 拖进别的 Frame、复制时，位置一句按这个方向的定位方式写，例如「离容器右边 70px（CSS `right`，照图层现在的定位方式按这条边摆，不要用 `left`）」。没有这种情况时，说明和原来一字不差。
  - 「How to write them」的「Centered」一条加上移动的写法；「Placed from the right or bottom」也在拖进别的 Frame、复制时打印。
  - 「How the page checks」多一句：居中图层按那一边在每个宽度的值核对；只在窗口宽度对的 px 值，在其他宽度不对。
- **核对（`done`）**：
  - 居中图层移动后，在每个宽度按「百分比 × 页面上容器在那个宽度的大小 + 多出来的 px」核对那一边（加外边距）。Agent 写成 px 时，窗口宽度上对，在平板、手机宽度报「没有显示」，`done` 说画布在那个宽度把它居中在哪里，让它写成百分比。
  - 按右边、下边定位的移动是 Right / Bottom 改动，照 75 的做法核对（含 `placedOtherwiseAt`）。
  - 拖进别的 Frame 又拖回原来的 Frame 的移动（页面能核对的结构性移动），位置记了 `placed` 的方向按那一边核对。
- **属性面板的断点标记**：在平板、手机视图里移动按右边、下边定位的图层，Right / Bottom 改动在 Position 行出标记；尺寸行的标记只在尺寸改过时出现，重置时照 75 连带 Right / Bottom。
- spec 的「控制点」一节末尾改了一句，新加「移动时保留定位方式」一节，「改动说明」「核对」「Out of Scope」各补了一句；GLOSSARY「定位方式」和 ADR 0014 的 Consequences 各补了一句。

*代定的事（待设计师确认）*

我按「最贴近设计师决定」代定的：

1. 居中图层移动后，那一边写成「百分比 + px」：`calc(50% + 20px)`；多出来的是 0 时写 `50%`，百分比是 0（例如 `left-[200px] -translate-x-1/2`）时写 px。百分比读不出来时（那一边用了 `var()` 之类），照原来写 px，图层仍按 `left` 居中，但不再随容器宽度跟着走。
2. 居中图层的改动在改动单里仍是 X（或 Right）改动，值是正在工作的视图里属性面板显示的 X，另记百分比和多出来的 px 供说明和核对用。改动列表里看到的是「X 640 → 660」这样的数。
3. 按右边定位的图层移动后，改动列表里是一条 Right 改动（往右移时数变小），不再有 X；按下边定位的是 Bottom。
4. 拖动时保留图层自己的 `translate`，这对所有带 translate 的自由图层都成立，不只居中的：例如 `translate-x-4` 的图层拖动中不再跳 16px，落点也不再偏 16px。
5. 属性面板 Position 行的断点标记连带 Right / Bottom（移动会改它们）；尺寸行只在宽高改过时出标记，点它重置宽高和 Right / Bottom，所以在断点上先改尺寸再移动，点尺寸行的标记会连移动一起重置。
6. 拖进别的 Frame 时，按右边定位的 `right` 按新 Frame 的内框宽度算，居中的百分比照旧、多出来的 px 按新 Frame 算；拖进 Stack、Grid 的排列里时照旧去掉自由定位。
7. 拖进别的 Frame 再拖回原来的 Frame（改动单里是一条结构性移动），位置记了 `placed` 的方向按那一边的值核对，不比外边距（原来按 `left` / `top` 核对时比外边距）。

*结论*

定位线（80、79）的整线代码审查在 79 上找到六个行为上的毛病，和一批写法上的问题，都已改好。最要紧的是一个虚假的 ✓（docs/goals.md「虚假的 ✓ 0」）：居中图层移动后，Agent 把它的 translate 去掉了，`done` 仍在每个宽度报「显示了」，页面上图层却偏了半个宽度。拖动、微移、改 X / Y 时设计师看到的行为没有变；变的是 `done` 和改动说明的几句话，和断点标记重置的范围（代定第 1 条）。

*审查找到的毛病*

1. **居中图层的核对不看 translate 还在不在（虚假的 ✓）**。居中的图层移动后，页面只按那一边（`left` / `right`）算出来的值核对。场景：Agent 写了 `left-[calc(50%+20px)]`，却去掉了 `-translate-x-1/2`，或者 v3 里别的 `transform`、`rotate` 类盖掉了 translate。每个宽度都报「显示了」，页面上图层比画布往右偏半个宽度。拖进别的 Frame 又拖回原来的 Frame（同一个容器里的移动）也一样。
2. **留到下一轮、重读改前时，说明前后两处不一致**。下一轮 `claim` 按代码现状重读改前，只改了 X 的改前，没改「那一边原来写成什么」。场景：Agent 写了 `left-[600px]` 没过，下一轮的说明同时写「from `50%` to `calc(50% + 20px)`」和「X goes from 600 to 660」。
3. **`done` 的说法顺序**：拖进别的 Frame 又拖回、位置记了 `placed` 的移动，只要页面没显示，`done` 一律先说「not where the notes place it」，排在「图层还不是自由定位」（ticket 80 的说法）前面。场景：按右边定位的图层拖出原 Frame 再拖回，Agent 没写 `absolute`，`done` 不说「not placed absolute」。
4. **副本和位置按桌面视图读定位方式**。放下的位置按正在工作的视图读定位方式（75 定下、设计师已确认），但移动的起点、⌘D 的副本、删除的位置按桌面视图读，容器空间也用另一种算法。场景：在手机视图里 ⌘D 一个只在手机上按右边定位的图层，改动单记成按左边定位。
5. **断点标记可能留下一半**。79 让 Position 行的断点标记也管 `right` / `bottom`。场景：在平板视图里改按右边定位图层的宽度（宽和 `right` 一起变），尺寸行和 Position 行都出标记；点 Position 行的标记只重置 `right`，宽度留着改过的值，图层的左边往左挪了 20px。e2e 先在没改的代码上复现过（见「测试」）。
6. **改动说明的文案退回了 ticket 76 修过的歧义**。拖进别的 Frame、复制时，某一方向没有 `placed`，说「Y 10px from its top」，"its" 读起来像图层；从右边定位那一支写死了「the container's」，拖进 Frame 时同一句前后是「Frame」和「container」两个说法。

*改了什么*

- **核对看 translate**（毛病 1）：居中图层的移动，页面先看图层在那个方向是不是仍居中（自身一半的 translate 还在，没被别的 `transform`、`rotate`、`scale` 换掉），再看那一边的值。不是居中，就算「没显示」，`done` 说：「The layer is not centered on where its `left` places it: the page does not move it back half its width by `translate: -50%` (Tailwind's `-translate-x-1/2`), or something else, such as another `transform` or `rotate`, takes its place. Keep its `translate`, as the notes say, and run `npx 03kind done 1` again.」从右边居中的说 `right`、forward、`translate: 50%`；不在窗口宽度时开头是「At 768px wide, the layer …」。拖进别的 Frame 又拖回的移动同样。「How the page checks」里居中那条补了「and its translate still centering it there」。连带：页面算容器宽度（`roomOf`）原来用图层画出来的边框，图层被旋转时会算错，改为用排版的宽度，不受 `transform`、`rotate` 影响。
- **重读改前时两处一起变**（毛病 2）：页面没显示居中图层时，另外答出那一边现在写成什么（能读成「百分比 + px」就照读，读不出来时用 px）。下一轮重读改前时，X 的改前和「那一边从什么改」一起换成代码现状。上面的场景现在说「from `600px` to `calc(50% + 20px)`」和「X goes from 600px to 660px」。
- **`done` 先说不是自由定位**（毛病 3）：移动的改动，页面答「不是自由定位」时，先说 ticket 80 那句，按说明给的那一边写：「The layer is not placed absolute, not absolute at 40px from its container's right edge and Y 8px: check its `position`, `right` and `top`, …」；居中的那一方向写「centered on `left: calc(50% + 20px)`」。没有 `placed` 的移动说法逐字不变。
- **按工作的视图读**（毛病 4）：移动的起点、⌘D 的副本、删除时记下的位置，定位方式和那一边的值都按正在工作的视图读，和放下的位置一样；容器空间两处统一为一个算法（`roomIn`：容器边框以内的大小，精确到小数）。X、Y 本身照旧按桌面视图读（代定第 2 条）。
- **一起变的一起回去**（毛病 5）：在断点上宽和 `right`（高和 `bottom`）两样都改过时，点尺寸行、Position 行的标记，或断点列表里任一样的重置，两样一起回去；只改过一样时只回那一样。标记的提示文字列出两样，例如「Right and Width」。规则写在一处（`BreakpointMark.tsx` 的 `RESET_TOGETHER`），尺寸行、Position 行、断点列表都按它。
- **改动说明照 76 的说法**（毛病 6）：每个方向都写出容器，用传进来的名字：拖进 Frame 时「at 70px from the Frame's right edge (CSS `right`, …) and Y 10px from the Frame's top edge (CSS `top`)」，复制时「… and Y 0px from the container's top edge (CSS `top`)」；居中那一支写「50% of the Frame's width from its left edge」。没有 `placed` 的位置说法逐字不变。
- **写法**（照 75 整线审查立的规矩，输出逐字不变）：
  - 裸布尔改成有名字的参数：写法规则里的 `placedOtherwise(change, { centered: true })`。
  - 用已有的类型：`Edge`、`Axis`。
  - 一名多义各起准确的名字：`along` 在核对里改 `placedBy`，在 `absoluteAt` 里改 `how`（和改动说明里同一样东西的名字一致），在改动说明里改 `whereOnAxis`，断点标记的 `along` 参数随毛病 5 的改法去掉了；`otherwise` 在 `done` 里改 `placedOtherwise`，在核对里改 `sideOff`；编辑命令里的 `centered`（装的是那一边、百分比、容器空间）改 `centeringSide` / `centering`，`offCenterAt` 去掉，直接写进改动。
  - 轴和边的对应放进 `checkable.ts` 的共用表：`AXIS_SIZE`（width / height）、`AXIS_WAY`（across / down）、`CENTERING_SIGN`（translate 的正负号）、`OTHER_EDGE`，各处改用。
  - 改动单的 `centeredOn` 改为 `{ before: Share; after: Share }`（这条线没合进 main，不兼容旧写法），不再各处临时拼 `{ percent, px }`。

*代定的事（待设计师确认）*

我按「最贴近设计师决定」代定的：

1. **一起重置的规则**（毛病 5，照 75 代定第 8 条和 79 代定第 5 条「一起变的一起回去」）：在断点上，宽和 `right`、高和 `bottom` 两样都改过时，从尺寸行、Position 行的标记，或断点列表里任一样重置，两样一起回去；只改过一样时只回那一样。所以先改尺寸再移动（`right` 改了两次），点任一处都回到改尺寸之前；只移动过（只改了 `right`）时，Position 行只回 `right`。
2. **位置的 X、Y 照旧按桌面视图读**，只有定位方式和那一边的值按工作的视图读（毛病 4）。X、Y 是放回、解散 Frame 时写在所有宽度上的值，原来就按桌面视图；改成按工作的视图会让在手机视图里删掉再放回的图层在桌面视图里挪位。代价：一个各断点定位方式不同的图层，在手机视图里删除、再放回，放回后在所有宽度按手机视图的定位方式摆（遗留风险第 2 条）。

6. **「How the page checks」补一句**说也看 translate：居中改动的一轮，`claim` 的这一句多了「and its translate still centering it there」。
7. **移动时的 `done`，不是自由定位时**，按说明给的那一边说该查什么（`right` / `bottom` / 居中的那一边），和 80 对 X、Y、右边、下边的说法一致。
8. **（补 79 代定）放回、删除后撤销、解散 Frame 也保留定位方式**：79 让删除、放回、解散 Frame 记下的位置也带上 `placed`，所以一个按右边定位或居中的图层被删除后放回（从画布外拖回原处或别处）、删除后撤销、所在的 Frame 被解散后，仍按原来的定位方式摆，和拖动、复制一样（约束跟着图层走）。79 的实现记录里没写，补在这里。
