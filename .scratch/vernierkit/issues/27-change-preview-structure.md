# 27: 结构类改动的预览

**What to build:** 改动预览覆盖能在真实页面上显示的结构类改动：Stack 内换顺序、同一父容器内改为自由定位、删除。改动预览无法显示的结构类改动——跨容器移动、合成或解散 Stack、新建文字或 Frame、复制——标为"落地后可见"，计入"N 处改动落地后才能看到"的提示。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。改动预览不移动、不新建页面中由 React 管理的元素（ADR 0001）。

**Blocked by:** 25, 15, 17, 19

**Status:** done

- [x] Stack 内换顺序后，真实页面上的顺序与画布一致，其他图层照常让位
- [x] 同一父容器内改为自由定位的图层，在真实页面上停在画布上的位置
- [x] 删除的图层在真实页面上不再显示
- [x] 无法预览的结构类改动计入"落地后才能看到"的提示
- [x] 改动预览不改动真实页面的元素结构，页面重新渲染时不报错

## Comments

**实现记录（2026-10-27）**

- 能预览的结构类改动（`change-preview.ts` 的 `canPreview`）：Stack 内换顺序（同一容器、前后都不是自由定位）、同一容器内改为自由定位、删除。以下仍计入 "N changes show once applied"：跨容器移动、合成或解散 Stack、新建文字或 Frame、复制、改文字；循环渲染的实例单独换序或删除（数据改动，页面上分不出是哪一个）；混排裸文字的改动；本轮新建图层上的改动；容器中混有裸文字的换序（裸文字是匿名的 flex 项，`order` 排不了它）。
- 不改页面元素结构（ADR 0001），全部用注入的样式表加属性标记：
  - 换顺序：改动单的换序改动多了 `order`：容器中各图层按画布上现在的顺序排列的使用处 key（无源码标记的为 null），以及容器是否为普通从上到下排列（`flow`）。每次结构改动后（编辑中的画布、保存的本轮上撤回），同一容器的所有换序改动都更新为画布上的最新顺序（`moves.ts` 的 `syncOrders`），所以先后换了几个图层也只有一个顺序。预览时在真实容器的每个子元素上标 `data-vk-preview-order`，按 key 找到它在新顺序中的位置；顺序里没有的元素（页面另有的）跟在它前一个元素后面。普通排列的容器标 `data-vk-preview-flow`，显示为 flex 竖排，`order` 才生效。React 渲染出新元素或换了元素时（MutationObserver）重新标记。
  - 同一容器内改为自由定位：图层的参考样式（`position: absolute`、`left` / `top`、宽高）照常注入；容器在页面上未定位时（移动改动记 `reference`），容器标 `data-vk-preview-reference`，设为 `position: relative`。
  - 删除：参考样式 `display: none` 照常注入。
- 核对（`check.ts`）：换序比较页面上容器子元素的 key 顺序与改动记下的顺序（只比两边都有的）；自由定位检查页面上的元素是否绝对定位、`left` / `top` 是否为记下的 X / Y（±0.5px）；删除检查页面上是否还有这个元素（按源码标记找到、且同一标签可见；标记移动后找到的元素还要开始标签相同，免得把别的元素当成它）。其余结构类改动、新图层上的改动、混排裸文字的改动返回 "unchecked" 并说明原因。`done` 对这三种"没有显示"给出各自的说法（"Its container's layers are in another order on the page: put it 2nd…"、"The layer is at X…, not absolute at X…"、"The layer is still on the page…"）。
- 目标（`Target`）多了 `run`：混排裸文字是容器中的第几段文字。19 让包了 `<span>` 的裸文字带上容器的源码标记后，它的 `loc` 是容器的，`run` 用来让预览与核对不把改动用到整个容器上。
- Skill：读 `done` 输出的部分写明哪些结构类改动会核对、如何核对，其余为 "Not checked"。
- 测试：辅接缝 1 `edits.browser.test.ts` 新增一组"画布上编辑、在另一份同样的页面上预览与核对"（Stack 内换序与其他图层让位、普通排列中的换序、多次换序共用一个顺序、Frame 内自由定位与定位参照、删除后其他图层让位、跨容器移动 / 新建 / 合成不改页面、改动增减时重新显示与关闭后复原、页面重新渲染出新元素时立即排序、核对三种改动）；命令行接缝新增三种"没有显示"的说法；主接缝新增 `structure-preview.spec.ts`（Stack 内换序在真实页面上显示、页面元素结构不变、打开对话框让 React 重新渲染后无报错且顺序保持、切到 Now 复原；卡片中普通排列的换序在循环的三个实例中显示而另一处使用不变；删除后页面上隐藏、跨容器移动计入"落地后可见"），`drag.spec.ts` 中原来"移动落地后可见"的用例改为换序在页面上显示，`claim.spec.ts` 中 `done` 核对换序（未落地时 "does not show"）。

**已知限制**

- 同一容器内改为自由定位的预览无法在示例项目上端到端测试（示例中没有 React 渲染的 Frame），只在辅接缝 1 覆盖。
- 普通排列的容器预览换序时显示为 flex 竖排：子元素之间的外边距不再折叠，间距可能与画布略有不同；不是块级的子元素也会按 flex 项排布。
- 删除的核对在源码标记移动后，靠开始标签认元素：若 Agent 先落地了这个图层的类名改动、又没有删除它，可能误判为已删除。

**代码审查后的修正（2026-10-27）**

- 换序的核对不再按源码位置比较：Agent 移动 JSX 时源码标记跟着变，原来会把正确的落地判成"没有显示"，或在上方多一行时把没落地的判成"显示了"（违反 ADR 0006 的零虚假 ✓）。现在 `order` 另记各图层的外观（`signs`：标签加前 80 个字，画布上用改字前的原文），核对按外观比较页面上的顺序；被换序的图层在页面上找不到时为"没能核对"。预览仍按源码标记排序（落地前标记不变）。
- 同一容器里先后换了几个图层时，每条换序的核对只看自己：`order.self` 是它移动的图层，`order.others` 是其他换序移动的图层，核对时不计后者。只落地其中一条，`done` 也能判成显示。
- 同一容器内的自由定位：核对还要求页面上的定位参照就是它的容器（`offsetParent`），忘了给容器设 `position: relative` 时判为没有显示（"The layer is placed absolute, but not from its container…"）。
- 删除的核对：容器也不在页面上时（例如在关着的弹窗里）为"没能核对"，不再直接判成已删除；文字图层按外观（标签与文字，`Target.context.text`）认元素，同类兄弟元素移到原来的源码位置时不会被当成没删掉。
- 混排裸文字导致无法核对换序时，原因写明 "text runs on among the layers of its container"。
- "普通从上到下排列"按块级排列判断（与图层模型一致），不再是"不是 flex 或 grid 就算"。
- 整理：`edits.ts` 中重复的绝对定位样式合为 `absoluteAt`，循环实例的判断共用 `isLoop`，几个辅助函数改名（`stackOn` / `stackOff`、`madeLayer` 返回 `make` / `takeOff`），`change-preview.ts` 的 `keyOf` 改名 `usageKeyOf`，补了注释。
- 测试：辅接缝 1 新增标记随 JSX 移动时的换序核对、两条换序分别核对、缺少定位参照、删除时容器不在与兄弟元素占位；命令行接缝新增"缺少定位参照"的说法。

**已知限制（补充）**

- 同一容器里有标签与前 80 个字都相同的兄弟元素时，换序的核对分不清它们。
