# 42: 结构编辑的验收修正

**What to build:** 设计师验收 17、19 时发现的问题：

1. Stack 改了方向后，拖拽的落点与让位仍按原来的方向计算。拖拽应按 Stack 此刻实际的排列方向。
2. 合成 Stack 时保留了子图层的外边距：间距显示为 0，子图层之间却有空隙，Hug 也把外边距包了进去。合成时把子图层之间的外边距并入推断出的间距，子图层的外边距清零；最外侧的外边距移到新 Stack 自己身上，画面不跳。属性面板上看到的间距就是实际的间距。
3. 新建的 Frame 显示为普通的空 Frame（无填充、无虚线、框内不显示说明文字），之后还可以在里面编辑；生成说明只在属性面板中编辑，图层树中有生成说明的 Frame 带一个标记。
4. 文字编辑状态按 Framer 的样子：进入编辑时文字框的边框变为蓝色、选区为蓝色。
5. 工具栏：右上角贴着属性面板，放"选择（V）""Frame（F）""文字（T）"三个工具，显示当前工具，点击切换，与快捷键一致。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

## Comments

**实现记录（2026-10-28）**

1. 方向：改样式后，Stack 此刻的排列方向（`stackOf`）与图层模型记的不同时，重建图层模型（`edits.ts` 的 `apply` 末尾），撤销也走这里。拖拽、图层树的"Horizontal / Vertical Stack"都读图层模型，因此跟着变。
2. 外边距：合成时按边框盒（`borderBox`）推断方向、间距、对齐与内边距，外边距不计入；有外边距的子图层在 `Composed.layers` 中记 `unmargined`，合成时写 `margin: 0px`（`memberStyle`，撤销与解开合成时按它恢复）。新 Stack 在布局中时，子图层最外侧的外边距写到 Stack 自己身上（`outerMargin`：沿排列方向取第一个之前、最后一个之后，交叉方向取共同的部分），画面不动；自由定位的新 Stack 不写外边距。Frame 变成 Stack 时，外边距那部分空间计入内边距。改动说明新增 "Drop the margins" 一行，Skill 补充对应规则。示例页面中段落与按钮合成后间距为 24px（原来是 0，按钮的 `mt-6` 藏在外边距里）。
3. 新 Frame：画布上只有一条很淡的细边（`outline: 1px solid rgb(128 128 128 / 0.3)`），没有灰底、虚线，也不显示说明文字；图层树中带生成说明的一行右侧有标记，悬停显示说明。
4. 文字编辑：编辑时画一个 2px 的蓝色框（`.vk-selection[data-kind="typing"]`），随文字变长而变宽；画布上编辑中的元素没有浏览器的焦点框，选区与光标为蓝色。
5. 工具栏：`Shell.tsx` 的 `Tools`，在画布右上角、Design 面板旁，选择（V）、Frame（F）、文字（T）。工具状态从 `CanvasView` 提到 `Shell`，键盘与工具栏共用；新增 V 回到选择工具。播放时隐藏。

**已知限制**

- 合成时子图层宽度不一（例如一个拉伸、一个靠左），新 Stack 不拉伸子图层，拉伸的那个会按内容收窄（17 已记）。
- 外边距是 `auto`（居中）的子图层，合成后外边距清零，居中改由对齐表达；各图层原来的交叉方向偏移不同时，会按推断的对齐对齐。

**代码审查后的修正（2026-10-28）**

- 子图层清零外边距改为逐边写（`margin-top` 等），撤开合成时各边原来的样式能分别恢复（原来写简写 `margin`，子图层原本只在 style 属性里写了 `margin-top` 时会丢）。
- 合成改动记下子图层外边距由谁设定（`sources`），改动说明多一行 "Currently set by (the margins)"；"Drop the margins" 写出是哪些图层。
- 文字编辑的蓝框在播放、画布往返动画时不画；`Tool` 类型、`spotIn`、命名等整理。
