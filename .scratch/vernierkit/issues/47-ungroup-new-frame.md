# 47: 解除分组新建 Frame 时，里面新建的图层留下

**What to build:** 设计师验收时，在新建的 Frame 里放了文字，把 Frame 合成 Stack，再按 ⌘⇧G 解除分组：Frame 和文字一起从画布上消失，改动列表也清空了，图层树却还显示着它们。同类问题：把新建 Frame 里的文字拖出来，再删掉 Frame，文字也会跟着消失。另外，合成时推断出顺排方向的对齐（例如底部），只记在改动里，没有写进 CSS，画布上仍然排在顶部。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 解除分组新建的 Frame（含合成过的 Stack）：里面的图层占它原来的位置，Frame 去掉，可撤销、重做
- [x] 新建 Frame 里新建的图层，拖出 Frame 后再删除 Frame，这些图层留下
- [x] 留下的图层在改动里记为"在新位置新建"，不再有移动，也不依赖已删除的 Frame
- [x] 合成时推断出的顺排对齐写进 CSS，画布与改动一致

## Comments

**实现记录（2026-10-28）**

- 原因：新建图层的改动记着"新建在这个 Frame 里"。删除本轮新建的 Frame 就是撤回它的新建，撤回会带走所有依赖它的改动，里面新建的图层因此一起被撤掉，即使它们已经被移了出去。
- `edits.ts` 新增 `rehome`：删除本轮新建的图层之前，找出在它里面新建、后来又移出去的图层，把移动并入各自的新建记录，改为在现在的位置新建（位置、目标、样式都随之更新，自由定位的样式只在新位置是自由定位时保留），画布不动。撤销时把新建与移动的记录原样放回。
- `changeset.ts` 新增 `restore(change)`：按原编号放回一条改动，保持排序。回放已保存的画布是按编号进行的，所以编号不能变。
- `stacks.ts` 的 `stackStyle`：顺排方向不是起点时写 `justify-content`。
- 单元测试：解除分组合成过 Stack 的新 Frame（含撤销、重做）、拖出文字后删除新 Frame，以及推断为底部对齐时画面不动。

**已知限制**

- 只处理新建（`create`）的图层；在新 Frame 里复制出来的图层（`duplicate`）拖出后再删除 Frame，仍会一起消失。
- 验收那一轮里已有的 Stack 记的是底部对齐，但保存的样式里没有 `justify-content`，所以画布上仍在顶部。在属性面板里重新点一次对齐就会写进去。
