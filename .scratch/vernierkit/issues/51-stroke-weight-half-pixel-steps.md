# 51: 描边粗细按 0.5px 取整，核对按页面画出来的值比较

**What to build:** 设计师在属性面板输入的描边粗细统一按 0.5px 取整（也就是 2x 屏上浏览器能原样画出的粗细），与所在屏幕无关；面板显示的粗细始终与样式里写的一致；只改描边颜色或线型时不改源码里的粗细；Agent 运行 `done` 时，核对把改后值也放到真实页面上让浏览器画一遍再比较，不再因为浏览器对边框粗细的取整而误报。

参考本功能的 spec.md（同目录上一级，"核对"一节），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策，尤其是 ADR 0006。

**Blocked by:** 11（已完成）

**Status:** done

- [x] 输入的粗细按 0.5px 向下取整，不足 0.5 的取 0.5（1.25 → 1，1.75 → 1.5，0.3 → 0.5），与屏幕无关；分边设置时每条边各自取整
- [x] 被取整时弹一句简短提醒（例如"描边按 0.5px 取整，1.25px 已改为 1px"）；输入本来就是 0.5 的倍数时不提醒
- [x] 面板显示的粗细与样式里写的一致，1x 屏上也是：本轮改过的显示改后值；页面原有的按设定它的样式里写的值读，读不到时（例如经由 `var()`）才退回浏览器读回的值
- [x] 只改描边颜色或线型时，这条改动的参考样式不含粗细，Agent 落地后源码里的粗细不变
- [x] 核对时改后值也在真实页面上由浏览器画一遍，再与页面比较：1x 屏上源码写 1.5px、页面画成 1px，`done` 说明页面显示了这条改动；真写错（例如写成 3px）仍说明页面没有显示；已有属性的核对结果不变

## 背景

- 浏览器把边框粗细对齐到整数个物理像素：不足 1 个物理像素的取 1 个，其余向下取整，读回的计算值也是取整后的值。2x 屏上 1.25px 画成 1px、1.5px 保留；1x 屏上 1.5px 画成 1px。SVG 的线（如编辑层的图标）不受此影响，按真实宽度抗锯齿绘制。（已在本机 2x 屏的 Chromium 152 与 1x 屏的 Chrome 156 上实测。）
- 现在 `done` 用改后值与页面读回的值逐字比较，所以正确落地的小数粗细会被报成没有显示；面板只改颜色时也会把读回的（已取整的）粗细一并写进参考样式，Agent 可能据此把源码里的 1.5px 改成 1px。
- 实现时注意：Playwright 用 deviceScaleFactor 模拟的 2x 屏不会按物理像素取整（模拟下 1.5px 仍读回 1px），不能用来验证 2x 屏上的行为；e2e 按 1x 屏的规则写。

## Comments

**实现记录（2026-10-28）**

- 新模块 `client/stroke-weight.ts`：描边粗细"写的值"与"画出来的值"。`edits.ts` 只改了描边一项的读（`readWrittenStroke`），给 `Definition` 加了可选的 `reference`（参考样式取 `write` 的一部分时用），`apply` 里多查一次这条改动起始的 `before`（仅对有 `reference` 的属性）。`CanvasView.tsx` 没有改。
- 画出来的值：`drawnWidths` 在同一文档里放一个隐藏元素（`!important` 的内联样式，页面规则够不着），读回四边的计算宽度后立即移除，不经过绘制。它就是浏览器在这块屏幕上画这些粗细的结果。
- 读（面板显示、改动的 before / after）：每条画出来的边，先看画布上编辑写的内联 `!important` 声明，否则用 `sourcesOf`（"Currently set by" 的样式来源查找）找到设定 `border-<side>-width` 的那条声明，取其中的 px 值；读不到（`var()`、非 px 单位）或这个值画出来和这条边实际画出来的不一样（来源找错了）时，退回计算样式。所以 1x 屏上源码写 1.5px、本轮改成 1.5px，面板都显示 1.5。
- 取整（面板）：Stroke 的粗细框与 Custom 的四个分边框，输入经 `stepped` 按 0.5px 向下取整，不足 0.5 取 0.5，0 仍是 0（没有描边）。被取整时在 Stroke 段末尾显示一句 "Stroke weights go in 0.5px steps: 1.25px is now 1px."：沿用面板已有的 `vk-layer-note` 说明样式，加 `role="status"`。改颜色、线型、边、加或去描边时消失，下一次输入不需取整时消失，撤销等让粗细不再是取整后的值时也消失，换选中时消失（Stroke 段随选中重建）。
- 参考样式：这条改动从起始到现在粗细不变（只改颜色或线型）时，参考样式去掉 `border-width`；描边只在部分边上时，`border-style` 换成那几条边各自的 `border-<side>-style`，否则 Agent 照抄会让其余边按默认 3px 画出来。画布上仍声明完整的三项。
- 核对（`check.ts`）：新增按属性的 `AS_DRAWN` 表，目前只有描边：页面按计算样式读（画出来的），改后值在开始观察页面之前先在真实页面上画一遍（`drawnStroke`），两者比较。没有显示时，`actual` 报写的值（同上的读法），所以提示里是源码里写的 3px 而不是画出来的值；为不在 MutationObserver 回调里改动页面，只在最后超时那次读 `actual`。其他属性的核对不变。
- 测试：辅接缝 `edits.browser.test.ts`：页面原有粗细按写的值读、经 var() 退回画出来的值、本轮改的值读回原样、只改颜色 / 线型时参考样式不含粗细（含改了粗细又改回、经 var()、只在部分边上），以及核对：1x 屏上 1.5px 显示、3px 不显示并报 3px、分边、颜色不对、经 var() 写对、写成 1.25px（画出来相同）。主接缝 `properties.spec.ts`：1.25 → 1、0.3 → 0.5、Custom 的 1.75 → 1.5 及提醒，1.5 不提醒且在 1x 屏上显示 1.5、换选中后仍是 1.5，撤销后提醒消失。`round.spec.ts`：源码写 `border-[3px]` 时 `done` 报没有显示，改成 `border-[1.5px]`（画成 1px）后报显示；只改颜色时 changeset 里的参考样式不含粗细，源码只改颜色后 `done` 报显示。

**已知限制**

- 按画出来的值比较是这张 ticket 定下的规则，它的另一面：画出来相同的粗细核对不出区别。1x 屏上把 1px 改成 1.5px，Agent 什么都不改，`done` 也报显示（页面原来的 1px 与 1.5px 都画成 1px）；写成 1.25px 也算显示。2x 屏上 1.5px 与 1px 能分开。（已由 54 解决：核对先比较写的值；只有经 `var()` 写的粗细仍按画出来的值比较。）
- Playwright 用 deviceScaleFactor 模拟的 2x 屏不按物理像素取整，测试只覆盖 1x 屏的行为。
- 读写的值依赖 `sourcesOf`：浏览器对 `border: var(--w) solid` 这样经 var() 的简写，各条长写属性读出来是空的，这条规则不参与比较。另一条优先级更低、写了 px 的规则就可能被当成来源；两者在这块屏幕上画出来相同时（例如 1x 屏上的 1px 与 1.5px）校验也拦不住，面板会显示那条规则的值。"Currently set by" 原本就有同样的限制。（已由 54 解决：经 `var()` 的边框简写现在算作来源。）
- 读一个有描边的图层，每条画出来的边都要查一次样式来源（四边最多四次遍历样式表），还要放一次隐藏元素。面板每次重绘都会读。
- 只有输入会取整。页面原有的、不在 0.5px 步长上的粗细（如源码写 1.25px）照原样显示和保留；切换边时沿用这个值。
