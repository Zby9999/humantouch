# 26: 落地时撤下改动预览

**What to build:** Agent 落地期间，每 `done` 一条改动，就撤下这条改动的预览，页面显示的是 Agent 写进源码后的真实结果；`finish` 或手动解锁后，页面上不再有任何改动预览。这样改动预览不会掩盖 Agent 没能 1:1 落地的改动。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

**Blocked by:** 25, 07

**Status:** done

- [x] `done <编号>` 之后，这条改动的预览立即撤下，其他未完成的改动仍在预览中
- [x] `finish` 后页面上不再有改动预览，页面就是代码的真实样子
- [x] 手动解锁后，已完成的改动不再预览；未完成的改动随本轮一起归档，也不再预览
- [x] 主接缝：端到端测试走通 claim → done → finish，断言每一步真实页面上的预览与真实结果

## Comments

**实现记录（2026-10-23）**

- `EditorLayer.tsx`：已认领时，改动预览只显示还没 `done` 的改动（`pending`）。每次状态推送（07 的 `/events`）都会重新计算，`done` 一条，页面上就撤下这条，露出 Agent 写进源码后的样子（开发服务器热更新）。角标、"Changed / Now" 开关和"落地后才能看到"的提示也按 `pending` 计算。
- `finish` 或手动解锁后，本轮已归档，编辑层重新读本轮读到的是没有：改动预览清空，预览样式表和元素上的标记全部撤掉。未完成的改动随本轮一起归档，不再预览。
- 测试：`e2e/tests/round.spec.ts` 中两条。测试里没有真的改源码，所以 `done` 之后的"真实结果"就是改前的样子，正好用来断言预览已撤下。

**已知限制**

- 落地期间刷新页面，本轮先读回来、状态后到，已完成的改动会闪一下预览（毫秒级）。
