# 04: 第一处改动：纯色填充 + 统一圆角

**What to build:** 设计师选中图层后，在属性面板里修改纯色填充和统一圆角，画布 0 延迟生效，同一使用处的实例同步变化；改动被记入（内存中的）改动单，同一图层同一属性反复修改只保留最初值和最终值。这是编辑命令与改动单的第一条完整路径。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

**Blocked by:** 03

**Status:** ready-for-agent

- [x] 修改纯色填充或圆角后画布立即变化，没有可感知的延迟
- [x] 同一使用处的所有实例同步变化
- [x] 改动单记录目标（元素位置、使用链、组件名、实例数量）、作用范围（这一处使用）、改前与改后的值
- [x] 同一图层同一属性多次修改只产生一条改动，保留最初值与最终值
- [x] 锁定图层不提供填充与圆角编辑（只允许整体移动和调整外部尺寸）
- [x] 辅接缝 1：在固定画布副本上直接调用编辑命令，断言画布结果与改动记录

## Comments

**实现记录（2026-10-23）**

- 模块：
  - `client/edits.ts`：编辑命令，`createEditor(tree, changes)`，返回 `can / read / set` 三个方法。每个属性在 `PROPERTIES` 表里登记四项：适用的图层类型、读取方式（转成设计语言）、写到画布上的 CSS、以及可选的 `applies` 条件。之后新增属性，在这张表里加一项即可。
  - `client/changeset.ts`：改动单，`createChangeSet()`，返回 `record / list`。目前只放在内存里，跟随画布一起创建。05 再负责保存和恢复。
  - `client/Properties.tsx`：属性面板中的 Appearance（统一圆角）和 Fill（纯色）两节。
- 画布上的写法：在同一使用处的每个实例元素上，写带 `!important` 的内联样式。它的优先级高于页面样式表里的 `!important`，所以改了一定能看到。命令是同步执行的：输入事件触发后，画布在同一帧内变化。
- 图层的身份：图层第一次被编辑时，给它在各实例中的元素都打上 `data-vk-layer`。改动单按"图层 id + 属性"合并改动。这个 id 存在画布副本里，能撑过之后的保存与恢复，也能撑过结构性移动。没有标记的图层同样适用。
- 改动单的 target 里放这几项：元素位置、使用链、组件名、实例数量、是否锁定、是否未定位。作用范围目前固定为 `usage`，推广留给 20。
- 设计语言下的值：
  - 填充记为 `{ type: "solid", color: "#RRGGBB", opacity }`，没有填充记为 `null`。读取方式是把颜色画到 1×1 的 canvas 上再取像素，所以 Tailwind v4 的 oklch 也能正确换成 sRGB。为了避免预乘 alpha 损失精度，颜色和透明度分两次读。
  - 圆角记为数字。各角不同时记成 `[左上, 右上, 右下, 左下]`，面板上显示 Mixed。
  - 圆角读的是设置的值，不是实际画出来的值，和 Figma 一致。超过短边一半的圆角，画出来和恰好一半一样，都是胶囊形，但面板和改动单里照样记 99 这样的设置值。
    - 超过 9999 的值记成 9999。Tailwind v4 的 `rounded-full` 是无穷大，也记成 9999。
    - 百分比按对应的边换算成 px。椭圆角取较小的半径。

**决定：改回原值的改动从改动单中去掉（2026-10-23）**

依据是用户故事 84 的"Agent 不会做无用功"。有两种情况：

- 某个属性被改回最初的值：删除这条改动；
- 设置的值和当前值相同（比如在 12 上输入 12，或在 0 上按 ↓）：不产生改动。

之后再改，会拿到新的编号，编号可能不连续。21 做改动列表时如果需要连续编号，到时再处理。

**决定：哪些图层提供填充与圆角（2026-10-23）**

- 填充：只提供给 Stack、Grid、Frame。如果图层已经有 `background-image`（渐变或图片），不提供纯色填充，因为纯色会被盖住，改了看不出来。渐变留给 11。
- 圆角：提供给 Stack、Grid、Frame、Image、Still。
- 文字图层两者都不提供。在 Figma 里，文字的 Fill 是文字颜色，这个留给 13 一起做。这也意味着"只含文字、但带背景色"的元素（例如徽标式的 `<span>`）暂时改不了背景。13 需要决定它显示成什么。
- 锁定图层两者都不提供：面板显示说明，`set` 直接拒绝。

**已知限制与待定问题（留给后续 ticket）**

- 圆角：
  - 起初读的是实际画出来的值（不超过短边的一半）。这导致在 44.8px 高的按钮上输入 99，面板仍显示 22.4，↑ 和拖动也卡在 22.4。已改为读设置的值（2026-10-23）。这样一来，`rounded-full` 的改前值记为 9999，Agent 也更容易对上源码。
  - 百分比和椭圆角在设计语言里没有对应的写法，只能取近似值。11、12 写改动说明里的"参考样式"时，应该附上原始的 CSS 值。
- `set` 已经能写分角圆角（类型是 `Radius`）。面板只用统一值，切换到分角留给 12。
- 面板额外加了几个 Figma 式的细节：
  - 添加 / 删除填充；
  - 透明度字段；
  - ↑↓ 步进，加 ⇧ 每次 10；
  - 在数值框的图标上左右拖动改值（Figma 的 scrub），每 px 改 1，加 ⇧ 每次 10。拖动时锁定鼠标指针，拖到屏幕边缘也能继续改。这个做在共用的 `NumberField` 里，之后的数值框都会带上。不透明度框没有图标，所以没有这个功能；
  - 输入框在 Enter 或离开时提交。离开输入框时如果已经选中了别的图层，值仍然写给原来那个图层。
- 调整数值时选中框立即隐藏，最后一次改动后 0.2 秒淡入回来，免得直角的选中框挡住圆角。
- 改动单在退出编辑模式时随画布一起丢弃。05 会让一轮回到同一张画布。
- 辅接缝 1 用 vitest 的 browser 模式（Playwright 驱动系统 Chrome）在真实浏览器里跑，测试文件约定为 `test/*.browser.test.ts`。源码标记转换的测试仍然在 node 环境里跑。
