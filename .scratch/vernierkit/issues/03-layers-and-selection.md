# 03: 图层与选中

**What to build:** 冻结后，编辑层把副本翻译成图层树，并读取原页面的使用链。设计师可以按 Figma 的习惯选中图层，属性面板顶部显示该图层属于哪个组件、源码位置在哪里。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

## Comments

**实现记录（2026-10-22）**

- 模块：
  - `client/usage-chain.ts`：使用链读取，`readUsageChain(el) → UsageLevel[]`。这是唯一读取 React 内部字段的模块，读的是开发模式下的 `__reactFiber$*` 和 `_debugOwner`。
  - `client/layers.ts`：图层模型，`buildLayerTree(canvas.document)`。
  - `client/selection.ts`：选中规则，都是纯函数。
  - `LayerTreeView.tsx`、`LayerInfo.tsx`、`icons.tsx`：界面。
  - `markers.ts`：标记名常量。从 `source-marker.ts` 抽出来，客户端代码因此不会引入 Babel。
- 使用链：沿 owner 链（`_debugOwner`，即"写出这段 JSX 的组件"）往上走，不沿渲染树（`return`）走。这样，作为 children 传进别的组件的元素，仍然属于写出它的组件。每一层记录组件名、使用处位置（取该组件 props 上的 `data-vk-usage`）、是否来自第三方依赖。第三方的判定规则是"这个组件写出的 JSX 没有标记"：第 0 层看元素自己有没有 `data-vk-loc`，第 i 层看第 i−1 层有没有使用处标记。各层的"元素位置"就是下一层的使用处位置，所以没有单独存。冻结时在原页面上读一次，以 JSON 写进副本的 `data-vk-chain` 属性，之后只读副本。
- 翻译规则按规格的表格实现，补充约定如下：
  - 第三方组件 → 锁定图层。锁定图层是叶子，名称和使用处取最外层的那个第三方组件。
  - 只含文字 → 文字图层。子元素只能是 `display: inline` 的片段（加粗、链接等）。
  - Flex → Stack，按 `flex-direction` 分横纵；Grid → Grid。
  - 块级容器里，脱离绝对定位之后的子元素全部是块级、且没有浮动 → 纵向 Stack。
  - 其他 → Frame。
  - 绝对 / 固定定位 → 自由定位。它和类型可以并存，显示为 "Grid · Absolute" 这样的形式。
  - `display: contents` 不算图层，它的子元素直接挂到上一层。
  - 另外加了两种叶子类型：`img` / `svg` → Image（规格的表格里没有这一行）；`data-vk-frozen`、视频、图表画布 → Still（静态画面）。
- 图层名：组件使用处取组件名，文字取内容，其余取类型名（Stack / Grid / Frame）。
- 组件使用处的判定：父元素的使用链正好是本元素使用链去掉最内层之后剩下的部分，也就是本元素是该组件渲染出的最外层元素。选中框颜色：普通图层蓝 `#0d99ff`，组件使用处紫 `#9747ff`，锁定图层灰 `#8c8c8c` 并加锁形图标。
- 实例：元素位置相同、且使用链完全相同的图层。锁定图层没有元素位置，用使用处位置代替。属性面板在实例数大于 1 时显示数量。
- 选中规则按 Figma 的习惯：
  - 单击停在当前选中的深度：选中与当前选中项同一层、位于指针下的图层；没有选中时选最外层。
  - 双击朝指针方向深入一层；锁定图层不能深入。
  - ⌘ / Ctrl + 单击选最深处。
  - Esc 回到父图层；在最外层时清空选中。
  - 命中检测用画布文档的 `elementFromPoint`。画布里统一设了 `pointer-events: auto !important`，页面里 `pointer-events: none` 的装饰层和图标也能选中。
- 属性面板顶部依次显示 Type、Component、Source（无标记时显示 "Not located"）、Usage（仅组件使用处）、Instances（仅大于 1 时）。
- 键盘处理器通过 ref 读取最新的选中状态。原因：Preact 的 effect 在绘制之后才运行，单击后紧接着按 Esc 时，effect 里的闭包还拿着旧的选中状态。

**决定：大页面的图层树初始只展开前几层（2026-10-22）**

一次渲染约 3000 行图层树，会让进入编辑模式从约 35ms 涨到约 100–270ms，耗时主要在渲染行，建树本身只要约 7ms。做法：初始逐层展开，展开到下一层就会超过 200 行时停止，更深的层级折叠；选中时自动展开到选中项，并滚动到可见位置。这和 Figma 的图层面板一致。示例项目这种小页面仍然全部展开。改后在 3000 个元素的页面上实测：无头 33–83ms，读使用链约 5ms，建图层树约 7ms。加入混排文字图层后复测：32–93ms。

**已知限制与待定问题（留给后续 ticket）**

- 已决定（2026-10-22，见下方「决定：混排中的裸文字单独成为文字图层」）：混合内容里的文字没有图层。例如 `<button><svg/> Save</button>`：它不算"只含文字"，而文字节点又不是元素，所以 "Save" 不会出现在图层树里。要支持，需要让文字节点也能成为图层，建议在 13 文字排版或 19 新建 / 删除时一起考虑。
- 已决定（2026-10-22，见下方「决定：转发 props 的第三方组件按普通图层处理」）：第三方组件包着项目内容时怎么处理。最典型的是 `motion.div`：它渲染出的 `div` 没有元素位置标记，所以整个被判成锁定图层，传进去的、带标记的项目子元素既选不中、也不出现在树里。规格写的是"不能进入内部"，但这些 children 属于项目代码。建议在 22 兼容性中决定：要么允许锁定图层露出带标记的后代，要么把"只是包了一层宿主元素"的组件当成普通图层。
- 段落里由第三方组件渲染的行内元素（比如路由库的 `<Link>` 渲染出的 `<a>`）会并进文字图层，不单独显示成锁定图层。这符合用户故事 38（链接算作同一个文字图层），但修改文字样式时可能会动到第三方组件的输出。
- 由别的组件原样渲染出来的元素（例如 `<Slot>` / `asChild` 模式）会让使用处的判定落在最内层的组件上。
- 项目代码里用 `React.createElement` 写、而不是用 JSX 写的元素没有标记，会被判成第三方。
- 02 提到的"钉住产生的内联样式"在 03 中没有用到：图层模型只读 `position`，钉住不会改它。10 读取 X / Y 时需要区分哪些内联样式是冻结时写入的，届时再给钉住的元素加标记。
- 已解决（2026-10-22）：术语。GLOSSARY 的改动：
  - Frame 放宽为"既不是 Stack 也不是 Grid 的容器图层，页面原有的或设计师新建的都算"。
  - 实例只指组件渲染出的最外层图层（紫框）。
  - 补充 Grid、文字图层、静态画面 (Still) 三个词条。
  - 锁定图层改为"第三方依赖自己生成、项目源码控制不到的部分"。

  规格、ticket 20 中的相关措辞已同步修改。代码随之调整：`isUsage` 改为 `isInstance`，`instancesOf` 改为 `acrossInstances`。属性面板上，实例显示 "Instances: N"，实例里的图层显示 "Repeated: In N instances"。

**决定：转发 props 的第三方组件按普通图层处理（2026-10-22，已实现）**

锁定的目的是避免产生 Agent 无法落地的改动，不是说页面显示不出来。判断一个元素该不该锁，要看它的样式由谁控制，而不是谁渲染了它。

- 如果第三方组件渲染出的元素带着 `data-vk-usage`，说明使用处的 props 被原样转发到了这个元素上（`motion.div`、`Link`、`asChild` / `Slot`、Radix / Headless UI 的大多数组件都是这样）。这时它按普通图层处理：
  - 源码位置取使用处；
  - 类型照常按翻译规则判定；
  - 可以进入内部；
  - 改动落在项目代码里的使用处。
- 组件自己生成、没有任何标记的内部元素，仍然是锁定图层。
- 验证：读了 motion 12 的源码（`framer-motion/dist/es/render/dom/utils/filter-props.mjs`），它默认把所有非 motion 的 props（包括 `data-*`）原样转给 DOM。示例项目没有引入 motion，而是在第三方替身库 acme-ui 里加了一个转发 props 的 `Surface` 组件，用它包住卡片网格。Radix 的 `Slot` / `asChild` 会把使用处的 props 合并到项目自己写的子元素上，那个子元素本来就带元素位置标记，不受这条规则影响。
- 实现：`layers.ts` 的 `originOf`。元素没有元素位置、写出它的组件来自第三方、但身上带着 `data-vk-usage` 时，它的源码位置取最外层那个第三方组件的使用处，使用链去掉前面的第三方层级。
- 配套修改：标记转换现在把标记写在开始标签所有属性的最后（原来紧跟在标签名后面）。这样，组件转发进来的 `{...props}` 里如果带着别处的标记，会被这里的标记覆盖，而不是反过来。顺带修了 `<List<string> />` 这类带类型参数、没有其他属性的写法：原来标记会插到类型参数前面，生成的代码无法解析。
- 已知风险：
  - 有的库在根元素上合并自己的样式（如 MUI），会覆盖使用处新加的 className；
  - `motion` 在运行时用内联样式驱动 transform / opacity，会盖掉设计师对这些属性的改动。

  遇到这些情况，由 Agent 报告"无法 1:1 落地"。
- 被否决的方案：
  - 保持整块锁定：`motion.div` 常常包住整个区块，大片页面会改不了。
  - 锁定图层只露出项目传进去的子元素：外层本可以改却被锁住，图层树也不再如实。
  - 维护一份库名白名单：名单需要一直维护，覆盖不到没见过的库。

**决定：混排中的裸文字单独成为文字图层（2026-10-22，已实现）**

`<button><svg/> Save</button>` 这类元素和文字混排的容器里，每段连续的非空文字单独成为一个文字图层，和兄弟元素并列。例如 `flex gap-2` 的按钮显示为横向 Stack，里面是图标和 "Save" 两个图层。这和浏览器的排版一致：在 Flex 容器里，浏览器本来就把这段文字当作一个独立的排版项。

- 这种文字图层没有自己的元素，改动按下面的方式落地：
  - 改文案：改 JSX 里的那段文字。
  - 改文字样式（字号、颜色、字重等）：写在父元素上，画布同样作用在父元素上，所见即所得。属性面板要提示"样式作用于所在的 <父图层名>"。用 `currentColor` 的图标会跟着变色，这正是落地后的真实效果。
  - 移动、改成自由定位、拖进别的容器：由 Agent 给这段文字包一层 `<span>`，改动说明里要写明。
- 实现：`Layer.text` 存这段文字的文本节点，`Layer.el` 指向它所在的元素，也就是样式实际写在的地方。`boxOf(layer)` 按文字实际占的区域（Range，去掉两端空白）给出位置，选中框用它来画。`tree.layerAt(x, y)` 先用 `elementFromPoint` 找到元素对应的图层，再看这个点是否落在其中某段文字上。同一图层在各实例里的对应关系，按"所在元素的来源 + 第几段文字"判定。属性面板会提示 "Text styles apply to the layer it sits in, <父图层名>."
- 后续的编辑命令（04 起）需要处理 `layer.text` 不为空、即"没有自己的元素"的图层。
- 被否决的方案：
  - 保持现状：文字选不中、改不了，图层树也不如实。
  - 把整个元素当作一个文字图层：打破"Flex → Stack"，图标也不能单独编辑。
- 时机：和"转发 props 的第三方组件"一起，作为 03 的补充，在 04 之前完成。


**补充：悬停框（2026-10-23，在 04 期间加入）**

指针在画布上移动时，用 1px 的框描出"此刻单击会选中的图层"：

- 按住 ⌘ / Ctrl 时，描出指针下最深处的图层。不用移动鼠标，按下、松开 ⌘ 时悬停框就会切换。
- 选中框和悬停框颜色规则相同：蓝、紫、灰。悬停框不带锁形图标。
- 以下情况不画悬停框：
  - 悬停的图层就是当前选中的图层；
  - 正在平移画布，或按着空格；
  - 正在调整数值；
  - 指针已经离开画布。
- 实现：悬停框和选中框用同一个 `Outline` 组件绘制，判定同样用 `selectOnClick` / `selectDeepest`，所以悬停框描出的一定是单击后会选中的图层。
