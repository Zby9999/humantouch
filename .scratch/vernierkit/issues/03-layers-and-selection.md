# 03: 图层与选中

**What to build:** 冻结后，编辑层把副本翻译成图层树，并读取原页面的使用链。设计师可以按 Figma 的习惯选中图层，属性面板顶部显示该图层属于哪个组件、源码位置在哪里。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

**Blocked by:** 02

**Status:** ready-for-agent

- [x] 图层按规格的翻译规则分类：Flex → Stack，Grid → Grid，普通从上到下排列 → 纵向 Stack，绝对 / 固定定位 → 自由定位，只含文字（含行内片段）→ 文字图层，第三方组件 → 锁定图层，其他容器 → Frame
- [x] 图层树如实显示页面结构，图层名自动取组件名或文字内容
- [x] 单击选中最外层、双击逐层深入、⌘ 加单击选中最深处、Esc 回到上一层
- [x] 属性面板顶部显示所属组件名与源码位置；无标记的图层显示为未定位
- [x] 元素位置与使用链都相同的图层被识别为同一使用处的实例
- [x] 选中框颜色：普通图层蓝色、组件使用处紫色、锁定图层灰色加锁形图标；锁定图层不能双击进入内部
- [x] 使用链读取逻辑集中在单一模块，是唯一依赖 React 内部字段的地方

## Comments

**实现记录（2026-10-22）**

- 模块：
  - `client/usage-chain.ts`：使用链读取，`readUsageChain(el) → UsageLevel[]`。这是唯一读取 React 内部字段的模块，读的是开发模式下的 `__reactFiber$*` 和 `_debugOwner`。
  - `client/layers.ts`：图层模型，`buildLayerTree(canvas.document)`。
  - `client/selection.ts`：选中规则，都是纯函数。
  - `LayerTreeView.tsx`、`LayerInfo.tsx`、`icons.tsx`：界面。
  - `markers.ts`：标记名常量。从 `source-marker.ts` 抽出来，客户端代码因此不会引入 Babel。
- 使用链：沿 owner 链（`_debugOwner`，即"写出这段 JSX 的组件"）往上走，不沿渲染树（`return`）走。这样，作为 children 传进别的组件的元素，仍然属于写出它的组件。每一层记录组件名、使用处位置（取该组件 props 上的 `data-vk-usage`）、是否来自第三方依赖。第三方的判定规则是"这个组件写出的 JSX 没有标记"：第 0 层看元素自己有没有 `data-vk-loc`，第 i 层看第 i−1 层有没有使用处标记。各层的"元素位置"就是下一层的使用处位置，所以没有单独存。冻结时在原页面上读一次，以 JSON 写进副本的 `data-vk-chain` 属性，之后只读副本。
- 翻译规则按规格的表格实现，补充约定如下：
  - 第三方组件 → 锁定图层。锁定图层是叶子，名称和使用处取最外层的那个第三方组件。
  - 只含文字 → 文字图层。子元素只能是 `display: inline` 的片段（加粗、链接等）。
  - Flex → Stack，按 `flex-direction` 分横纵；Grid → Grid。
  - 块级容器里，脱离绝对定位之后的子元素全部是块级、且没有浮动 → 纵向 Stack。
  - 其他 → Frame。
  - 绝对 / 固定定位 → 自由定位。它和类型可以并存，显示为 "Grid · Absolute" 这样的形式。
  - `display: contents` 不算图层，它的子元素直接挂到上一层。
  - 另外加了两种叶子类型：`img` / `svg` → Image（规格的表格里没有这一行）；`data-vk-frozen`、视频、图表画布 → Still（静态画面）。
- 图层名：组件使用处取组件名，文字取内容，其余取类型名（Stack / Grid / Frame）。
- 组件使用处的判定：父元素的使用链正好是本元素使用链去掉最内层之后剩下的部分，也就是本元素是该组件渲染出的最外层元素。选中框颜色：普通图层蓝 `#0d99ff`，组件使用处紫 `#9747ff`，锁定图层灰 `#8c8c8c` 并加锁形图标。
- 实例：元素位置相同、且使用链完全相同的图层。锁定图层没有元素位置，用使用处位置代替。属性面板在实例数大于 1 时显示数量。
- 选中规则按 Figma 的习惯：
  - 单击停在当前选中的深度：选中与当前选中项同一层、位于指针下的图层；没有选中时选最外层。
  - 双击朝指针方向深入一层；锁定图层不能深入。
  - ⌘ / Ctrl + 单击选最深处。
  - Esc 回到父图层；在最外层时清空选中。
  - 命中检测用画布文档的 `elementFromPoint`。画布里统一设了 `pointer-events: auto !important`，页面里 `pointer-events: none` 的装饰层和图标也能选中。
- 属性面板顶部依次显示 Type、Component、Source（无标记时显示 "Not located"）、Usage（仅组件使用处）、Instances（仅大于 1 时）。
- 键盘处理器通过 ref 读取最新的选中状态。原因：Preact 的 effect 在绘制之后才运行，单击后紧接着按 Esc 时，effect 里的闭包还拿着旧的选中状态。

**决定：大页面的图层树初始只展开前几层（2026-10-22）**

一次渲染约 3000 行图层树，会让进入编辑模式从约 35ms 涨到约 100–270ms，耗时主要在渲染行，建树本身只要约 7ms。做法：初始逐层展开，展开到下一层就会超过 200 行时停止，更深的层级折叠；选中时自动展开到选中项，并滚动到可见位置。这和 Figma 的图层面板一致。示例项目这种小页面仍然全部展开。改后在 3000 个元素的页面上实测：无头 33–83ms，读使用链约 5ms，建图层树约 7ms。

**已知限制与待定问题（留给后续 ticket）**

- 混合内容里的文字没有图层。例如 `<button><svg/> Save</button>`：它不算"只含文字"，而文字节点又不是元素，所以 "Save" 不会出现在图层树里。要支持，需要让文字节点也能成为图层，建议在 13 文字排版或 19 新建 / 删除时一起考虑。
- 待定：第三方组件包着项目内容时怎么处理。最典型的是 `motion.div`：它渲染出的 `div` 没有元素位置标记，所以整个被判成锁定图层，传进去的、带标记的项目子元素既选不中、也不出现在树里。规格写的是"不能进入内部"，但这些 children 属于项目代码。建议在 22 兼容性中决定：要么允许锁定图层露出带标记的后代，要么把"只是包了一层宿主元素"的组件当成普通图层。
- 段落里由第三方组件渲染的行内元素（比如路由库的 `<Link>` 渲染出的 `<a>`）会并进文字图层，不单独显示成锁定图层。这符合用户故事 38（链接算作同一个文字图层），但修改文字样式时可能会动到第三方组件的输出。
- 由别的组件原样渲染出来的元素（例如 `<Slot>` / `asChild` 模式）会让使用处的判定落在最内层的组件上。
- 项目代码里用 `React.createElement` 写、而不是用 JSX 写的元素没有标记，会被判成第三方。
- 02 提到的"钉住产生的内联样式"在 03 中没有用到：图层模型只读 `position`，钉住不会改它。10 读取 X / Y 时需要区分哪些内联样式是冻结时写入的，届时再给钉住的元素加标记。
- 术语：规格把"其他容器"也叫 Frame，GLOSSARY 中 Frame 的定义是"设计师新建的容器"；`Layer.isUsage` 把"使用处"用在了图层上。这两处建议用 `/domain-modeling` 统一。
