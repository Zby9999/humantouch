# 52: 径向渐变的中心与大小，色标保留原单位

**What to build:** 设计师能在属性面板上看到并修改径向渐变的中心（X、Y）与大小，画布立即生效；页面上用 px 写的色标，在色标条上的位置与页面画出来的一致，写出的样式中仍用 px。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

**Blocked by:** 11（已完成）

**Status:** done

- [x] 面板显示并可修改径向渐变的中心 X、Y 与大小（横向、纵向半径，两者相等即为圆形），画布立即生效
- [x] 页面上用关键字写的大小（如 `closest-side`、`farthest-corner`）和用 % 写的中心，没改动时原样保留
- [x] 线性与径向渐变中用 px 写的色标，在任意形状与中心下在色标条上的位置都正确；画布、参考样式和改动说明中仍用 px；新加的色标用 %
- [x] 改动说明用设计语言描述径向渐变的中心与大小，不再原样贴出 CSS 的形状文本
- [x] 画布上的拖拽手柄不在本 ticket 内（要改画布，等视图那条线合并后另开 ticket）

## 背景

- 现在径向渐变的形状与中心按 CSS 文本原样保留，面板无法编辑。
- 色标位置一律存为百分比，px 写的色标按默认椭圆（图层中心、到最远角）的半径换算，形状或中心不同时会算错。例：200×100 的图层，`circle closest-side at 30% 20%` 的半径是 20px，20px 处的色标应是 100%，现在读成约 14%。
- 写出的样式一律用 %，Agent 落地时会把源码里的 px 悄悄改成 %；px 是固定长度，% 随图层缩放，图层尺寸一变渐变就变样。
- 模型以 CSS 能表达的为界：CSS 的径向渐变不能旋转椭圆，不照搬 Figma 的旋转手柄。

## Comments

**实现记录（2026-10-29）**

- 改在 `client/paint.ts`（模型、读、写）、`Properties.tsx`（面板）、`design-values.ts`（改动说明）。`edits.ts`、`CanvasView.tsx` 没有改。
- 模型：
  - 色标改为 `{ color, opacity, position, unit }`，`unit` 是 `"%"` 或 `"px"`，记页面写的单位。
  - 径向渐变去掉 `shape` 文本，改为 `center: { x, y }` 和 `size`。`x`、`y` 是 `Length { value, unit }`，`%` 指图层宽 / 高的百分比。`size` 有两种：按关键字写的 `{ extent, circle }`；按长度写的 `{ x, y }`，两个都是 px 且相等就是圆。CSS 不能旋转椭圆，模型也不支持旋转。
- 读：
  - Chrome 的计算值里，关键字中心已换成 %，em 已换成 px，默认的 `ellipse` / `farthest-corner` / `at 50% 50%` 不写出来。只有一个长度表示圆。
  - 中心只认 % 和 px 两种长度（含关键字），`calc()` 不认。`at right 10px bottom 20px`（计算值是 `calc(100% - 10px)`）这样的渐变按原样保留中心与大小，见下面的修正记录。
  - 色标沿用 CSS 规则：先定首尾，再把比前一个已写位置还靠前的色标挪到它那里（单位也取它的），最后给省略的色标补位置。补位时两边单位相同就用同一单位，一边 px 一边 % 就用 %。比较先后用真实的渐变长度：线性是沿角度的长度，径向是终止形状的横向半径。
  - 横纵半径按 CSS 规则从中心与关键字算出：圆取最近 / 最远的边或角；椭圆到边取两轴各自的距离，到角再乘 √2。
- 渐变长度、中心与半径按背景定位区计算，默认是边框以内（`background-origin`），以前用的是包含边框的盒子。所以有描边的图层，线性渐变到角的角度和 px 色标的位置也随之更准。
- 写：
  - 色标按渐变上的先后排好，用原单位写出。
  - 径向的大小和中心照 Chrome 的写法，省去默认值。圆写 `circle 20px`，椭圆写两个长度，关键字照写，中心是正中时省略 `at`。
  - 设计师没改大小时，关键字原样保留。
- 面板（类型为 Radial 时，在色标条上方，与线性的 Angle 同位置）：
  - Center X、Center Y 以图层的 % 显示，带 "%"。输入后按页面原单位写回，px 中心按当前图层尺寸换算。
  - Radius X、Radius Y 以 px 显示，精确到 0.1px，这样输入的 px 存成 % 后读回来仍是原数。改一个半径时：两个相等就写成 px 的圆；原来是关键字就把两轴都写成图层的 %；原来是长度就各轴保留原单位。
  - 多选时，每个图层按自己的尺寸换算。
  - 色标条按当前图层尺寸和渐变长度把 px 色标换算成比例来画。超出条的色标画在条的端点。
  - 拖动 px 色标按整 px 移动，限在条内。方向键按色标自己的单位移 1（⇧ 10）。px 色标的 `aria-valuemax` 是渐变长度。
  - 位置框显示 "20px" 或 "35%"。输入带单位就换成那个单位，不带就沿用原单位。点色标条和 "+" 新加的色标用 %。
- 改动说明：
  - 色标写成 "#FF0000 at 10px"。
  - 径向渐变：默认的仍是 "from the middle out"。其他写成 "centered 30% across and 20% down, 20px out"、"from the middle, a circle out to the closest side"、"…, an ellipse out to the farthest corner"、"…, out 50% across and 30px down"，不再贴 CSS 形状文本。
  - Skill 里填充那句补了 px 色标和径向的中心与大小。
- 测试：
  - 辅接缝 `edits.browser.test.ts`：线性与径向渐变的各种读法，包括 px 色标、混合单位补位、靠前色标的处理、关键字与长度大小、关键字中心；径向渐变的写出与读回，包括圆、关键字、默认、% 与 px 混写的椭圆。
  - 命令行接缝 `cli.test.ts`：径向渐变中心与大小的说法，以及 px 色标。
  - 主接缝 `properties.spec.ts`：页面的 `circle closest-side at 30% 20%` 与 20px 色标在面板上的显示和色标条位置；改色标时形状原样保留；依次改中心、半径（到 % 椭圆，再到 px 圆）；px 色标用方向键移动；新加的 % 色标。

**修正记录（2026-10-29）：calc() 中心的径向渐变重新作为填充提供**

- 退步：上面的实现里，中心写成 `calc()` 的径向渐变（包括从右 / 下边偏移的 `at right 10px bottom 20px`）读不成中心与大小，整个填充读不出来，属性面板的 Fill 段消失；ticket 11 里这种渐变还能改色标、换类型。
- 修法：模型加了一个原样分支 `KeptRadialGradient { type: "radial", shape, stops }`，`shape` 存页面计算值里的形状、大小与中心文本。凡是读不成中心与大小的径向渐变都走这一支（不只 `calc()`，`min()` 等也一样）。
  - 写出时原样写回这段文本，色标照常排序、用原单位写出。
  - 面板不显示 Center X / Center Y / Radius X / Radius Y；色标照常加、删、拖、改，填充类型照常可换（换走再换回径向是默认椭圆，撤销可回到页面原样）。
  - 改动说明写成 "a radial gradient centered and sized as the page has it: …"，不贴 CSS 文本；Skill 里补了这句说法的意思。
  - px 色标的位置：Chrome 规整后的 `calc(百分比 ± px)`（可有多项，加减）按图层尺寸算成 px，再算真实的渐变长度；算不出来（`min()`、乘除等）按默认椭圆（图层中心、到最远角）近似。
- Chrome 不接受混用 % 与 px 的 `calc()` 大小（整条 `background-image` 无效），只含 px 的 `calc()` 大小在计算值里已是 px，所以"`calc()` 半径"在编辑器里就是普通的 px 大小，面板照常显示半径。
- 测试：`edits.browser.test.ts` 覆盖 `at right 10px bottom 20px`、`calc()` 中心（含负的百分比）、`calc()` 大小、算不出来的 `min()` 中心的读，以及改色标后的写出与读回；`cli.test.ts` 覆盖原样分支的说法；`properties.spec.ts` 覆盖这种图层的 Fill 段、不显示中心与半径字段、改色标、加删色标、换类型再撤销。

**已知限制**

- 中心或大小读不成长度的径向渐变（`calc()`、`min()` 等）按原样保留：面板上不能改它的中心与大小，只能改色标和类型。其中算不出来的（不是 `calc(百分比 ± px)` 的写法），px 色标在色标条上的位置按默认椭圆近似，可能与画布不一致；写出的样式仍用原来的 px，画布不受影响。
- 关键字写的中心（`at left top`）一旦渐变有改动，就写成 `at 0% 0%`，渲染一样，但文字和源码不同。
- 大小一旦改成横纵相等，就写成 px 的圆，页面原来的 % 单位不再保留。CSS 的圆不接受 %，面板也没有形状开关。
- px 色标在条上的位置、拖动时的换算、中心与半径的显示，都按第一个选中图层在桌面视图里的尺寸。其他视图或别的实例尺寸不同时，px 色标仍是同样的 px，画出来的比例会不同。这正是 px 的意思。
- 画布上的拖拽手柄不在本 ticket 内。
