# 82: 「只改这一处」漏到其他使用处，有几种情况页面查不出

**What to build:** 设计师定了做法（见下面「设计师决定」）。ticket 77 让页面查出「只改这一处」的改动被写进组件本身、漏到组件的其他使用处，按设计师的决定，改前的值取「认领时活页面上的值」，只做简单的版本。下面几种情况页面查不出（都不会误报）：

1. 认领之后才打开页面，或认领期间刷新了页面：页面按那时的样子重新记，之前已经漏过去的看不出来。
2. Agent 没认领就改代码，由 78 自动认领：认领时漏改已经在页面上了。
3. 只写在某个断点上的漏改（例如组件里加 `max-md:`）：页面只在窗口宽度记、只在窗口宽度比，窗口不在那个范围时查不出。

参考本功能的 spec.md（同目录上一级），目标与指标以 docs/goals.md 为准（Faithful 的虚假 ✓），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（ADR 0006、0013）。

- [ ] 78 自动认领的一轮：改前用代码开始改动之前页面上的值（例如 78 判断页面变没变时手上的那一份），自动认领时已经在页面上的漏改也查得出（第 2 种）

- [ ] 没有漏改时，`claim`、`done`、`finish` 的输出逐字不变；不跑真实 Agent

## 背景

- 来自 77 的实现记录（2026-11-02，「风险和没做到的」）和落地线整线审查。真实 Agent 一般先认领再动手，第 2 种情况少见；设计师在 77 认领后刷新页面并不少见。
- 可选做法：
  1. 改前的值从这一轮冻结的画布（`.03kind/canvas.html`）读，不从认领时的活页面读。三种情况都覆盖，但画布可能和活页面有别的出入（例如编辑期间代码改过、页面没变），可能误报；这也改动了 77 的设计师决定「改前的值是认领时活页面上的值」。
  2. 记下的值连同认领一起存进 `.03kind/`，刷新后沿用；自动认领时用代码改动前的那一次页面检查。覆盖 1、2，不覆盖 3。
  3. 在三个视图宽度上都记、都比（画布同时显示三个宽度）。只覆盖 3，代价是核对的元素多两倍。
  4. 维持现状，只在 spec 里写明这几种情况查不出。

## 设计师决定（2026-11-02，分诊）

- 第 1、2 种用做法 2：记下的值连同认领一起存，刷新后接着用；自动认领时用代码改动之前的值。第 1 种常见，第 2 种在 78 之后会变多，值得补；做法 2 也不推翻 77 定的「改前取认领时活页面上的值」，只是刷新后不丢。
- 第 3 种用做法 4：少见，补上要多核对两倍的元素，不划算，在 spec 里写明。
- 不用做法 1：从冻结的画布读改前会误报，凭空多报 ⚠️ 会让人不再信它。
