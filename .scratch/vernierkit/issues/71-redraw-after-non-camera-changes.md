# 71: 不动相机的变化之后改数值仍 ≤ 2 帧，性能测试量撤销

**What to build:** 有些变化不是相机移动，却会让整个 stage 进入视野：窗口变高、删掉旁边的视图、视图变矮。这类变化之后，编辑层也像相机停下后一样，重新只画看得到的部分，改数值保持在 ≤ 2 帧。性能测试补上这些情况，再加一项"连续改值中按 ⌘Z / ⇧⌘Z"，撤销那一帧也有数字。

参考本功能的 spec.md（同目录上一级），目标与指标以 docs/goals.md 为准，用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（ADR 0011）。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 窗口变高、删掉旁边的视图、视图变矮后约 100ms，stage 重新只画看得到的部分，与相机停下后一样。e2e 至少覆盖"删掉旁边的视图"和"窗口变高"
- [ ] 性能测试新加一项：大页面上先做一次上面的变化，再改数值，p95 ≤ 33.3ms
- [ ] 性能测试新加一项：连续改值时按 ⌘Z 和 ⇧⌘Z，记下那一帧的主线程时间和"按键到画完"的时间（中位数 / p95），目标 p95 ≤ 33.3ms。达不到就记下数字和原因，和设计师商量，不要自己放宽目标
- [ ] 进入编辑模式、改数值、按住方向键、拖拽四项照旧达标
- [ ] 改动前后的数字记在 Comments（docs/goals.md「度量」）

## 背景

- 来自 22 的遗留风险。风险第 4 条：这类变化不触发重新计时，stage 会一直粘住，直到下一次相机停下或模式切换动画结束，期间改数值回到约 25–34ms，最差超过 33ms 的目标。22 把要不要处理留给主线决定，用户 2026-10-30 决定处理。
- 撤销、重做时旁边的视图立即追上，是设计师 2026-10-30 的决定（ADR 0011）。代价是连续改值中按 ⌘Z 的那一帧要同时重画三个视图，但性能测试不测撤销，这一帧现在没有数字。
- 有窗口的验收会打开一个 Chrome 窗口、抢焦点，跑之前先问设计师；平时用 headless 量。
