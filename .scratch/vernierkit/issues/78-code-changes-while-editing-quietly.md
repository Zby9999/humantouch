# 78: 编辑时代码变了：该锁就锁，其余只在左下角轻轻提醒

**What to build:** 改造 66「编辑模式中没认领却在改代码」的反应。不再一律在画布正中弹窗、暂停编辑，而是按页面实际发生了什么分四种情况：

1. **Agent 没认领就在落地设计师的改动**：页面上出现了画布上某条改动。页面当作 Agent 认领了，编辑层照常收起成切换按钮、锁定，进度环按页面核对走，和跑了 `claim` 之后一样，不弹窗。
2. **代码变了，页面看起来没变**（工程上的整理：重命名、拆函数、加类型等）：什么都不做，画布也没有过时。
3. **页面变了，画布上还没有改动**：自动按最新代码重新冻结。画布区域左下角弹一个 toast「Canvas updated to the latest page」，约 3 秒后消失。
4. **页面变了，画布上已有 N 条改动**：画布不动。左下角弹 toast「The page has changed since this canvas was frozen」，带「Update canvas」按钮。点了以后，在这个 toast 里确认「Discard your N changes and update?」，两个按钮 Cancel / Discard and update。确认后放弃全部改动，按最新代码重新冻结。

参考本功能的 spec.md（同目录上一级），目标与指标以 docs/goals.md 为准，用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（ADR 0001、0005、0013）。

## 背景

- 66 做出的弹窗会盖住画布、暂停编辑。设计师 2026-11-01 看过以后觉得打扰太大。
- 编辑时代码会变，一般是四种原因：
  1. Agent 还在做上一件事，设计师已经进来调了；
  2. 设计师在对话里让 Agent 改了别的；
  3. Agent 没按流程，直接落地设计师的改动；
  4. 设计师自己或工具改了代码（手改、切分支、格式化）。

  只有原因 3 是流程漏洞。ADR 0005 的锁靠 `claim` 触发，Agent 没认领就锁不上。其余几种设计师一般知道代码为什么在变，不该打断。
- 画布是冻结的副本（ADR 0001），代码一变就可能过时。样式改动受影响不大：认领时页面按代码现状重读「改前」，核对也在活页面上做（64、68）。真正的风险是设计师照着旧样子调细节，所以页面变了要让设计师知道。
- 「回预览再进来」只在画布上没有改动时才会重新冻结（05 的规则）。有改动时，回到的还是原来那张画布，所以情况 4 给的是「放弃改动并更新」，不是「回到预览」。

## 设计师决定（2026-11-01）

- 情况 1 自动认领，认领之后的行为和正常认领一样，没有特殊规则。
- 页面看起来没变的代码改动不提示：工程上的整理不需要设计师操心。
- 页面变了要让设计师知道，用 toast，不用弹窗；位置在画布区域左下角。理由有两条：
  - 它是外面发生的事、带按钮、停得久，和底部正中回应设计师自己操作的 toast 不同，分开放一眼就能分清；
  - 现有 toast 是新的顶掉旧的，放在一处，带按钮的这个会被取整之类的提示顶掉。
- 情况 4 给「Update canvas」并二次确认。设计师一般清楚自己改了多少，确认防的是手滑和记不清，所以要写出会丢几条。
- **先不做「保留改动、自动搬到新画布上」**（按新代码重新冻结，再把改动重新应用上去）。在主流程里，Agent 先把页面做完，设计师再精调，编辑时代码变化不常见。为它写一个按每种改动重做画布的模块不值得，结构改动还会对不上。设计师发现自己常常在过时的画布上调东西时，再回来做；样式改动最容易搬，可以先只做它。

**做了什么（起点 2fec03a）**

- 66 的居中暂停窗口、暂停编辑都去掉了（`CodeChangeNotice.tsx` 删除，`.tk-paused` 的样式删除）。编辑模式中、这一轮没被认领时，开发服务器给页面送来热更新，页面就：
  1. 从热更新开始起看着页面的变化（只在这次变化期间看）；
  2. 等代码停下约 1 秒（和 66 一样：相隔不到 1 秒的热更新算同一次，Agent 连着写好几个文件只处理一次）；
  3. 再等设计师手上没有正在进行的操作：鼠标按着（拖拽、拖数值、改尺寸，ADR 0012），输入框里打了字还没生效，画布上的文字图层正在打字，生成说明正在写；每 0.25 秒再看一次；
  4. 先问本机服务现在的状态（`GET /status`，和 66 一样），已认领就什么都不做；
  5. 然后按 ticket 的四种情况：
     - **情况 1**：画布上页面能核对的改动里，有一条在页面窗口宽度上显示了，就当作认领。页面先把还没存的编辑存好，再请本机服务认领（新加 `POST /claim`）。之后完全走正常认领的路：本机服务写下认领状态、推送给页面，编辑层收起成切换按钮、锁定，进度环按页面核对走；`done`、`finish`、67 的「Agent 好像停了」、长按结束这一轮都照常。Agent 之后自己跑 `claim`，拿到的是「claim 再跑一次」的说法。
     - **情况 2**：热更新前后，元素的增删、属性、文字和样式表内容都没变，什么都不做。源码标记（`data-tk-loc`、`data-tk-usage`）随行号移动不算变（改类型、加一行都会让它们移动）；React 把同样的内容重新画一遍、换了新元素也不算；编辑层自己的宿主元素、Vite 报错时盖上来的提示层不算页面。
     - **情况 3**：画布上没有改动，就按最新代码重新冻结，视图的位置和缩放照旧，左下角 toast「Canvas updated to the latest page」，约 3 秒消失，指针停在上面时不消失。
     - **情况 4**：画布上有改动，画布不动，左下角 toast「The page has changed since this canvas was frozen」带「Update canvas」，约 8 秒消失，指针或焦点在上面时、确认问着时不消失。点了以后在同一个 toast 里问「Discard your N changes and update?」（1 条时写 change），Cancel 收起确认、画布不动；Discard and update 走改动列表 Discard all 的同一条路径放弃全部改动，再按最新代码重新冻结，视图位置和缩放照旧。同一次过时只提醒一次，直到画布重新冻结（情况 3、Update canvas，或没有改动时进入编辑模式）。
- 两个 toast 放在画布区域左下角：Layers 面板右边 16px，面板收起或播放时离窗口左边 16px，离底 16px。样式复用现有 toast 的深色胶囊（`.tk-toast`）和改动列表的按钮（`.tk-button`、`is-danger`），没有另起一套视觉，具体样子留给前端调整线。它们和底部正中的 toast 各管各的，互不顶掉；两者之间仍是新的顶掉旧的。
- 重新冻结的做法：编辑层换一张新画布（外壳按新的 key 重新挂上），冻结时不做进入编辑模式的动画、不先变透明，相机直接放在原来的位置。重新冻结前先把还没存的东西存好（例如画布外图层的移动）。
- `last` 能退回自动认领的一轮：Agent 没认领就开始改代码，等页面认领时代码已经变了。所以本机服务在这一轮被编辑、还没认领时，第一次保存这一轮、以及每次代码停下约 1 秒（Vite 的文件监听，`.03kind/` 不算）各记一份当时的代码（git tree，和 `claim` 一样，不动暂存区）；页面认领时带上它看到的这次变化从什么时候开始，本机服务取这之前最近的一份当「改前」。这样 Agent 在这次变化里的修改也在 `last` 的 diff 里。没有这样一份时用认领时的代码。

**风险和没做到的**

- 判断「页面变了」是按热更新前后 DOM 和样式表文字比的：页面自己一直在变的东西（时钟、轮播）在这期间变了，也算页面变了（没有改动时会重新冻结，有改动时提醒一次）。CSS-in-JS 用 `insertRule` 改样式表、不改文字的（开发模式下少见），看不出来。`<link>` 引入的样式表热更新时 Vite 换一个带新时间戳的 `<link>`，算页面变了，即使内容一样（示例项目的样式都是 `<style>`，不受影响）。
- 重新冻结时外壳整个换新：选中、播放、⌘Z 的历史都清掉（情况 3 本来就没有改动；情况 4 是设计师确认放弃之后）。新画布冻结好之前，画布区域会空一下（大页面上约一两帧到 0.1 秒），不会露出底下的页面。
- 自动认领的一轮如果带着上一轮留下的改动（68），不会像 `claim` 那样先请页面按代码现状重读「改前」和「Currently set by」：Agent 没跑 `claim`，本来也拿不到改动说明；它之后真跑 `claim` 时拿到的是「claim 再跑一次」的说法。
- 本机服务为了 `last`，在这一轮被编辑时每次代码停下会跑一次 `git add`（用自己的临时 index，不动暂存区），往仓库里写改过的文件的对象，和 `claim` 一样。只在有没认领的一轮、代码在变时做。
- 写 `code-changes.spec` 时，头两次整个文件跑，「按着鼠标时」「打了字还没生效」各有一次 5 秒内没等到 toast；之后整个文件连跑 6 遍、相关几条连跑 3 遍、两次全量 e2e 都过，没能复现，原因没有查实。为此加了两处保险：开发服务器说开始热更新、5 秒都没说结束的当作结束；判断中出错只记日志。
- ADR 0013 正文里「没认领就改代码：编辑层先暂停编辑，提示设计师」一条是 66 时的写法，78 的变化记在它最后一条后果里；按规矩 ADR 不改，这里记一下。
