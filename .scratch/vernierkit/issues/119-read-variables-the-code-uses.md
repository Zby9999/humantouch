# 119: 面板读出代码里在用的设计变量

**What to build:** 现在属性面板只认这一轮在面板里选过的设计变量。代码里本来就用着变量的值，面板上只显示数值，例如卡片写的是 `bg-brand-2`，填色那里只看到 `#2F6BFF`。值等于哪个变量，是按数值去对的，所以两个变量同值时可能对错，例如 `brand-1` 恰好也是 `#2F6BFF`。复制样式（ticket 117）也因此带不过去：设计师复制的是用 `brand-2` 的图层，粘过去可能记成 `brand-1`（117 代定 3）。Figma 在面板上能看到图层绑的是哪个变量。

要做到：
- 选中图层时，面板每个能选设计变量的地方，都显示代码里给这个值的那个变量，样子和选过的变量一样，但不算改动。这里说的变量，包括 Tailwind 主题的类（`bg-brand-2`、`p-gutter`）、CSS 规则里的 `var(--brand-2)`、Tailwind v3 配置里的值。
- 读的是正在工作的视图里实际起作用的那条规则：在手机视图里看手机宽度上的那条。
- ⌥⌘C 复制时把这些变量一起记下，⌥⌘V 粘过去还是那个变量。
- 两个变量同值时，代码里用的那个优先于按数值去对。

参考本功能的 spec.md（同目录上一级，「属性面板」「设计变量提示」「改动单」里「改前值的来源」），用词以 GLOSSARY.md 为准（设计变量），并遵守 docs/adr/ 中的决策（ADR 0008）。

### 做了什么

- `src/client/code-variables.ts`（新）：选中时读。按正在工作的视图里这个图层**自己的**规则，在层叠里胜出的那条声明（`style-source.ts` 新的 `winnersAmong`，物理、逻辑属性和简写放在一起比，例如 `p-4 px-6` 左右是 `6`），声明写的是 `var(--x)` 或 `calc(var(--spacing) * N)` 就是那个变量（Tailwind v4 主题的类、CSS 规则、`bg-(--x)`）；不是的，按规则的类名认 Tailwind 的变量（v3 把值写死了：`bg-brand-2`、`hsl(var(--primary) / …)` 的 `bg-primary`）。**只有这个变量的值正好等于面板上现在显示的值才算**，所以透明度修饰、几条叠在一起、改过的值都自然落回数值。一个元素第一次读时一次走完所有属性的层叠，按元素缓存。
- `Editor.inCode(layer, property)`（`edits.ts`）：在正在工作的视图里读（ADR 0008），这一轮新建的图层不读；按这个属性在这个图层上的改动记个戳，改动变了才重读。`bind` 多了一个 `code` 参数：一条改动里没改的部分，优先记成代码里用的那个，而不是按值相等的第一个；它在改动开始时读一次，拖动的每一步沿用。
- 面板：`boundTo` = 这一轮选过的，否则代码里的（`inCode`），样子和选过的一样，不标改动、不进改动列表。解开代码里的变量只是面板上的状态（这次选中内有效），不调 `editor.set`，不记改动、不产生撤销步；接着输入新值才是改动。正在输入的框不会因为变量晚到而变成芯片（`useTypedIn`，`variables-late.spec` 抓到的）。Variants 列表的「在用」也认代码里的。
- ⌥⌘C 把代码里的变量和选过的一起记下，⌥⌘V 作为选过的设上；目标的值相同、已经是那个变量（选过的、按值认的或代码里的）时不算改动。

#### 代定的事（待设计师确认）

1. **Tailwind 的默认主题也算**（`p-4` 显示 `4`、`bg-white` 显示 `white`、`rounded-xl`、`text-stone-600`），和面板里能选的变量一致（默认的本来就列在「Tailwind」一组里）。结果是 Tailwind 项目里大多数字段都显示成名字，要输数值得先点「解开」，这和 Figma 里绑了变量的字段一样。觉得太多的话，可以改成只显示项目自己的。
2. 解开代码里的变量**只在面板上**把这一项换回输入框（这次选中内有效，换个选中再回来又是名字），不记改动。代码里继续用那个变量，直到输入了新值。Figma 里解开是一次改动，这里的改动单只记值的改动，同值没法记成「去掉变量」。
3. 同值换变量不算改动：在 `brand-2` 的卡片上选同值的 `brand-1`，或 ⌥⌘V 粘一个同值的别的变量，什么也不记，面板仍显示 `brand-2`。原因同上，和 117「选一个值和现在一样的变量不算改动」一致。
4. 读不出来源的照旧显示数值：写死的值；带透明度或混在一起的（`bg-brand-2/50`、`color-mix`）；从上层继承来的文字样式（只读图层自己的规则，所以文字在 `text-ink` 的 div 里，文字图层显示数值，div 显示 `ink`）；项目设计变量以外的变量（第三方的 `var(--lib-x)`）；四边或四角不是同一个变量的统一圆角或描边颜色（这时分角圆角各显示各的）；值和变量对不上的。渐变色标、投影的颜色、文字投影不读（Tailwind 的 `from-*`、`shadow-*` 颜色要沿着 `--tw-*` 走，没做）。
5. 改前的值**不**写成变量名（不加「from `brand-2`」）：改动说明逐字不变。Agent 看「Currently set by」里的声明和类名，已经知道代码现在用的是什么。
6. 一条改动里没改的部分记成代码里用的变量（例如只改上内边距，其余三边记 `gutter`，不记同值排在前面的 `5`），**Variables** 一行因此可能和以前不同；28 个场景里没有一句变。改动开始前就有的改动（变量晚到时 `bindRecorded` 补名字）仍按值相等的第一个。
7. ⌥⌘C 带上的代码里的变量，粘过去记成「选过的」（`picked`），改动说明里就是那个变量。复制源上解开了的不算，照样带上（解开只是面板状态）。
8. 多选时，各图层都是同一个变量才显示名字（和选过的一样）；有的是选过的、有的是代码里的也算同一个。

#### 遗留风险

1. 选中时多一次层叠遍历：96 张卡片的页面上中位数多 0–2ms、p95 多几 ms（headless，负载高），没在窗口模式的 Chrome 里量。一次改动的第一步也多一次遍历（`sourcesFor` 之外），一次改很多元素时（解散 Stack 给 N 个子图层设宽高、多选粘贴）每个元素各一次，没专门量。
2. 缓存按元素记，不随结构改动失效：图层换了容器以后，`:first-child`、后代选择器胜出的规则可能变了，还用旧的。只有新值恰好等于旧变量的值时才会显示错，因为每次都会和现在的值核对。
3. 同一条规则里同时写了物理属性和逻辑属性（`padding-inline-start: a; padding-left: b`）时，分不出谁在后，取先列的那个。同样有值核对兜着。
4. 类名那条路认任何长得像 Tailwind 的类（手写的 `.text-title{font-size:18px}` 也会去对 `title`），也靠值核对兜着。
5. e2e 默认把代码里的芯片解开，所以除了 `code-variables.spec` 和单元测试，别的测试看不到错显示的芯片；tw4 的 `var()` 那条路 e2e 里只有一条测试。
6. 示例里几乎所有字段都成了芯片（代定 1）：设计师实际用起来是不是太吵，没人试过。tuning 可能会改芯片的样子（tuning 定样子，票定行为）。
7. 真 Agent 没跑；认领说明逐字没变，Agent 那边没有新东西可看。
