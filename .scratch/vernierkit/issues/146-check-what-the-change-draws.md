# 146: 核对比画出来的效果：值的写法不同、看起来一样的，算显示了

**What to build:** ADR 0016 的第一部分（设计师 2026-11-11 定：唯一的真源是视觉）。

现在的核对读页面上这一层这项属性的值，按设计用语逐字和改后值比（`check.ts` 的 `sameValue`）。所以「写法不同、画出来一样」会被判成没显示：

- 0 的字间距（ticket 142）；
- spread evenly 时主轴上的点（ticket 145）；
- Agent 用另一种写法画出了一样的效果，比如用 gap 代替 margin，用 `max-w-[500px]` 代替固定的 500 宽（容器够宽时一样），用 `justify-end` 代替很大的底部内边距。

要做到：

- 页面上读到的值和改后值对得上，照旧直接算显示了。这一步不变，也最快。
- 对不上时，再比这条改动在页面上画出来的效果，一样就算显示了。
- 建议的做法（由实现定，写进 Comments）：在页面这一层上临时加上画布上这条改动的样式，画面一点不变，说明页面已经显示了它，然后马上拿掉。
  - 「画面」指这一层和它里面各层的位置与尺寸、画出来的颜色、文字的宽度等。
  - 这和 `AS_WRITTEN` 里「在页面上画一下再比」的做法同一路数，同样要在绘制前完成，不能让页面闪。
  - 比的只是这一条的样式加不加，同一轮里别的改动有没有落地不影响它。
  - 位置和尺寸差 0.5px 以内算一样，颜色取整后相同算一样。
- 这一张只管改动所在的宽度：桌面视图里的改动看页面窗口的宽度，断点上的改动看它范围内的视图宽度。其他视图宽度的规矩是 ticket 147。在 147 做完之前，其他宽度照现在的做法核对，但同样用「画出来一样就算」。
- 确实不一样的，照旧判 not shown，`actual` 照旧报页面读到的值。
- ticket 142、145 加在 `AS_WRITTEN` 里的特例，能被这个机制吸收的就拿掉；保不保留由实现决定，写进 Comments。
- 改动说明、`claim` 的写法不动。

参考 ADR 0006、0016、`check.ts`、`page-copy.ts`；用词以 GLOSSARY.md 为准。

**2026-11-11，实现（分支 `ticket-146`）**

改了什么：

- 新模块 `src/client/draws-alike.ts`，`check.ts` 的 `lookStyle` 和 `lookGap` 在值对不上时用它。值对得上照旧直接算显示了（这一步没变）。
- 做法一（票里建议的）：把画布上这条改动的参考样式（`Change.style`）临时加到页面这一层的元素上，比加之前和加之后画出来的东西，一样就算显示了，然后马上拿掉。
  - 加样式用 document 的 adopted stylesheet（声明全是 important，选择器按元素在父元素里的位置从根写到它），不改属性、不插元素，所以盯着页面的 MutationObserver（`page-checks`、`code-changes`、页面副本）都看不到。加和拿掉在同一个任务里、绘制前完成，页面不闪。
  - 比的东西：这一层、它的父层、父层里的其他层、它里面的各层的位置和尺寸（0.5px 以内算一样；没有面积的盒子只比尺寸，它画不出来）；这一层和它里面各层的颜色（按面板的读法画成颜色再比，所以 `white`、`#fff`、`oklch(1 0 0)` 一样）和其他画法（阴影、圆角、透明度、字体等，数字取整后比）；里面每段文字的位置和宽度。
  - 有 transition 的，加和拿掉时先把 transition 停住，再按原样放开，不会起动画（测试里查了 `getAnimations()` 为空）。窗口和外面滚动容器的滚动位置量完后放回原处。
  - 说不准的不算一样：元素没画出来；样式是空的；页面自己的 important 声明会盖过它（style 属性里的、CSS layer 里的、带 id 的）；样式是排列子层的（gap、对齐等）而这一层不是 flex/grid，或者是摆放自己的（flex-grow 等）而父层不是；加上去的 px 长度没生效（被页面的 max/min 卡住，比如页面写了 `max-width: 498px`，加 `width: 500px` 不会变，不能据此说一样）；区域里超过 1500 个元素；有 input/textarea/select（它们的字没有文字节点，量不到）。
- 做法二（补做法一的缺口）：页面用「加法」的写法画出同样的效果时（用子层的 margin 代替 padding，用 margin 代替 gap），把样式再加上去会多挪一次，做法一说不一样。所以页面第一次看这条改动时（认领后马上，改动还没落地），在同一次加样式里顺便记下「这条样式会把哪些东西挪到哪里」（`EffectNotes`，按改动和宽度记，每个元素一份，位置相对父层/本层，按结构路径认）。之后页面上这些东西都在记下的位置（0.5px 以内），就算显示了。
  - 只在第一次看时记，之后不再补记（代码已经改过，记下的就不是改动本身的效果）。第一次看就已经对得上的，也标为已看过、不记。
  - 只改画法的属性（填充、圆角、阴影、颜色等，`PAINT`）什么也不挪，不记；样式里有画法类属性的也不记（评审 2）。只在认领前就看到这一轮的页面上记（代定 2）；同一轮别的改动在附近时不用（风险 1）。
  - 第一个宽度没显示时，其他宽度第一次也照样去看、去记，结果仍按第一个没显示的报。
  - 循环出来的很多实例：只给前 4 个加样式去记，后面的找一个布局一样的（里面各层、本层尺寸、父层尺寸都一样）照搬。循环时只记每个实例自己的尺寸和里面各层的位置（评审 6）。
  - 只记在页面的内存里（`EditorLayer` 和 `otherUsages` 一样保留到这一轮不再认领），没写进 `.humantouch/`；页面刷新后没有记录，只剩做法一。
- 为了不变慢：同一个元素、画面（加样式之前读的那份）和样式都和上次看时一样时，直接用上次的结果，不再加一次样式（加样式会让整页重算样式）；只读这一层和它里面各层的画法，父层和兄弟层只量位置尺寸；important 的判断对同样 tag/class/style 的实例只算一次。
- `AS_WRITTEN`：
  - ticket 142 的 `letterSpacing` 特例保留（评审后放回）：页面和改动都是 0（任何单位）就算显示了，不用画面，没画出来的层也一样。其余值对不上时走做法一：`0.0625em`（标题 32px 时等于 2px）对 2px 判为显示了（以前是 not shown，这是故意的）。
  - 保留 ticket 145 的 `align` 特例：页面写 `align-items: stretch`、画布是 start 时，子层的盒子宽度不同（文字位置一样），做法一会说不一样。
  - stroke 不走画法比较，照旧按写法比（见代定 3）。
- `actual` 照旧报页面读到的值；`claim`、改动说明都没动。

代定：

1. 做法：值对不上时先「临时加画布样式、看画面变不变」，再看「第一次看时记下的挪动」。两条都过不了才 not shown。
2. 做法二的记录只在页面内存里，而且只在「认领前就看到这一轮」的页面上记：认领时已经打开的页面才记；认领后才打开或刷新的页面不记（它看到的可能已经是 Agent 改过的代码）；认领前来过代码更新、认领后来过代码更新、或页面 DOM 有变动，都关掉记录，没记的宽度不再补记。没记的只剩做法一，用加法写法画出来的会判 not shown（不会误判显示了）。要不要写进 `.humantouch/`（像 ticket 82 的 otherUsages）以后再定。
3. stroke 不比画法，照旧按写法比：1x 屏上 1.5px 和 1px 画出来一样，2x 屏上不一样，改动要在任何屏上都对。
4. 145 的 align 特例保留（stretch 和 start 的盒子宽度不同）；142 的 letterSpacing 特例也保留（评审：它便宜，没画出来的层也能说）。
5. 「画面」的范围：这一层、父层、父层里的其他层、这一层里面的各层和文字；画法只看这一层和它里面的。页面其他地方不看。
6. 颜色按面板读法比（8 位 hex 加两位小数的不透明度）；其他画法的数字，1 以内保留两位小数，大于 1 取整。
7. 说不准就不算一样（见上面列的几种），宁可 not shown，也不出虚假的 ✓。
8. 循环实例只给前 4 个加样式去记，后面的按布局一样的照搬。
9. 新场景用宽度（`max-w`）而不是 padding 换 margin：后者要靠认领后、落地前的第一次看来记，bench 里 claim 和 scripted 落地之间的时序说不准，场景会不稳。

风险：

1. 做法二只看样式挪动过的东西。页面挪对了这些，但又多挪了别的（比如父层尺寸变了、兄弟层动了），也会判显示了。同一轮有别的改动落在这一层、它的父层、兄弟层或里面的层（或往这些地方挪进/挪出层）时，做法二不用（评审 7）：别的改动可能把记下的东西挪到同样的位置。这时只剩做法一，可能 not shown（安全的方向）。
2. 页面重新渲染后实例的个数或顺序变了，记录按序号对应，可能对错实例；对错了多半是对不上（not shown）。
3. 选择器的优先级随层数增加；页面里不在 layer、不带 id 但优先级更高的 important 规则会盖过它。px 长度有「没生效」的检查兜着，颜色、关键字没有。很少见。
4. `::before`/`::after` 的内容没有文字节点，量不到；改动只影响伪元素时可能误判一样。
5. 加样式会让整页重算一次样式。没落地的改动每次看都要加一次（画面和上次一样时用缓存跳过）。很大的层（上千个元素）即使缓存命中，每次看也要约 10ms 去读画面（见评审 13）。
6. 暂停的 transition：如果看的那一刻这一层正在过渡，过渡会直接跳到终点。
7. （评审后不再是风险：142 的 0 字间距特例放回了，没画出来的层照旧按值算。）
8. 缓存按元素和样式分开存（同一元素上几条改动互不挤掉），按「加样式之前读到的画面 + 这些属性的计算值 + 窗口宽度」认；页面的规则变了而这些都没变（比如加了一条暂时不起作用的 max-width），会用到旧结果。
9. 循环实例「布局一样就照搬」：布局一样、但前 4 个之外的实例里样式会挪得不一样（很少见），可能判错；判错多半是对不上（not shown）。
