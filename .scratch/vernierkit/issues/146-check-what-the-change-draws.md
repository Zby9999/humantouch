# 146: 核对比画出来的效果：值的写法不同、看起来一样的，算显示了

**What to build:** ADR 0016 的第一部分（设计师 2026-11-11 定：唯一的真源是视觉）。

现在的核对读页面上这一层这项属性的值，按设计用语逐字和改后值比（`check.ts` 的 `sameValue`）。所以「写法不同、画出来一样」会被判成没显示：

- 0 的字间距（ticket 142）；
- spread evenly 时主轴上的点（ticket 145）；
- Agent 用另一种写法画出了一样的效果，比如用 gap 代替 margin，用 `max-w-[500px]` 代替固定的 500 宽（容器够宽时一样），用 `justify-end` 代替很大的底部内边距。

要做到：

- 页面上读到的值和改后值对得上，照旧直接算显示了。这一步不变，也最快。
- 对不上时，再比这条改动在页面上画出来的效果，一样就算显示了。
- 建议的做法（由实现定，写进 Comments）：在页面这一层上临时加上画布上这条改动的样式，画面一点不变，说明页面已经显示了它，然后马上拿掉。
  - 「画面」指这一层和它里面各层的位置与尺寸、画出来的颜色、文字的宽度等。
  - 这和 `AS_WRITTEN` 里「在页面上画一下再比」的做法同一路数，同样要在绘制前完成，不能让页面闪。
  - 比的只是这一条的样式加不加，同一轮里别的改动有没有落地不影响它。
  - 位置和尺寸差 0.5px 以内算一样，颜色取整后相同算一样。
- 这一张只管改动所在的宽度：桌面视图里的改动看页面窗口的宽度，断点上的改动看它范围内的视图宽度。其他视图宽度的规矩是 ticket 147。在 147 做完之前，其他宽度照现在的做法核对，但同样用「画出来一样就算」。
- 确实不一样的，照旧判 not shown，`actual` 照旧报页面读到的值。
- ticket 142、145 加在 `AS_WRITTEN` 里的特例，能被这个机制吸收的就拿掉；保不保留由实现决定，写进 Comments。
- 改动说明、`claim` 的写法不动。

参考 ADR 0006、0016、`check.ts`、`page-copy.ts`；用词以 GLOSSARY.md 为准。
