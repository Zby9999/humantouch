# 103: 页面核对靠认领时的代码快照，在源码里对照找到图层

**What to build:** Agent 改了代码以后，页面核对要回答「设计师改的那个图层，现在是页面上的哪个元素」。ticket 99 起，页面在 DOM 这一侧找：把这一轮存下的画布和页面上的源码标记按顺序配对，所有配法都指向同一个元素才认，分不清就说找不到。这已经不出虚假的 ✓，但能确定答案的信息在源码里，不在页面上：几个一样的兄弟挨着、上面删了一个同类兄弟、删掉的图层旁边有个像它的，页面这一侧只能说找不到或「没核对」（99 代定 1–3）。

工具手里有两份代码：认领那一刻 `snapshotCode` 存下的整份代码（git tree，`last` 撤销靠它），和现在磁盘上的。要做到：同一个文件拿改前、改后两个版本对照，先逐行比（没动的行直接对上：上面加了行、外面包了一层、参数拆成多行），再在 Agent 改过的那几段里把两边解析成 JSX，按标签、在父元素里排第几、属性像不像把元素一一对上，得出「改前 `file:line:col` 的元素现在在 `file:line':col'`」，页面按新位置去找。99 的页面配对留作第二道检查：两边都指向同一个元素才认；不一致、或没有快照（项目不在 git 里）时，照 99 的做法，认不出唯一的一个就说找不到。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（ADR 0006 的 Consequences：代码改了以后页面要跟着找到图层本身，认不出就说找不到；ADR 0011、0013）。

**Blocked by:** 无（开线时间等真实复验的数据，见「设计师决定」）

**Status:** ready-for-agent

- [ ] 先复现，用脚本剧本（`apply`）或单元测试，在 99 的代码上看着这几种情况说找不到或「没核对」：上面删了一个同类兄弟、图层上移；几个一样的、没有文字的兄弟挨着，删掉其中一个；Agent 改了图层自己那一行（`className`）同时在上面加了行；外面包一层、参数拆成多行（99 已经对的，改后仍对）
- [ ] 源码这一侧对照：改前那一份从认领时的快照取，不另存、不提交、不动设计师的分支和历史；对照在本地服务（node）那边做，页面拿到新位置去找；只对这一轮改动涉及、又被改过的文件做
- [ ] 两边对不上、或元素在源码里被删掉重写、挪进循环时，说找不到；删掉的图层在源码里没了就是删了

## 背景

- ticket 99 合并后（2026-11-05），设计师问：跳出 99 的做法，从第一性原理看最好的解法是什么。规划会话的回答：识别图层是「代码改动前后同一个东西在哪」的问题，信息在源码里，应该在源码这一侧对照，不在页面上猜；在源码里写 ID（动了设计师的代码，Agent 可能删掉或复制）、让 Agent 告诉 `done` 改的是哪个（ADR 0013 不靠 Agent）、按组件树路径认（包一层就变）都不如它。
- 已有的部件：认领时的快照（`snapshotCode`，`RoundState.code`），源码标记用的解析器（Babel，`source-marker.ts`），99 的页面配对（`page-elements.ts`）。

## 设计师决定（2026-11-05，分诊）

- 走源码对照，99 的配对留作第二道检查。
- 什么时候开线看真实复验（97–101 合进后按 88 的次数重跑 24 个场景）的数据：复验里「写对了却说找不到 / 没核对」的条数明显，就在发布前做；很少，就放到发布以后。
