# 56: 只含文字的按钮与链接也能改外观

**What to build:** 页面上只含文字、但自己画出一个盒子的图层（例如 `<button>Close</button>`，或画出背景、边框、内边距、圆角的 `<a>` 与 `<span>`），设计师能像改 Frame 一样改它的填充（背景）、描边、圆角和效果（`box-shadow`，含内阴影，以及模糊），同时仍能改它的文字排版。纯文字（段落、标题、不画盒子的行内文字）仍按现在的文字图层处理。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

**Blocked by:** 11、12、13、53（都已完成）

**Status:** needs-triage

验收项是草案，等用户定下设计后再定稿：

- [ ] 只含文字的 `<button>`，以及画出盒子的 `<a>`、`<span>`，属性面板提供 Fill（背景）、Stroke、Corner radius、Effects（`box-shadow`）和 Text 段，文字颜色在 Text 段里改
- [ ] 它在页面上原有的背景、边框、圆角和 `box-shadow` 能正确读出并显示在面板上
- [ ] 纯文字图层不变：Fill 仍是文字颜色，Effects 仍写 `text-shadow`
- [ ] 改动说明和 Skill 分得清这两种图层
- [ ] 撤销、断点上的改动、推广和设计变量，在它上面与其他属性的表现一致

## 背景

- 现象：只含文字的 `<button>`、`<a>` 被当成文字图层。ticket 13 让它的 Fill 只改文字颜色；ticket 11、12 的描边、圆角、`box-shadow` 和模糊只给 Stack、Grid、Frame、图片和静态画面；ticket 53 给它写 `text-shadow`，它在页面上原有的 `box-shadow` 不显示。示例项目里 Dialog 的 Close 按钮就是这样：这是设计师最常改的按钮，它的背景、边框、圆角却都改不了。
- 根源在图层模型（ticket 03 判定文字图层的规则），不是属性面板这条线带来的回退。属性面板线整线审查时发现了它；因为要改图层模型，合并前改风险高，没有在这条线里做。
- 需要用户决定的设计点：
  - 怎样判定"画出一个盒子"：按标签，还是按计算样式里的背景、边框、内边距和 `display`。
  - 这类图层在图层树里叫什么、用什么图标：一种新的图层，还是带文字的 Frame。
  - Fill 在这类图层上指背景时（与 Figma 里按钮是带文字的 Frame 一致），文字颜色放在哪里。
