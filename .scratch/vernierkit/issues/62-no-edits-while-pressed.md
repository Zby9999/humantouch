# 62: 鼠标按着时快捷键不改画布和历史

**What to build:** 鼠标按着、还没松开时，会改画布、改动单或撤销历史的快捷键都不起作用：按下去什么也不发生，改动单、画布、Layers 都不变。"按着"包括：在画布上按住图层（从按下起，还没移动满 3px 也算，一直到松手、按 Esc 取消拖拽或指针被取消）、在数值图标上拖、拖渐变色标、用 T / F 工具画图层。撤销和重做（ticket 61 已经在拖拽图层时拦下）并进同一条规则。平移和缩放视角的键（空格平移、⇧1 看全部视图，⌘ 加滚轮本来就不是键）、Esc、修饰键本身（拖拽中 ⌘ 关吸附、⌥ 量距离或放下时复制、拖数值时 ⇧ 一次 10）照常可用，浏览器自己的快捷键（编辑层不用的 ⌘ 加字母，例如 ⌘R、⌘F）也照常。输入框里还有没提交的文字时，⌘Z 仍归输入框自己（同 61）。不在按着时，所有快捷键的行为不变。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（拖拽中的让位见 ADR 0011，画布外的图层见 ADR 0009，本条规则写进 ADR 0012）。

## 背景

- 来自 ticket 61。61 只拦下了拖拽图层时的撤销和重做，在它的 Comments 里实测和列出了其他快捷键、其他"拖"的问题：
  - 拖拽中 ⌘D 复制出的副本一直带着拖拽用的行内样式（`pointer-events: none`、`z-index`、`translate`），停在偏开的位置、点不到；
  - 拖拽中 Delete 删掉被拖图层，松手后它又出现在放下的地方；
  - ⌘X、⇧A 也会在拖拽中执行；
  - 推测：拖数值时按 ⌘Z，下一次移动会把值写回去，撤销顺序就乱了；拖色标时，撤销如果改了色标数量，后面可能挪到另一个色标上；
  - 按住图层还没移动满 3px 时撤销如果去掉了按住的图层，再移动会拖一个已经不在画布上的图层。
- **设计师的决定（2026-10-30）**：
  1. **拖拽图层时，改画布的快捷键都不起作用。** 松手或按 Esc 之前，⌘D、Delete / Backspace、⌘X、⌘V、⇧A、⌥⇧A、⌘⇧G，代码里其他会改画布或改动单的快捷键，以及撤销和重做（61 已做，并进同一套规则）都忽略。平移和缩放视角（空格平移、⌘ 加滚轮、⇧1 等）和 Esc 照常可用。
  2. **从按住起就算。** 鼠标在画布上按住图层、还没移动满 3px 时，也按拖拽处理，套用上一条的规则，从 pointerdown 一直到松开、Esc 或 pointercancel。Esc 取消拖拽仍按现在的 3px 判断，不改。
  3. **其他"拖"的操作也一样。** 规则统一为"鼠标按着时不改历史"：拖数值图标、拖渐变色标、用 T / F 工具画图层，鼠标没松开时，撤销、重做和改画布的快捷键都忽略。这些操作的 Esc 行为保持现状。
- 没有决定到的：既不改画布也不动视角的键（⌘C、切换工具、切换模式、开关面板等），逐个判断：按着时执行会带走拖拽的临时状态、或打断弄坏这次拖动的，一并忽略；确实无害的照常执行。判断和理由写在 Comments 里。

## Comments

**实现记录（2026-10-30）**

*做了什么*

1. **"按着"记在哪里**（新模块 `pointer-held.ts`）：`holdPointer(pointerId)` 在按下时登记一次按着，返回提前结束它的函数；`pointerHeld()` 回答现在有没有按着。登记的那个指针松开（`pointerup`）或被取消（`pointercancel`）时，窗口上先于页面上任何处理的监听把它去掉，所以组件漏了结束也不会一直按着。四处登记：
   - `CanvasView` 在画布上按住能挪动的图层时（`press`，从 pointerdown 起，没移动满 3px 也算），Esc 取消拖拽时提前结束（`endPress`）；按住未满 3px 时 Esc 照旧选父图层，按着不结束（这时再移动仍会拖起按住的图层，撤销去掉它的问题正是决定 2 要防的）。
   - `CanvasView` 用 T / F 画图层时（`drawing`），到松开为止；Esc 照旧放下工具，松开时不新建。
   - `Properties` 的数值图标（`Scrub`）和渐变色标（`GradientStops`）按下时，到松开为止。
   ticket 61 的 `onDragging` 和 Shell 里的 `dragging` ref 去掉，并进这个模块。
2. **按着时一个键怎么处理**（`canvas-keys.ts` 的 `heldKey`）：`passes` 照常；`text` 在能打字的输入框里照常打字，但输入框和编辑层都不拿它做别的；`ignored` 谁也不处理，连浏览器的默认动作也拦下。见下面的分类表。`canvasKey` 多了 `held`：按着时只有 `passes` 的键起作用（T / F / V 不换工具）；`historyKey` 的 `dragging` 改名 `held`，按着时撤销、重做返回 `ignored`。
3. **接线**（`Shell.tsx`）：撤销那个窗口级监听先按 `historyKey`，不是撤销键时，按着就按 `heldKey` 拦：`ignored` 调 `preventDefault` 和 `stopPropagation`，`text` 只 `stopPropagation`（输入框、色标、按钮上的处理都收不到，打字的默认动作照常）。另一个按选中图层动作的窗口级监听（⌘D、Delete 等）按着时直接返回，因为 `stopPropagation` 挡不住同在窗口上的监听。文字图层里打字时键盘事件在视图自己的文档里，不经过 Shell，`beginTyping` 里另外拦下按着时的回车。
4. **ADR**：新开 ADR 0012"鼠标按着时，键不改画布、改动单和历史"，ADR 0011"拖拽"一条里 61 那一行改成指向 0012。理由：规则已不只是拖拽、也不只关于旁边的视图让位（0011 的主题），涉及四种操作和所有快捷键，又有真实的取舍（在键上拦还是在编辑器上拦、放行名单还是拦截名单、浏览器快捷键拦不拦），值得单独一条。GLOSSARY 没有加词："按着"是普通说法，没有和已有词冲突，也不是设计师要用的新概念。

*按 code-review 修正（2026-10-30）*

- Spec：原来的做法除 Esc、空格、⇧1、修饰键外一律忽略，连浏览器自己的快捷键（⌘R、⌘F、⌘L、网页缩放、Tab）也拦，超出了"确实无害的照常执行"。改为带 ⌘ 的键只拦编辑层用的字母（⌘C、⌘X、⌘V、⌘D、⌘⇧G、⌘Z、⌘Y，`EDITOR_COMMANDS`），其余照常；ADR 0012 记下这个取舍。另外发现 Tab 在输入框里归为 `text` 时会把焦点移出输入框、提交输入的值（拖数值时焦点留在输入框里），改为忽略，并加进单测和拖数值的 e2e。e2e 补了旁边的视图、画布外的图层更多的键，以及按着时空格、⇧1、Esc 照常。实现记录补上分类表。
- Standards：`canvasKey` 里拦键那一行的注释原来只讲工具键，改成讲整条规则；`HeldKey` 的说明原来没写空格、⇧1 放行的条件，补上，并把说明挪到 `heldKey` 函数上；Shell 里的 `kept` 改名 `whileHeld`；`pointer-held.ts` 的 `listen(on)` 拆成 `watchLifts` 和 `stopWatching`；`CanvasView` 里两处"结束按住"并成 `endPress`。判断性意见没改的：`takesText` 和 `isEditable` 有重叠（前者是后者里能打字的那部分，分开写更直白）；"按着"在五处检查（两个 Shell 监听、`canvasKey`、`historyKey`、打字的回车），因为 `stopPropagation` 挡不住同在窗口上的监听、打字在视图自己的文档里，ADR 0012 Consequences 写了加新监听时要自己检查。

*风险和没做的*

- T 画文字图层和 F 画 Frame 走同一段代码（`drawing`），e2e 只测了 F。
- 按住不能挪动的图层（例如最外层的页面）不算按着：它不会变成拖拽，按键照常。按住时按着 ⇧（加选）也不算。
- 按住未满 3px 时按 Esc 选父图层，按着不结束，直到松手；决定 2 里的"Esc"按"Esc 取消拖拽"理解。
- 按着靠主窗口收到 `pointerup` / `pointercancel` 结束。四种操作都捕获了指针（`setPointerCapture`），松开总会到主窗口；没有加 `lostpointercapture`，因为拖数值时锁定指针（`requestPointerLock`）可能触发它，提前结束按着。万一某次松开没有到主窗口，下一次在主窗口松开指针时会一并结束。
- 加新的带 ⌘ 的编辑层快捷键时，要加进 `EDITOR_COMMANDS`，否则按着时它不会被拦下默认动作，元素上的处理也照常收到；窗口上新加的键盘监听要自己检查 `pointerHeld()`（ADR 0012）。
- 拖切换按钮（停靠的角落）不在范围里：它不改画布和历史，按着时快捷键照常。

**最后 review 修正（2026-10-30）**

*改了什么*

1. **按着时只拦编辑层真正绑定的组合**（820e0db、0f84066）。原来 `heldKey` 按 `EDITOR_COMMANDS` 只比对字母、不看修饰键，⌘G（查找下一个）、Mac 上的 ⌘Y（历史记录）、⌘⇧C（检查元素）、⌘⇧V（粘贴为纯文本）这些浏览器快捷键按着时也被拦了，不符合"浏览器自己的快捷键照常"。现在 `canvas-keys.ts` 有一个 `editorCommand(event)`，按字母和修饰键整个组合回答这个键是不是编辑层的命令：⌘C、⌘X、⌘V、⌘D、⌘⇧G、⌘Z、⇧⌘Z、Ctrl+Y，⌘ 和 Ctrl 在任何系统上都一样，带 ⌥ 的都不是。`heldKey`、`historyKey` 和 Shell 里执行 ⌘C / ⌘X / ⌘V / ⌘D / ⌘⇧G 的监听都用它，所以"按着时拦哪些"和"编辑层实际执行哪些"是同一个判断，以后加新的 ⌘ 快捷键只改一处。`EDITOR_COMMANDS` 删掉了，上面"风险和没做的"里"要加进 `EDITOR_COMMANDS`"改为加进 `editorCommand`。
   - 核对 ADR 0012 的名单：原来写的 ⌘Y 不是编辑层的键（Mac 上的重做是 ⇧⌘Z），以代码实际绑定为准改成 ⌘Z、⇧⌘Z、Ctrl+Y，并写明按整个组合比对。
   - 实际绑定不分平台：Mac 上 Ctrl+Y 也是重做、Ctrl+C 也是复制（改动前就是这样）。按"Ctrl+Y 只在非 Mac 上用"去改会改变设计师按键的结果，所以没有加平台判断，只在 ADR 里写清楚。
2. **Shell 里按着时拦键的闸门单独一个监听**（3114253）。原来挂在 ⌘Z 的窗口监听里，那个监听在播放中或还没有 editor 时（`!editor`）直接返回，闸门也一起跳过。现在是 Shell 里第一个窗口级键盘监听，只做一件事：按着时按 `heldKey` 拦（`ignored` 调 `preventDefault` 和 `stopPropagation`，`text` 只 `stopPropagation`），不看 editor、不看播放。
   - `!editor` 时这样是对的：规则只关于指针（ADR 0012），和有没有 editor 无关。实际上没有 editor 时（画布还没冻结出来）没有图层可按、Design 面板没有数值图标，`pointerHeld()` 不会为真，所以行为和改动前一样；放在独立监听里只是不再依赖这一点。播放中 `onPointerDown` 直接返回，也不会按着。
   - 窗口捕获阶段的几个监听注册顺序不影响结果：同一目标上 `stopPropagation` 本来就挡不住其他窗口监听，它们各自检查 `pointerHeld()`；也没有监听读 `defaultPrevented`。
3. **T 画文字图层的 e2e**（9bbb772）：`create.spec.ts` 新加一条，和 F 那条对称。先删标题（可撤销），删 Get started 再撤销（可重做）；按 T 在段落下面拖、不松手，依次按 ⌘Z、⇧⌘Z、Delete、Enter、F、V，每次检查标题仍删掉、按钮还在、hero 的结构不变、改动 1 条、工具仍是 Text；松手后输入 Hello there 回车，改动 2 条。⌘Z 先撤回输入的字（变回占位的 Text，打字本身是单独一步，这是原有行为），再 ⌘Z 撤回新建的文字，再 ⌘Z 撤回删标题。临时让 `pointerHeld()` 恒为 false 跑过，这条失败，改回后通过。
4. Shell 里 `editorCommand` 的结果叫 `shortcut`，和"按了 ⌘ 或 Ctrl"的 `command` 分开（按 review 修正）。

*没改、记下的*

- 预览模式的改动列表（`ChangeList.tsx`）自己绑了撤销：那里 ⌘Y 是撤销、Ctrl+⇧Y 是重做，和编辑层不一样。它是编辑模式之外的弹层，一按外面就关，按着画布时不会开着，所以没有并进 `editorCommand`；要统一需要设计师决定。
