# 62: 鼠标按着时快捷键不改画布和历史

**What to build:** 鼠标按着、还没松开时，会改画布、改动单或撤销历史的快捷键都不起作用：按下去什么也不发生，改动单、画布、Layers 都不变。"按着"包括：在画布上按住图层（从按下起，还没移动满 3px 也算，一直到松手、按 Esc 取消拖拽或指针被取消）、在数值图标上拖、拖渐变色标、用 T / F 工具画图层。撤销和重做（ticket 61 已经在拖拽图层时拦下）并进同一条规则。平移和缩放视角的键（空格平移、⇧1 看全部视图，⌘ 加滚轮本来就不是键）、Esc、修饰键本身（拖拽中 ⌘ 关吸附、⌥ 量距离或放下时复制、拖数值时 ⇧ 一次 10）照常可用。输入框里还有没提交的文字时，⌘Z 仍归输入框自己（同 61）。不在按着时，所有快捷键的行为不变。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（拖拽中的让位见 ADR 0011，画布外的图层见 ADR 0009，本条规则写进 ADR 0012）。

**Blocked by:** None

**Status:** ready-for-agent

- [ ] 在桌面视图、旁边的视图里拖图层，或拖画布外的图层，松手前按 ⌘D、Delete、Backspace、⌘X、⌘V、⇧A、⌥⇧A、⌘⇧G、方向键、⌘Z、⇧⌘Z，改动单、画布、Layers 都不变；松手后没有残留的拖拽样式，这次拖拽照常放下，一次 ⌘Z 撤回
- [ ] 在画布上按住图层、还没移动满 3px 时，同样适用；松手后（没有拖动）一切照常
- [ ] 拖拽中按 ⌘D 不再出现带着拖拽行内样式（`pointer-events: none`、`z-index`、`translate`）的副本；拖拽中按 Delete 被拖的图层不再先删掉、松手后又出现
- [ ] 拖数值图标、拖渐变色标、用 T / F 画图层时，鼠标没松开就按 ⌘Z、⇧⌘Z，历史和画面都不变；松开后撤销顺序正确（一次 ⌘Z 撤回这次拖动或新建的图层，再一次撤回之前的改动）
- [ ] 拖渐变色标时按 Delete、方向键，色标不被删掉、不被挪动
- [ ] 按着时空格平移、⇧1、Esc 照常；拖拽图层时 Esc 照旧取消拖拽，T / F 画图层时 Esc 照旧放下工具，按住未满 3px 时 Esc 照旧选父图层
- [ ] 不在按着鼠标时，所有快捷键的行为不变
- [ ] ADR 写下这条规则（新开 ADR 0012，ADR 0011"拖拽"一条里 61 的那一行指过去）
- [ ] 全量 typecheck、单测、e2e 通过，测试数量不少于改动前

## 背景

- 来自 ticket 61。61 只拦下了拖拽图层时的撤销和重做，在它的 Comments 里实测和列出了其他快捷键、其他"拖"的问题：
  - 拖拽中 ⌘D 复制出的副本一直带着拖拽用的行内样式（`pointer-events: none`、`z-index`、`translate`），停在偏开的位置、点不到；
  - 拖拽中 Delete 删掉被拖图层，松手后它又出现在放下的地方；
  - ⌘X、⇧A 也会在拖拽中执行；
  - 推测：拖数值时按 ⌘Z，下一次移动会把值写回去，撤销顺序就乱了；拖色标时，撤销如果改了色标数量，后面可能挪到另一个色标上；
  - 按住图层还没移动满 3px 时撤销如果去掉了按住的图层，再移动会拖一个已经不在画布上的图层。
- **设计师的决定（2026-10-30）**：
  1. **拖拽图层时，改画布的快捷键都不起作用。** 松手或按 Esc 之前，⌘D、Delete / Backspace、⌘X、⌘V、⇧A、⌥⇧A、⌘⇧G，代码里其他会改画布或改动单的快捷键，以及撤销和重做（61 已做，并进同一套规则）都忽略。平移和缩放视角（空格平移、⌘ 加滚轮、⇧1 等）和 Esc 照常可用。
  2. **从按住起就算。** 鼠标在画布上按住图层、还没移动满 3px 时，也按拖拽处理，套用上一条的规则，从 pointerdown 一直到松开、Esc 或 pointercancel。Esc 取消拖拽仍按现在的 3px 判断，不改。
  3. **其他"拖"的操作也一样。** 规则统一为"鼠标按着时不改历史"：拖数值图标、拖渐变色标、用 T / F 工具画图层，鼠标没松开时，撤销、重做和改画布的快捷键都忽略。这些操作的 Esc 行为保持现状。
- 没有决定到的：既不改画布也不动视角的键（⌘C、切换工具、切换模式、开关面板等），逐个判断：按着时执行会带走拖拽的临时状态、或打断弄坏这次拖动的，一并忽略；确实无害的照常执行。判断和理由写在 Comments 里。
