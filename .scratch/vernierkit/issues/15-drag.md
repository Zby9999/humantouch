# 15: 拖拽：重排、换容器、自由定位

**What to build:** 设计师可以在画布上拖动图层：在 Stack 里调整顺序（其他图层让位，显示插入指示线）；拖进另一个 Stack 插入到落点位置；拖到 Frame 的空白处成为自由定位，停在松手位置。拖动过程只做位移，松手才改结构。

参考本功能的 spec.md（同目录上一级），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策。

## Comments

**交接（2026-10-23，开工前请读，流程见 21 的交接）**

- **这是第一种结构类改动，风险最高。** 如果做到一半发现比预期大，停在 21、10 完成的地方，先向设计师汇报再决定，不要硬塞进这一轮。必要时可拆成"Stack 内换序"和"换容器 / 自由定位"两步。
- **拖动过程中只做位移（transform），松手才改结构**（规格要求，为了流畅）。帧率在 22 正式测量。
- **改动单要扩展。** 目前 `Change.kind` 只有 `"style"`，合并按"图层 id + 属性"进行。移动要有自己的种类（换顺序、换容器、自由定位），并定好合并规则：同一图层移动多次只记从最初位置到最终位置，移回原处就删掉。目标容器用它的位置、使用链和页面上下文描述，位置用"第几个"或 X / Y。
- **撤销（21）要从一开始覆盖移动。**
- **改动预览：结构类的预览是 27 的事。** 这一轮里，结构类改动在 `change-preview.ts` 的 `canPreview` 中要返回"显示不了"。这样它们计入 "N changes show once applied"，离开编辑模式时照旧淡出（`Shell.tsx` 的 `changed` 依赖它）。
- **核对（29）：** `check.ts` 现在只比较属性值，结构类改动要明确返回 "unchecked"（附原因），不能误报 "not shown"。
- **图层树要重建。** 图层树在画布出现时只建一次（`Shell.tsx` 的 `onCanvas`），`Layer` 里存着元素引用和实例分组。松手改了结构后要重建，并按 `data-vk-layer` 找回选中的图层。图层身份 `data-vk-layer` 在画布上随元素移动，能撑过保存与恢复（04）。
- **被移动的元素保留原来的源码标记和使用链**，正好用来在改动说明里写"从哪里来"；新位置要另外描述。
- **混排中的裸文字没有自己的元素**（03 的决定）。移动它时，画布上要给它包一层元素，改动说明写明由 Agent 包一层 `<span>`。
- **循环渲染的实例**（例如一组卡片中的一张）在同一使用处内换顺序，落地时其实是改数据的顺序。规格只对删除、复制写了"数据改动"，换顺序怎么处理需要先决定。
- **冻结时钉住的元素**（见 10 的交接）被拖成自由定位时，要分清钉住的值和设计师拖出的新位置。
- Skill 补充：自由定位的图层要把父容器设为定位参照（`position: relative`）。

**实现记录（2026-10-23）**

- 改动单（`changeset.ts`）：`Change.kind` 多了 `"move"`，属性名记为 `move`（`MOVE`），同一图层的移动只有一条，`before` / `after` 是 `Place`：所在容器（画布上的图层 id 和给 Agent 的 `Target`）、在容器图层中的第几个（`nth`）、在容器子节点中的位置（`slot`，用来在画布上放回去，不算元素之间的空白）、自由定位时的 `left` / `top`（`absolute`）。移回原处就删掉。另有 `data`（循环渲染的实例被移动，是数据改动）和 `wrap`（混排裸文字被包了一层 `<span>`）。
- 编辑命令（`edits.ts`）：`move(layer, to)`、`canMove`、`canDrop`、`tree()`。目标是 Stack 中的第几个，或 Frame 中的 X / Y。能放入的容器：Stack 或 Frame，不是图层自己或其内部，不是锁定图层（锁定图层可以整体移动，但不能放入其内部），并且容器的实例数与图层所在容器的实例数相同（图层在每个实例里都有容器可去；例如卡片标题不能放进另一个使用处的单张卡片）。Grid 不是目标（留给 18）。
  - 移动在画布上做结构改动（`moves.ts` 的 `relocate`，只靠图层 id 和 `Place`，编辑中的画布与保存的本轮共用）：每个容器实例里同一位置的那个元素一起移动；循环渲染的实例共用一个容器，只移动被拖的那一个。
  - 变为自由定位：图层写上 `position: absolute`、`left` / `top`、当前的宽高（保持原来的大小），容器若未定位则在画布上设为 `position: relative`（`data-vk-reference`）；离开或撤销时，容器里不再有自由定位的图层就恢复。原本就是自由定位的图层放进 Stack 时写 `position: static`。已经是自由定位、在自己的容器里拖动，只是改 X / Y（样式改动，可预览、可核对）。
  - 混排的裸文字先在每个实例里包一层 `<span>`（带同一个图层 id），再移动；改动说明写明由 Agent 包一层。
  - 移动后图层树重建（`buildLayerTree`），`LayerTree.layerOf` 按元素（或文字节点）找回图层；`Shell` 据此找回选中、图层树找回折叠状态，画布的悬停若指向旧树里的图层则忽略。
  - 撤销（21）：移动是一步，撤销 / 重做按 `Place` 来回移动；改动列表的逐条撤销在编辑模式中走 `editor.revert`，在预览模式中走 `revertSaved` 移回原处。
- 拖动（`drag.ts`、`CanvasView.tsx`）：在可移动的图层上按下并移动 3px 以上开始拖动（没有选中时按下选中的是最外层，和 Figma 一样）。拖动中只用 `translate` 位移：被拖的图层跟着指针（`pointer-events: none`，命中测试跳过它），让位的图层带 150ms 过渡；容器取指针下最深的、能放入的 Stack 或 Frame，同级的 Stack 只有指针在它中间一半时才进入，靠边时仍算在外层 Stack 里重排。Stack 里按各图层主轴中点算插入位置，画插入线并高亮目标容器；Frame 里按松手时的位置成为自由定位。松手才改结构；Esc 取消，全部复原。裸文字没有元素可移，拖动时画一个跟随的框。
- 改动说明（`change-notes.ts`、`design-values.ts`）：种类为 Reorder / Move / Absolute；设计意图写从第几个到第几个、从哪个容器到哪个容器（名称、开始标签、源码位置或页面位置）、自由定位的 X / Y 并要求把容器设为定位参照；数据改动、包一层 `<span>` 各有一行；参考样式为空时写 "none: only its place changes"；移动不写 "Currently set by"。改动列表显示如 "Reorder · Button  3rd → 2nd"。
- Skill：说明三种移动；移动 JSX 本身，数据改动改数据；自由定位的图层用 `position: absolute` 和给出的 `left` / `top`，容器未定位时设为 `position: relative`。
- 改动预览与核对：`canPreview` 对移动返回 false（计入 "N changes show once applied"，离开编辑模式时照旧淡出）；`done` 对移动返回 "unchecked"（"only style changes are checked on the page so far, not moves"），待 27。
- 循环渲染实例换顺序的决定：按数据改动处理（与规格中删除、复制实例的"数据改动"一致），改动说明请 Agent 改数据的顺序，数据来自代码之外时在报告中说明。
- 测试：辅接缝 1 `edits.browser.test.ts`（Stack 内换序、移回原处不算改动、撤销 / 重做、换 Stack、放入 Frame 成为自由定位并能撤销、保存的本轮上撤回移动、裸文字包一层、循环实例的数据改动、能否放入）；命令行接缝（三种移动的说法、数据改动与包一层）；主接缝新增 `drag.spec.ts`（重排时其他图层让位与插入线、⌘Z、放进另一个 Stack 且不进入锁定图层、锁定图层整体拖动、拖到 Frame 空白处成为自由定位、Esc 取消、移动在预览模式中计入"落地后才能看到"并出现在改动列表），`claim.spec.ts` 的移动改动说明和 `done` 不核对移动。

**已知限制**

- 只拖动一个图层；多选时拖动的是按下的那个。吸附、参考线、方向键微移是 16。
- 同一容器里先后移动了几个图层后，在改动列表里单独撤回较早的一个时，按记下的位置放回，可能与其他已移动图层的相对顺序有出入（按时间顺序 ⌘Z 撤销没有这个问题）。
- 图层被放进 Frame 后宽高固定为拖动前的大小；原来是 Fill / Hug 的，落地时 Agent 可能需要按设计判断。
- 注入到页面、React 之外的元素没有使用链，读作外层组件的实例（只影响测试里手工加的 Frame）。
