# 38: 断点对齐项目、播放与核对

**What to build:** 视图的宽度范围对齐项目已有的断点（从 Tailwind 主题与 CSS 媒体查询读取，读不到时按视图宽度划分），改动说明写出对应的项目断点（例如 Tailwind 的 md:）。播放时画布按窗口宽度显示，断点改动在对应宽度下可见（ADR 0010）。`done` 在该断点宽度下的真实页面上核对断点改动（例如在对应宽度的隐藏 iframe 中加载同一页面），读不到时结果为没能核对。

参考本功能的 spec.md（同目录上一级），目标与指标以 docs/goals.md 为准，用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（视图与断点见 ADR 0008，挪出画布的图层见 ADR 0009）。

**Blocked by:** 37, 50

## Comments

**实现记录（2026-10-28）**

- 读项目断点：本机服务新增 `GET /breakpoints`（`project-breakpoints.ts`），项目依赖里有 tailwindcss 时读 Tailwind 主题。v4 先读 `tailwindcss/theme.css` 的默认 `--breakpoint-*`，再按路径顺序读项目 CSS 中 `@theme` 的声明（支持 `initial` 去掉某个或全部）；v3 用项目自己的 `tailwindcss/loadConfig` 与 `resolveConfig` 解析 `theme.screens`（含 extend 与默认值），只取"从某宽度起"的 screen。没有 Tailwind 时，编辑层读页面样式表中按宽度的媒体查询（`readMediaBreakpoints`），每个宽度用最先读到的那条查询命名。都读不到时仍按视图宽度划分。只看项目 package.json 的依赖，因为 pnpm 的 NODE_PATH 能从任何工作区目录找到 tailwindcss。
- 视图范围（2026-10-29 改为 Framer 式，按项目断点取整，见 Comments）：项目断点把宽度切成若干段；桌面视图所在的段及更宽的段归桌面视图，落在其中或与桌面同宽、更宽的视图当作桌面视图（改动作用于所有宽度），与 ADR 0008"与桌面视图同宽的视图就是桌面视图"同理。其他视图代表自己宽度所在的段（同段的视图共享），并向上延伸到下一个更宽视图所在段的下沿，最宽的非桌面视图延伸到桌面段的下沿；最窄的视图向下延伸到 0。范围因此随视图集合与桌面宽度变化，已记下的改动不改写。默认 Tailwind 断点、桌面 1440 时，手机为 `max-md:`，平板为 `md:max-xl:`。视图标签与属性面板的断点区显示 Tailwind 写法。
- 范围漂移：面板认出、标出、重置的是"范围包含当前视图宽度"的断点改动，不再要求范围与视图的范围完全相同；在视图里改同一属性时，若已有覆盖当前宽度的断点改动且它在视图范围之内，就更新那一条（保留它的范围），不新建；超出视图范围时按拆分规则处理（见 Comments 2026-10-29）；没有时用视图的范围，并裁掉与该属性其他断点改动重叠的部分，所以不会叠出重叠的改动。重置会去掉所有覆盖当前宽度的该属性改动（一步撤销；超出视图范围的只清掉视图范围内的部分）。落在桌面区间的视图里同样认出旧的窄范围改动。读到项目断点后，旧改动的边恰好是项目断点时，补上项目写法。
- 改动说明：断点改动写出 Tailwind 写法（"The project writes these widths with Tailwind's `max-md:`"）或项目自己的媒体查询及其边界；复制改动的 Copied breakpoints 同样写出。Skill 相应更新。
- 播放：画布 iframe 宽度跟随视口（窗口）宽度，窗口缩放时跟着变，断点改动按媒体查询在对应宽度显示；停止播放后恢复冻结时的宽度。
- `done`：窗口宽度不在改动范围内时，在页面里加一个隐藏 iframe（`data-vk-check`，编辑层不在其中挂载），以范围内的宽度（下边界，或上边界减 1）加载同一页面并在其中核对，核对完移除；3 秒内加载不了则为"没能核对"。命令行等待时间相应加长到 9 秒。
- 示例 `next-app-css-modules` 的 `page.module.css` 加了两条桌面优先的媒体查询（767px、1023px），作为纯 CSS 断点。

**修复记录（2026-10-29）**

- 读纯 CSS 断点（`readMediaBreakpoints`）只看项目自己的样式表，排除来自 `node_modules` 的依赖样式表与编辑层自己的样式表（a095c4d）；spec.md 的播放描述改为画布按窗口宽度显示、断点改动在对应宽度显示（0e6a0e0）。

**用户决定（2026-10-29）：视图范围改为 Framer 式，按项目断点取整**

- 原因：严格按项目断点区间时，默认 Tailwind 断点（sm 640、md 768、lg 1024、xl 1280、2xl 1536）下手机 390、平板 768 只代表 [0, 640) 与 [768, 1024)，640–767 和 1024–1279 没有视图代表，那些宽度只拿到桌面改动，画布上看不出来。
- 新规则：没有视图的段归它下面最近的视图。手机 390、平板 768、桌面 1440 时，手机是 [0, 768)（`max-md:`），平板是 [768, 1280)（`md:max-xl:`）；桌面窗口为 1200 时，平板是 [768, 1024)（`md:max-lg:`）。没有项目断点时按视图宽度划分的退路不变。已记下的改动不改写，识别规则不变。
- 拆分规则：在视图里改一个属性时，若这里认出的该属性旧断点改动超出了视图现在的范围（例如平板上记了 768–1279 的改动，之后加了 1100 的视图，平板缩成 768–1023），旧改动只保留视图范围以外的部分（原值，一段或两段），视图范围内记新值；同一属性的断点范围仍互不重叠，一次撤销恢复原样。在视图里重置同理，只清掉视图范围内的部分。桌面视图的改动仍是基础样式。没有项目断点时同样按此拆分。
- 实现：`breakpointOf` 按新规则取范围；`edits.ts` 的 `editHere` 在旧改动超出视图范围时先用 `cutting` 把它裁成范围外的部分，再在视图范围记新值，作为一步（拖动中的后续步骤合并进来，重做时先裁）；`inherit` 对超出视图范围的改动用 `cutStep` 只清掉范围内的部分。
