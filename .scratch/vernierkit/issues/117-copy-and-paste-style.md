# 117: 复制样式、粘贴样式

**What to build:** 编辑层现在能复制、粘贴图层（⌘C、⌘X、⌘V），但不能只复制样式：⌥⌘C、⌥⌘V 现在什么都不做。设计师在 Figma 里常用 Copy properties / Paste properties，把一个图层的样子套到别的图层上。要做到：选中一个图层按 ⌥⌘C 记下它的样式，选中一个或几个图层按 ⌥⌘V，把样式套上去，画布马上变，三个视图都变。

复制哪些照 Figma 的 Copy properties：外观（填色、描边、圆角、效果、不透明度等）和文字样式（字体、字号、字重、行高、字距、文字颜色等）；不含位置、尺寸、Stack / Grid 的布局，也不含文字内容。开线时先核对 Figma 实际复制哪些，有出入的作为代定。每一项粘贴出来都是一条普通的样式改动，和在面板里一项项改一样，Agent 那边没有新东西。

参考本功能的 spec.md（同目录上一级，「属性面板」「合成与解散 Stack」里 ⌘C、⌘V 的规则），用词以 GLOSSARY.md 为准，并遵守 docs/adr/ 中的决策（ADR 0008、0012）。

**核对 Figma**

- help.figma.com「Copy and paste properties between layers」：右键 Copy/Paste as → Copy properties / Paste properties，Mac ⌥⌘C / ⌥⌘V，Windows Ctrl+Alt+C / Ctrl+Alt+V；粘贴全部属性时只套目标图层支持的属性。页面没有列出到底复制哪几项，也没说多选、变量、文字和 Frame 之间怎么对；单项复制只提到填色、描边、效果。

**做了什么**

- 新模块 `style-copy.ts`：`copyStyle` 读一个图层的样式（正在工作的视图里显示的值，和设计师选过的变量），`styleFor` 算目标图层能套哪些，`pasteStyle` 在一次 `editor.batch` 里逐项 `editor.set`，和面板一项项改走同一条路：作用于这个使用处的全部实例，平板、手机视图里只在那个断点、有断点标记；改动列表和改动说明与面板改出来的逐字一样（单测比过整条改动）。目标已经是这个值的不改；先读完再写，免得写一项读一项让页面一再重新计算样式。
- 复制的：填色、描边、圆角、不透明度、裁剪内容、投影 / 内阴影、图层模糊、背景模糊；文字图层的字体、字号、字重、行高、字距、对齐、大小写、下划线 / 删除线、文字颜色、文字投影。不复制：X / Y、尺寸和最小 / 最大、Stack / Grid 的排法（方向、间距、内边距、对齐、换行、列数、`arrangement`）、显示 / 隐藏、文字内容。
- 文字和 Frame 之间：文字颜色 ↔ 纯色填色，文字投影 ↔ 投影（只有文字画得出的：全是投影、没有扩展），选过的变量跟着换成对应那一项（填色的 `color` ↔ 文字颜色的整项）。对不上的不套。
- 键：`editorCommand` 认 ⌥⌘C / ⌥⌘V（Ctrl+Alt 一样），按打出的字符认：c / v，或 Mac ⌥ 打出的 ç / √（review 后，不再按 `event.code`，见代定 11）；带 ⇧ 的、⌥⌘ 加别的字母都不是。于是按着指针时 `heldKey` 把它们当编辑层的键拦下，什么也不做（ADR 0012）；ticket 62 那条「⌥⌘C 放行」的测试改成 ⌥⇧⌘C。Shell：单选一个图层按 ⌥⌘C 记下（只在编辑层里，不碰系统剪贴板，和 ⌘C 记的图层分开）；⌥⌘V 套到选中的图层上，一步，选中不变；焦点在输入框里时键归输入框；浏览器对这两个键的默认动作拦下。
- 文档：spec 补用户故事 65b 和「合成与解散 Stack」里 ⌥⌘C / ⌥⌘V 一条；ADR 0012 的键名单补上这两个（原来写「带 ⌥ 的都不是」）。

#### 代定的事（待设计师确认）

1. 复制的范围：外观（填色、描边、圆角、不透明度、裁剪内容、投影 / 内阴影、图层模糊、背景模糊）和文字样式（字体、字号、字重、行高、字距、对齐、大小写、下划线 / 删除线、文字颜色、文字投影）。Figma 的帮助页没列清单；照它的「只套目标支持的」。不复制显示 / 隐藏、最小 / 最大尺寸。
2. 和 Figma 的出入：Figma 粘贴会带自动布局（论坛有人说带上了间距），这里照票不带 Stack / Grid 的排法，内边距也算排法不带（Figma 的内边距是自动布局的一部分）。裁剪内容带（Figma 的 Clip content 是 Frame 的外观属性）。
3. 和 Figma 的出入：这一轮在面板里选过的设计变量粘过去还是那个变量（Figma 只粘值，官方记为功能需求）。**代码里本来就写着的变量、这一轮没选过的，不随复制带过去**，粘贴时照常按值命名，和面板里输入一个值一样：源图层写的是 `bg-brand-2`、`brand-1` 和它同值时，粘过去可能记成 `brand-1`。面板本身也不显示代码里原有的变量（只显示这一轮选过的），所以没有现成的读法可以照搬；要带上得另读源码的类名或 CSS 变量，请设计师确认要不要。目标已经是同一个值、同一个选过的变量时不算改动。
4. 多选按 ⌥⌘C：什么也不记，原来记下的保留（Figma 的做法帮助页没写；不猜从哪一个复制）。没有提示。
5. 文字和 Frame 之间：文字颜色对纯色填色（Figma 里文字的颜色就是它的填色，所以照它），渐变填色不套成文字颜色；文字投影对投影，内阴影或有扩展的投影不套到文字上。从标题复制再粘到卡片上，卡片底色会变成标题的文字颜色，和 Figma 一样，可能不是设计师要的。
6. 属性从哪里来：只取选中的那个图层自己的。选中按钮（Frame 包着它的文字）复制，拿到的是按钮的外观，不含里面文字的样式；要文字样式就选里面的文字。粘到按钮上也只套按钮能用的，文字样式不往里面的文字套。值都按正在工作的视图里显示的取（手机视图里复制就是手机的值）。
7. 粘到实例上作用于这个使用处的全部实例（和面板一样）；ticket 114 还没做，114 做了之后自动按它的规则（粘贴走的就是 `editor.set`）。锁定图层不套，没有提示；选中里有锁定图层时其他图层照套。
8. 记下的样式只在这次编辑里有效，回到预览模式或刷新后就没了（和 ⌘C 一样）；不跟着图层，图层后来改了、删了，粘贴的还是复制时的值。
9. 粘贴后选中不变；目标已经全是这些值（选过的变量也一样）时什么也不记、不算一步、不刷新选中框，也不提示。
10. 在桌面视图里粘贴是基础样式，作用于所有断点，但目标在平板、手机视图里单独改过的属性仍保留它们在断点上的值，和在桌面视图的面板里改一样（ADR 0008）。
11. 快捷键按打出的字符认（review 后）：⌥⌘ 加 c / v，或 Mac 美式布局 ⌥ 打出的 ç / √；其他字符都不算。所以 Mac Dvorak 物理 C 键上的 ⌥⌘J（浏览器控制台）不会被当成复制样式，Windows 上 AltGr（Ctrl+Alt）打出 ć（波兰语）、@（匈牙利语）也照常是打字。代价：⌥ 打出别的字符的 Mac 布局（例如德语 ⌥V）用不了 ⌥⌘V。

#### 遗留风险

1. 性能：同类比较时一次粘贴 work 约 18–21ms，面板改一项约 10ms，在目标里，但仍多出约 1 帧的一半以上（主要在下一帧的绘制）；没细查。删掉一条改动（改回原值、粘回原值、撤回）比改一条改动慢得多（约 40–60ms），这是编辑层原有的，不是粘贴的，也许值得另看。
2. 快捷键只在 Mac 的 headless Chromium 里测过（合成的按键事件）；没在 Windows、Linux 和其他键盘布局上实际按过（代定 11）。有些输入法或系统快捷键可能占用 Ctrl+Alt+C / V。
3. Figma 的行为是从帮助页和论坛推的，没有在 Figma 里实际点过：多选复制、文字和 Frame 之间的对应、复制哪几项都可能和真 Figma 不一样（代定 1、4、5）。
4. 粘贴出来的是普通样式改动，Agent 那边和改动说明没变，没有专门的 Agent 场景；真 Agent 没跑。
5. 整套 e2e 还没跑（指挥合并前跑），所以验收里「e2e 全过」没勾。
6. 「粘到实例上」不跟随的实例照 ticket 114：114 还没做，现在粘贴和面板一样作用于全部实例；114 做了以后没有专门的测试确认粘贴跟着它走。
