# 03Kind 第一版规格

> 目标与最终验收标准见 [docs/goals.md](../../docs/goals.md)；术语以 [GLOSSARY.md](../../GLOSSARY.md) 为准；相关决策见 [docs/adr/](../../docs/adr/)；延后的能力见 [roadmap](../../docs/roadmap.md)；背景调研见 [research/figma-like-web-editor-feasibility.md](../../research/figma-like-web-editor-feasibility.md)。

## Problem Statement

设计师拿到 AI 生成的网页（或团队已有的网页）后，想像在 Framer、Figma 里一样直接动手调整：把元素拖到别处、把散落的元素整理成 Stack、调间距、圆角、阴影、字号。但他们不写代码，现在只能：

- 用文字向 Agent 描述"把这个按钮往右挪一点、圆角大一点"，来回多轮、词不达意；
- 或者回到 Figma 重画一遍，再让 Agent 照着改，设计稿与真实页面永远对不上。

已有的可视化编辑工具要么绑定某个平台或某个 Agent（v0、Lovable、Cursor、Figma Make），要么只支持特定技术栈并往用户源码里注入标记（Onlook），要么只能做简单的样式微调、做不了 Framer 式的自由摆放与 Stack 重组。设计师缺少一个"装进任意现有项目、像 Framer 一样改、再交给自己正在用的 Agent 落地"的工具。

## Solution

03Kind 是一个开源、本地运行、可一行安装的编辑层。设计师把 Guide 交给自己的 Agent，Agent 运行一条安装命令，页面上就出现一个切换按钮。

- 在预览模式下，设计师照常使用页面，把它操作到想改的状态；点切换按钮进入编辑模式，当前页面被冻结成画布。
- 回到预览模式，页面就是代码现在的样子；要看改动后的样子，在编辑模式中点某个视图标签右端的全屏按钮，画布按那个视图的宽度、真实大小单独显示（ADR 0010）。
- 在编辑模式下，界面像 Framer：左边图层树、中间画布、右边属性面板。设计师可以自由拖动图层、合成或解散 Stack、新建文字和 Frame、在属性面板里精细调整，所有改动在画布上 0 延迟生效。面板调不出来的意图，可以在任意图层上写一段生成说明，给 Agent 一个工作目标。
- 画布按桌面、平板、手机三个视图并排显示，在任一视图里改，其他视图同步变化；在平板或手机视图里改的样式与布局只在该断点生效，像 Framer 一样。暂时不确定的图层可以拖到画布之外放一边，它们跨轮次保留，随时可以拖回。
- 改动随编辑自动保存进项目。设计师在对话框里对 Agent 说一句"落地我的设计改动"，Agent 通过安装时放进项目的 Skill 认领改动单、逐条写进源码，编辑层收起成按钮并用进度环显示进度；完成后页面变为真实结果，Agent 报告哪些改动无法 1:1 落地。

整个过程没有发送按钮、没有复制粘贴、没有 MCP 配置，任何能读文件、执行命令、改代码的 Agent 都能用。

## User Stories

### 安装与环境

1. As a 设计师, I want to 把一段简短的 Guide 交给我的 Agent 就完成安装, so that 我不需要理解构建配置或写任何代码。
2. As an Agent, I want to 运行一条 `init` 命令就把编辑层装进项目, so that 我不必逐个文件手工修改。
3. As an Agent, I want `init` 自动识别项目是 Vite 还是 Next.js、使用哪种包管理器, so that 安装步骤不因项目而异。
4. As an Agent, I want `init` 在自动修改配置失败时输出清晰的手动步骤, so that 我仍能完成安装而不是卡住。
5. As an Agent, I want `init` 把 Skill 放进项目、并在 AGENTS.md 里留一行指向它, so that 之后设计师一句话我就知道怎么落地改动。
6. As a 设计师, I want 改动单所在目录自动被 git 忽略, so that 我的编辑草稿不会被误提交。
7. As an Agent, I want to 运行 `doctor` 检查安装是否完整、正式构建产物里是否不含编辑层代码, so that 我能向设计师确认安装成功且不影响线上。
8. As a 开发者, I want 编辑层在正式构建中完全不存在, so that 我敢把它装进真实项目。
9. As a 设计师, I want Agent 收到 Guide 后 60 秒内、无需我介入就让页面上出现切换按钮, so that 上手成本足够低。
9a. As a 开发者, I want 安装只改动项目源码不超过 2 处（构建配置一行、挂载一行）, so that 我一眼能看懂它对项目做了什么。
10. As a 开发者, I want 编辑层只在本地开发环境出现, so that 线上用户永远看不到它。
11. As a 开发者, I want 编辑层的本机服务只接受本机、且带口令的请求, so that 我浏览的其他网站无法借机篡改项目文件。
12. As a 设计师, I want 编辑层不需要账号、不联网、不收集使用数据, so that 我可以放心在任何项目里使用。
12a. As an Agent, I want to 运行一条 `remove` 命令就把 03Kind 完整卸载, 执行后 git diff 为空, so that 试用它没有任何风险。

### 预览模式与切换按钮

13. As a 设计师, I want 预览模式下页面上只有一个小小的切换按钮, so that 它不干扰我正常使用页面。
14. As a 设计师, I want to 把切换按钮拖到任意角落, so that 它不挡住我要看的内容。
15. As a 设计师, I want to 用快捷键切换预览模式和编辑模式, so that 我不必每次去找按钮。
16. As a 设计师, I want 切换按钮上用角标显示还没落地的改动数量, so that 我知道 Agent 还有多少事没做。
17. As a 设计师, I want to 点开角标看到改动列表并逐条撤销, so that 我能在交给 Agent 前清理不想要的改动。
18. As a 设计师, I want 改动列表里有"Discard all"并要求二次确认, so that 我能放弃这一轮、重新冻结画布，又不会误操作。
19. As a 设计师, I want 在预览模式下自由点击、跳转页面而不丢失本轮改动, so that 我可以随时查看页面其他部分。

### 冻结画布

20. As a 设计师, I want 进入编辑模式时当前页面状态（包括打开的弹窗）被原样冻结成画布, so that 我能编辑任何一个页面状态。
21. As a 设计师, I want 进入编辑模式几乎是瞬间完成的, so that 来回切换不会打断我的节奏。
22. As a 设计师, I want 画布上的样子和真实页面完全一致（字体、固定定位、样式规则）, so that 我看到的就是真实效果。
23. As a 设计师, I want 一轮里来回切换时始终回到同一张画布, so that 我在预览模式里的跳转不会让改动错位。
24. As a 设计师, I want 刷新浏览器后画布和改动原样恢复, so that 误刷新不会让我白干。
25. As a 设计师, I want 冻结时页面上正在播放的动画直接停在结束状态, so that 画布不会卡在动画中间的半截样子。
26. As a 设计师, I want 视频、图表、地图等无法复制的内容在画布上显示为静态画面并可整体操作, so that 页面不会出现空洞。
27. As a 设计师, I want 嵌入的其他网站显示为带名称的灰色占位框, so that 我知道那里有东西、也能挪动它。

### 编辑模式的界面与画布操作

28. As a 设计师, I want 编辑模式的布局是左图层树、中画布、右属性面板, so that 我能用 Framer、Figma 的习惯工作。
29. As a 设计师, I want 每个视图按它自己的宽度完整显示，整个工作区可缩放、平移, so that 面板不会挤压页面导致布局变形。
30. As a 设计师, I want 空格加拖动平移、⌘ 加滚轮或双指捏合缩放、⇧1 缩放到适合窗口, so that 画布操作和 Figma 一致。
31. As a 设计师, I want 编辑层界面仿 Figma 风格并跟随系统浅色、深色模式, so that 它看起来熟悉又不抢页面的视觉。
32. As a 设计师, I want 编辑层的样式完全不受页面影响、也不影响页面, so that 两者互不串味。

### 视图与断点

32a. As a 设计师, I want 进入编辑模式后桌面、平板、手机三个视图并排显示, so that 我改一处时立刻看到其他宽度有没有被挤坏。
32b. As a 设计师, I want 在任一视图里选中、编辑，其他视图同步高亮和变化, so that 三个视图始终是同一个页面。
32c. As a 设计师, I want to 添加自定义宽度的视图或删掉不需要的视图, so that 我能检查项目特有的宽度。
32d. As a 设计师, I want 三个视图都保留冻结时的页面状态（例如打开的弹窗）, so that 我在每个宽度下看到的是同一个场景。
32e. As a 设计师, I want 视图标签的提示里说明它只反映 CSS 响应式, so that 我知道靠脚本判断宽度的变化不会出现在这里。
32f. As a 设计师, I want 在平板或手机视图里改的样式与布局只在那个断点生效, so that 我能单独调整小屏的细节而不影响桌面。
32g. As a 设计师, I want 在桌面视图里改的属性作用于所有断点，除非某个断点已经单独改过, so that 断点之间的继承和 Framer 一样可预期。
32h. As a 设计师, I want 属性面板标出当前断点单独改过的属性，并能一键重置为继承, so that 我清楚哪些值是这个断点特有的。
32i. As a 设计师, I want to 在某个断点隐藏一个图层, so that 小屏上不需要的内容可以去掉，而结构仍然只有一份。
32j. As a 设计师, I want 换容器、合成或解散 Stack、新建、删除、复制在任何视图里做都作用于所有视图, so that 页面结构不会在不同宽度下分裂。
32k. As an Agent, I want 改动说明写明每条改动的断点（宽度范围）及其对应的项目断点, so that 我能用项目已有的断点写法落地。
32l. As an Agent, I want `done` 在该断点宽度下的真实页面上核对断点改动, so that 小屏上的修改也有可信的 ✓。

### 画布外的图层

32m. As a 设计师, I want to 把图层从画布拖到画布之外的空白处放一边, so that 我能先把不确定的元素拿出来，想清楚再放回。
32n. As a 设计师, I want 拖出画布的图层在落地、刷新、重新冻结后都还在, so that 我放一边的东西不会随一轮结束消失。
32o. As a 设计师, I want 画布外的图层保持拖出时的样子，即使它原来的样式之后已不存在, so that 它看起来始终可靠。
32p. As a 设计师, I want to 把画布外的图层拖回任一视图中的任意位置, so that 我能把它放回原处或新的地方。
32q. As a 设计师, I want to 在画布外照常编辑这些图层、却不产生改动, so that 我随手试几下不会给 Agent 制造无用的工作。
32r. As a 设计师, I want 画布外的图层在图层树中与画布并列、不另起名字, so that 用法和 Framer 一致。
32s. As a 设计师, I want to 删除画布外不再需要的图层, so that 工作区保持整洁。
32t. As an Agent, I want 拖出画布在改动说明中写成删除，拖回写成插入并附上原来的源码片段与外观, so that 即使原代码已删掉，我也能把它原样放回。

### 图层与选中

33. As a 设计师, I want 图层树如实显示页面结构, so that 我清楚自己选中、拖动的是哪一层。
34. As a 设计师, I want 图层名自动取组件名、文字内容或元素的用途（按钮、链接、输入框等）, so that 我不用猜每一层是什么。
35. As a 设计师, I want 单击选中最外层、双击逐层深入、⌘ 加单击直接选中最深处、Esc 回到上一层, so that 选中方式和 Figma 一致。
36. As a 设计师, I want to 多选图层并统一修改, 数值不同的属性显示为 Mixed, so that 我能批量调整。
37. As a 设计师, I want 页面里的 Flex 容器显示为 Stack、Grid 容器显示为 Grid、普通从上到下排列的区域也显示为纵向 Stack, so that 我只需要理解 Stack、Grid、自由定位三种排版。
38. As a 设计师, I want 段落里的加粗、链接等片段算作同一个文字图层, so that 文字不会被拆得过碎。
39. As a 设计师, I want 普通图层、实例、锁定图层的选中框颜色不同（蓝、紫、灰加锁形图标）, so that 我一眼知道能对它做什么。
40. As a 设计师, I want 第三方库组件只能整体选中、移动、调整外部尺寸，不能进入内部, so that 我不会做出 Agent 无法落地的改动。
41. As a 设计师, I want 按住 ⌥ 悬停时显示到其他图层的距离, so that 我能精确对齐。

### 拖拽与布局

42. As a 设计师, I want to 在 Stack 里拖动图层调整顺序、其他图层自动让位, so that 重排像 Framer 一样自然。
43. As a 设计师, I want to 把图层拖进另一个 Stack 并插入到落点位置, so that 我能自由重组结构。
44. As a 设计师, I want to 把图层拖到 Frame 的空白处、成为自由定位, so that 我能随意摆放元素。
45. As a 设计师, I want 拖动时吸附到兄弟图层和父容器的边缘、中线以及"等间距"位置，并显示参考线, so that 摆放又快又准。
46. As a 设计师, I want 按住 ⌘ 暂时关闭吸附, so that 我能做吸附之外的微调。
47. As a 设计师, I want 拖动全程流畅（60fps）, so that 手感像原生设计工具。
48. As a 设计师, I want to 用方向键微移 1px、加 ⇧ 微移 10px, so that 我能做像素级调整。
49. As a 设计师, I want to 用 ⌘D、⌥ 加拖动或 ⌘C ⌘V 复制图层，用 ⌘X ⌘V 把图层剪切到别处, so that 我能快速复用已有元素。
50. As a 设计师, I want to 选中几个自由定位的图层按 ⇧A 合成 Stack，并自动推断方向、间距、内边距和对齐, so that 合成后画面几乎不跳动。
51. As a 设计师, I want to 解散 Stack 后子图层变成自由定位并停在原位、原 Stack 变成普通 Frame, so that 我能接着自由拖动它们。
52. As a 设计师, I want 页面原有的 Grid 可以改列数和行列间距、在格子之间拖动换序, so that 已有的网格布局也能调整。
52a. As a 设计师, I want to 拖选中框四角和四边的控制点直接改图层尺寸：拖角改宽高，拖边改一个方向，按住 ⇧ 保持比例，按住 ⌥ 从中心改, so that 改尺寸像在 Figma 里一样直接，不用回到属性面板输数字。
52b. As a 设计师, I want 拖过的方向变成 Fixed、属性面板随之显示，自由定位的图层拖左边或上边时 X / Y 跟着变而对边不动，拖到最小、最大尺寸时停在边界上, so that 拖出来的结果就是我在面板里会设的值。
52c. As a 设计师, I want 文字图层拖宽度后变成固定宽度、高度随文字，锁定图层也能这样改外部尺寸, so that 文字换行和第三方组件的大小也能直接拖出来。
52d. As a 设计师, I want 拖控制点时吸附到兄弟图层和容器的边缘、中线并显示参考线，旁边显示 W × H，按住 ⌘ 暂时不吸附, so that 尺寸又快又准。
52e. As a 设计师, I want 在平板、手机视图里拖控制点只在该断点生效，一次拖拽是一步撤销，按 Esc 回到按下前, so that 改尺寸和改其他属性一样可以放心试。

### 属性面板

53. As a 设计师, I want 属性面板只用设计语言（Hug / Fill / Fixed、间距、内边距、对齐）, so that 我不需要懂 CSS。
54. As a 设计师, I want to 调整自由定位图层相对父容器的 X / Y, so that 我能精确放置它。
55. As a 设计师, I want to 为宽、高分别选择 Fixed / Hug / Fill 并设置最小、最大尺寸, so that 我能表达元素如何随内容和容器变化。
56. As a 设计师, I want to 调整 Stack 的方向、间距、四边内边距、九宫格对齐、均匀分布和换行, so that 我能完整控制自动排列。
57. As a 设计师, I want to 设置纯色、线性渐变和径向渐变填充（多个色标、可调角度）, so that 我能做出常见的填充效果。
58. As a 设计师, I want to 设置描边的颜色、粗细、实线或虚线以及分边描边, so that 我能精细控制边框。
59. As a 设计师, I want to 设置统一圆角或分角圆角, so that 我能做出任意圆角组合。
60. As a 设计师, I want to 添加多层投影、内阴影、图层模糊和背景模糊, so that 我能做出层次和玻璃质感。
61. As a 设计师, I want to 调整字体（项目已加载的）、字号、字重、行高、字距、对齐、颜色、大小写、下划线和删除线, so that 我能完整控制文字排版。
62. As a 设计师, I want to 调整透明度、显示或隐藏图层、裁剪内容, so that 常用的基础属性都在手边。
63. As a 设计师, I want 属性面板里每个可用变量的地方都能从项目已有的设计变量里选, so that 我的改动和项目设计系统保持一致。
64. As a 设计师, I want 设计变量按颜色、间距、圆角、字号、阴影分组显示, so that 我能快速找到想要的值。
65. As a 设计师, I want 读不到设计变量时仍能直接输入数值, so that 没有设计系统的项目也能用。
65a. As a 设计师, I want 我输入的数值接近某个设计变量时，输入框里安静地提示这个变量、点一下就换成它, so that 我的改动自然落在设计系统里，而不会被弹窗打断。

### 新建与删除

66. As a 设计师, I want to 按 T 在画布上拖出文字图层，默认使用页面正文样式, so that 新文字和页面风格一致。

## Implementation Decisions

### 包与模块

- 只发布一个 npm 包 `03kind`，以子入口区分用途：Vite 构建插件、Next.js 配置包装、React 组件、命令行。JS 标识符不能以数字开头，所以写进项目的名字是 `thirdKind()`（`03kind/vite`）、`withThirdKind()`（`03kind/next`）和 `<ThirdKind />`（`03kind/react`）（ticket 70）。
- 由以下深模块组成，各自对外只暴露窄接口：
  - **源码标记转换**：输入一份 JSX/TSX 源码，输出插入了标记的源码。只插入属性、不重写代码，保留行号；不处理第三方依赖中的代码。
  - **使用链读取**：输入原页面上的一个元素，输出它的使用链（每一层的组件名、元素位置、使用处位置、是否来自第三方依赖）。这是唯一依赖 React 内部字段的模块，与其他部分隔离。
  - **冻结器**：输入当前页面，输出一张画布（同源 iframe 中的副本，带使用链属性），并能把同一画布以不同宽度显示为多个视图。负责样式表搬运、动画跳到结束状态、无法复制内容的静态化。
  - **图层模型**：输入画布，输出图层树（Stack / Grid / Frame / 文字 / 静态画面 / 锁定图层，以及实例分组）。
  - **编辑命令**：一组纯粹面向设计语言的命令（改属性、移动、合成 Stack、解散 Stack、新建文字、新建 Frame、改文字、删除、复制、推广、写生成说明、在断点上改属性、在断点上隐藏、挪出画布、拖回画布），每条命令同时改画布（所有视图）、产出改动记录、提供撤销。
  - **改动单**：维护本轮改动（同一图层同一属性只保留最初值和最终值），负责序列化与读写。
  - **改动说明生成**：输入改动单，输出写给 Agent 的 Markdown。
  - **画布外图层存储**：保存挪出画布的图层（固化样式的外观、源码片段与位置、在画布外的编辑），不属于任何一轮，跨轮次保留。
  - **本机服务**：运行在开发服务器进程中，只监听 127.0.0.1、校验启动时生成的随机口令；负责读写 `.03kind/`、提供设计变量、监听状态变化并推送给编辑层。
  - **编辑层界面**：用 Preact 编写、挂载在 Shadow DOM 中，不依赖宿主项目的 React 版本；包括切换按钮、图层树、画布交互层、选中工具条、属性面板。
  - **命令行**：`init`、`doctor`、`remove`、`claim`、`done <编号> …`、`finish`、`last`。`done` 给出页面对这几条改动的核对结果（ADR 0006、0013）。
  - **Skill 模板**：安装时复制进项目。只有一轮的流程和报告格式；每种改动的写法在 `claim` 的输出里（ticket 65）。

### 架构决策

- 编辑发生在冻结的画布上（ADR 0001）；画布是放在同源 iframe 中的整页副本，按原始宽度渲染后整体缩放显示。
- 一轮只对应一张画布；有未落地改动时再次进入编辑模式回到同一张画布，无改动时才重新冻结。一轮结束时还有没落地的改动，下一轮接着用这张画布，直到它们都落地或都放弃（ticket 68，ADR 0013）。
- 交互层盖在 iframe 之上处理全部鼠标操作，选中框、控制点、参考线画在交互层，iframe 自身不接收鼠标事件。
- 拖动过程中只做位移，松手后才改结构，以保证流畅。
- 改动由 Agent 按轮落地，编辑层不直接改源码（ADR 0002）；不做 MCP、没有发送按钮（ADR 0004）；落地期间锁定编辑（ADR 0005）；编辑模式中没认领却在改代码时按页面怎么变来反应：页面显示出画布上的改动就当作认领，页面变了就重新冻结没有改动的画布、在有改动的画布上用 toast 提醒（ADR 0013，ticket 66、78）；只在本地开发环境运行（ADR 0003）。
- 第一版不附带截图；Agent 只依据改动说明的文字与数值落地。
- 真实页面上不显示还没落地的改动；改动只在画布上看，播放按真实大小显示画布（ADR 0010）。
- 视图复用同一份冻结副本，放进不同宽度的 iframe；断点编辑按 Framer 的模型进入第一版（ADR 0008）。
- 挪出画布的图层不属于任何一轮，跨轮次保留（ADR 0009），是"一轮只对应一张画布"的例外。

### 源码定位

- 构建时给普通 HTML 元素加上元素位置标记，给组件使用处加上使用处位置标记（文件:行:列）。
- 冻结时在原页面上读取一次使用链，写入副本；之后的编辑只读副本。
- 判定规则：
  - 实例 = 组件渲染出的最外层图层；元素位置相同且使用链完全相同的图层属于同一使用处，一起变化；
  - 锁定图层 = 没有元素位置标记、且所在组件来自第三方依赖；但第三方组件把使用处的 props 原样转给了它渲染的元素时（如 `motion.div`、`asChild`），该元素由项目源码控制，按普通图层处理，源码位置取使用处；
  - 推广的目标 = 使用链上离选中图层最近的组件。
- Next.js 服务端组件在浏览器中没有组件结构：元素位置仍可知，使用处可能无法确定，此时改动说明标注"使用处未确定"并附页面地址和周边结构。
- 没有标记的元素照常可编辑，改动说明中标注"未定位"。

### 图层翻译规则

| 页面中实际是 | 显示为 |
|---|---|
| Flex 容器 | Stack |
| Grid 容器 | Grid |
| 普通的从上到下排列 | 纵向 Stack |
| 绝对或固定定位 | 自由定位 |
| 只含文字（含行内片段） | 文字图层 |
| 只含文字但画出盒子的（例如按钮，见 ticket 56） | 一个 Frame，里面一个文字图层 |
| 与元素混排的一段文字 | 文字图层（样式作用于所在容器） |
| 视频、图表画布 | 冻结时刻的静态画面 |
| 跨域 iframe | 灰色占位框加名称 |
| 第三方组件自己生成的部分 | 锁定图层 |
| 其他容器 | Frame |

外边距不在面板中出现，只体现在画布测量的间距里。

### 设计语言与画布样式的对应

| 面板设置 | 画布上的实际样式 |
|---|---|
| Hug | 尺寸随内容 |
| Fill | 在 Stack 中占满剩余空间 |
| Fixed | 固定数值 |
| Stack 的方向、间距、内边距、对齐、分布、换行 | Flex 的对应属性 |
| 自由定位 | 相对父容器绝对定位，父容器设为定位参照；X / Y 就是 CSS 的 `left` / `top`，图层原有的外边距保留，画出来的位置是 X / Y 加上外边距 |

### 视图与断点

- 编辑模式默认并排显示桌面、平板、手机三个视图：桌面取冻结时的页面宽度，平板 768，手机 390；可添加自定义宽度、删除视图（至少保留桌面）。整个工作区可缩放、平移，⇧1 缩放到显示全部视图。
- 视图之间共享选中与编辑：在任一视图中选中或修改，其他视图同步高亮与变化，同样 0 延迟。
- 视图只反映 CSS 响应式（媒体查询、Tailwind 断点），靠脚本判断宽度的变化不会出现。
- 视图上方的标签只写名字和它实际覆盖的宽度范围（设计师 2026-11-08）：`768–1279`、`≥ 1280`、`≤ 767`；桌面视图写其他视图都不覆盖的那段宽度，读不到范围时写视图宽度。对应的项目断点写法（如 `md:max-xl:`）和「只反映 CSS 响应式」的说明放在范围的悬停提示里。标签右端是全屏按钮，平板、手机等视图再加删除 ×（× 在最右）。
- 断点：每个视图代表一个宽度范围，按项目已有的断点（从 Tailwind 主题与 CSS 媒体查询读取）取整，和 Framer 一样：落在桌面视图所在项目断点区间里的视图就是桌面视图，其他视图从自己宽度所在的区间向上延伸到下一个更宽视图所在的区间；比桌面窄的视图中最窄的从 0 起，没有视图的宽度归它下面最近的视图；比桌面宽的视图中最宽的没有上界，桌面区间与第一个更宽视图之间的宽度归桌面视图；读不到时按视图宽度划分。范围随视图和桌面宽度变化，已记下的改动保留当时的范围；在视图里改或重置一个范围超出该视图的旧断点改动时，只改视图范围内的部分，范围外保留原值。
- 继承：桌面视图是主视图，在其中的改动作用于所有断点，除非某个断点已单独改过该属性；在平板或手机视图中的样式与布局改动（含尺寸、Stack 参数、自由定位坐标、显示 / 隐藏）只在该断点生效。属性面板标出当前断点单独改过的属性，可重置为继承。
- 结构性改动（换容器、合成或解散 Stack、新建、删除、复制、挪出或拖回画布）始终作用于所有视图；某个断点不需要的图层用"在此断点隐藏"表达。
- 全屏播放按视图的宽度显示画布（桌面视图按窗口宽度），断点改动在对应宽度下可见。

### 画布外的图层

- 图层可被拖到画布之外的空白处；在页面上等于删除，改动说明写成删除。
- 挪出时保存：固化了全部样式的外观、当时的源码片段与位置、组件与使用链信息。
- 画布外的图层不属于任何一轮：落地、刷新、重新冻结都不清除；设计师可手动删除；`remove` 时清除。它们只在本机，与 `.03kind/` 一样被 git 忽略。
- 在画布外可以照常编辑（属性、合成 Stack 等），不产生改动；拖回任一视图时作为一次插入写进改动单，附源码片段、外观与在画布外做过的编辑。若同一轮内挪出又拖回原位置，两条改动相互抵消。
- 图层树中，画布外的图层与画布并列显示，不另起名字。

### 选中工具条

- 选中框右上角有一个固定位置的小工具条，承载与选中图层相关的按钮，按钮风格一致。
- 第一版：选中的实例带有未推广的改动时出现 **Promote**；取消选中后消失，重新选中再出现。锁定图层不出现。
- 第二版：选中组件时始终出现 **States**，进入组件沙盒（ADR 0007）。第一版为它预留位置，但不显示。

### 控制点（拖着改尺寸，ticket 69）

- 单独选中画布上的一个图层时，它在每个视图里的选中框四角有白色小方块，四边是看不见的控制点（指针移上去变成改尺寸的光标）。四边的控制点沿整条边，伸出图层 4px、伸进图层最多 4px 且不超过图层大小的四分之一，所以小图层仍能从中间拖动。图层在屏幕上小于 24px 时，四角只按看得见的方块大小响应；边比 24px 短时，边中间三分之一盖在四角上面，所以缩小看时也能只拖一个方向。按住 ⌘ 按在控制点上不改尺寸，照常选中最深处的图层（用户故事 35）。多选、页面本身、没有自己元素的文字、行内显示的图层、画布外的图层不显示控制点。
- 按下控制点到松开（或按 Esc）算"按着"（ADR 0012）：期间只有挪动视角的键、Esc 和修饰键起作用。指针移动满 3px 才开始改，此后每次移动是同一次改尺寸的一步：拖角改宽和高，拖边改一个方向；⇧ 保持宽高比例（按变化较大的那个方向缩放；拖边时另一个方向绕中线变），⌥ 从中心改（对边反向移动同样距离）。⌘、⇧、⌥ 在拖的途中按下或松开，不动指针也立即生效。
- 改的是设计语言的尺寸，和属性面板里改 W / H 走同一条编辑命令：拖过的方向变成 Fixed（原来是 Hug 或 Fill 也一样），没拖的方向不变（文字图层只拖宽度时，高度仍是 Hug，随文字换行变化）。自由定位的图层拖左边或上边时同时改 X / Y，对边不动；在 Stack 或流式布局里的图层由布局摆放，尺寸变了以后位置由布局决定。尺寸取整到 1px，吸附时精确到 0.01px；停在最小、最大尺寸上，也不会小于自己的内边距加边框，拖过对边不翻转，停在 0。
- 吸附：拖动的边（⌥ 时两条边）在屏幕上 5px 以内对齐容器内框的边缘、中线；自由定位的图层还对齐兄弟图层的边缘、中线（布局里的兄弟会随尺寸移动，不作为吸附目标）。对齐处画红色参考线（只画拖动的边），按住 ⌘ 不吸附。拖的时候选中框下方显示 W × H。
- 在平板、手机等视图里拖，那个视图成为工作的视图，尺寸只写进它的断点，属性面板上改过的输入框标出改动（ticket 57；2026-11-07 起标在各输入框上，蓝底、最右带重置）；在桌面视图里拖作用于所有断点。拖的视图当场显示，旁边的视图在指针停下约 100ms 后追上（按连续改值处理，ADR 0011）。
- 一次拖拽是一步撤销；改动单里是尺寸改动（width、height，以及 X、Y），同一图层同一属性只留最初值和最终值，Agent 落地后 `done` 照常核对。按 Esc 取消时回到按下前，这次拖拽不留在撤销或重做里。
- 自由定位的图层保留原来的定位方式（ticket 75，相当于 Figma 的 Right、Bottom、Center 约束）：按右边（下边）定位的，拖右边（下边）时改 `right`（`bottom`）的值，拖左边（上边）只改尺寸，对边都不动；用 `translate(-50%)` 居中的（Tailwind v3、v4 的 `-translate-x-1/2` 都认得；从右边、下边居中的，即 `right: 50%` 配 `translate: 50%`，也算居中，整线审查修正），那个方向拖哪条边两侧都对称地长，相当于总按着 ⌥，只改尺寸；用 `auto` 外边距居中的（那个方向两边都写了值、尺寸定死、两边外边距都是 `auto`，Tailwind 的 `inset-x-0 mx-auto w-12`，ticket 96）也一样；尺寸没写（`auto`）、靠最大宽度（高度）卡住的（`inset-x-0 mx-auto max-w-md`，ticket 97）也算这样居中，拖边改的是 `max-width`（`max-height`），尺寸照旧 `auto`，所以在两边留的空间比最大值窄的视图里它照旧撑满（浏览器在那里把它摆成撑满两边之间，中点仍在两边正中），控制点拖动时也不被原来的最大值挡住。在属性面板改 W / H 和 Figma 一样，左边、上边不动：按右边、下边定位的同时改 `right` / `bottom`，居中的照样居中。定位方式按改尺寸所在的视图读，同时按左右两边定位的、冻结时被钉住的（固定在窗口上的图层的上下方向）照旧按左边、上边；从右往左排的页面上宽度定死、左右两边都写了值的，浏览器按右边摆，就按右边（ticket 89）。移动时也保留，见下一节（ticket 79）。

### 移动时保留定位方式（ticket 79，ADR 0014）

- 移动自由定位的图层（在画布上拖动、方向键微移、在属性面板改 X / Y）时，和改尺寸一样保留原来的定位方式，相当于 Figma 的 Right、Bottom、Center 约束。按右边（下边）定位的改 `right`（`bottom`）的值：往右（下）移多少就减多少，改动单里是 `right`（`bottom`）改动，没有 X（Y）。居中的保持居中：那一边的百分比不变，只改多出来的 px，例如 `left: 50%` 往右移 20px 写成 `left: calc(50% + 20px)`，从右边居中的 `right: 50%` 写成 `right: calc(50% - 20px)`；改动单里是 X（Y）或 `right`（`bottom`）改动，另记下百分比和前后多出来的 px（`centeredOn`）。用 `auto` 外边距居中的（ticket 96）也保持居中：两边都保留、外边距照旧是 `auto`，两边的百分比不变，px 一个加、一个减同样多（`left: 0; right: 0` 往右移 20px 写成 `left: 20px; right: -20px`，Tailwind 的 `left-[20px] right-[-20px]`），所以在每个宽度中点都在容器中点往右 20px；旁边有视图（页面的断点）不这样居中的，只写起点那一边、加两倍（`left: 40px`，终点那一边照各个宽度原样），那个视图里它照写的 `left` 摆，不会多出一个它原来没有的 `right` 把它摆到别处，`done` 在那个宽度按 `left` 核对（`uncenteredAt`，审查后）；改动单里是 X（Y）改动，记下居中方式（`placedFrom.margins`），`centeredOn` 记中点所在的百分比和前后多出来的 px。只有一边外边距是 `auto` 的（`ml-auto`），浏览器把它推到另一边，就按另一边定位，照上一句改 `right`（`mr-auto` 照旧按左边）。尺寸 `auto`、靠最大值卡住的（ticket 97）照样两边一加一减，不写宽度（高度），所以不会缩成内容那么宽，在它撑满的视图里两边一起挪；改动单记下 `placedFrom.held`。
- 属性面板的 X / Y 照旧显示图层的 `left` / `top`（居中图层的 X 仍是它的中点；用 `auto` 外边距居中的、或一边外边距是 `auto` 被推到另一边的，X / Y 显示它画在哪里，即写的 `left` / `top` 加上 `auto` 外边距占掉的地方，拖动的落点、微移也按这个位置算，ticket 96；在排版里带 `auto` 外边距的图层（例如 Stack 里居中的 `mx-auto w-64`）被拖进 Frame、变成自由定位时，落点不减这份外边距：按一边定位后 `auto` 外边距算成 0，图层落在松手的地方，在每个视图里都在那个 X，ticket 97）；从右往左排的页面上，左右两边都写了值、排出来对不上空间（宽度定死）的图层，浏览器按 `right` 摆它，写的 `left` 不摆它，X 显示它画在哪里（离父容器左边多远，照 Figma），在面板里输 X、微移、拖动都按这个位置算，照上一条改 `right`（ticket 94，按页面核对用的同一条规则读）；一次拖动仍是一步撤销，Esc 回到按下前。定位方式按移动所在的视图读；75 定下的边界照旧：同时按两边定位的按左边，固定在窗口上被钉住的上下方向按上边，按右边、下边定位的百分比写成 px。居中的百分比保留，这是居中本身；那一边的值读不出百分比时（例如用了 `var()`），照旧写 px。
- 拖动时保留图层自己的 `translate`，拖动的位移加在它上面，所以居中的图层一直在指针下。放下的位置按图层画出来的边框算，减去它自己的 translate 才是 `left` / `top`，微移也一样，所以居中的图层落在放下的位置（原来拖动中往右偏半个宽度，松手后又往左偏半个宽度）。
- 拖进另一个 Frame、在那里仍是自由定位，或复制（⌘D、⌥ 加拖动、复制粘贴）时，移过去的图层和副本保留原来的定位方式，按新的 Frame 算：按右边定位的仍按新 Frame 的右边摆，改 `right` 的值；居中的仍居中，多出来的 px 按放下的位置算（用 `auto` 外边距居中的，两边写成以 0 为准、一加一减的值，例如中点在新 Frame 中点往右 25px 写成 `left: 25px; right: -25px`，外边距照旧，ticket 96；尺寸靠最大值卡住的，不写尺寸，ticket 97）（设计师 2026-11-02 定，和 Figma 一样，约束跟着图层走）。改动单的位置记下这个方向怎样定位、那一边的值（`Place.absolute.placed`），改动说明照它写。
- 在平板、手机视图里移动按右边、下边定位的图层，`right` / `bottom` 改动标在属性面板 Position 行的输入框上（蓝底，最右带重置按钮；断点区不再另列改动，设计师 2026-11-07）。宽高输入框只在尺寸本身改过时标出。在断点上宽和 `right`（高和 `bottom`）两样都改过时，点宽（高）输入框或 Position 行输入框上任一个的重置，两样一起回去，图层回到原来的位置；只改过一样时只回那一样（整线审查修正，照 75 代定第 8 条「一起变的一起回去」）。
- 改动单的位置（移动的起点、复制、删除）记下的定位方式也按正在工作的视图读，和放下的位置一样（整线审查修正）。

### 设计变量提示

- 设计师自由输入的值接近某个设计变量时，输入框内安静地显示该变量名，点击即替换为变量；不弹窗、不阻止输入。
- "接近"只在同组变量内判断：颜色按感知色差很小，数值按相差不超过 2px 且不超过 10%；阈值可在实现中调优。
- 提示只给设计师，由设计师决定是否采用；改动说明仍只按精确相等判断变量，不让 Agent 判断近似值。

### 生成说明

- 生成说明可附在任意图层上。附在新建的 Frame 上时，交代要在其中生成的内容（可配草图）；附在已有图层上时，表达属性面板调不出来的意图。
- 已有图层上的生成说明是一条独立改动（种类"生成说明"），带图层的源码位置与作用范围；Agent 落地后，`done` 不做属性核对，结果为"没能核对"，由 Agent 在报告中说明如何达成。
- 带生成说明的图层在画布与图层树上显示标记。

### 合成与解散 Stack

- ⇧A 合成：横向跨度大于纵向时横排，否则竖排；间距取相邻图层间距的中位数；内边距取外框到图层的距离；对齐按图层在交叉方向上的集中位置判定。
- Frame 里的图层是自由摆放的（例如新建 Frame 里的文字、解散后的 Stack）时，合成后由 Stack 重新摆放：每个方向的内边距两侧相同，取较近一侧的距离；余下的空间交给对齐，两个方向都取离图层现在位置最近的对齐（起点、居中、末端），合成时画面不动，之后改对齐图层会跟着动。
- 合成时子图层之间的外边距并入间距、子图层外边距清零，最外侧的外边距移到新 Stack 上，面板上的间距就是实际的间距。
- 解散（⌥⇧A）：记录子图层当前位置和尺寸，全部改为自由定位并固定在原位；原 Stack 变为 Frame。靠 `auto` 外边距在 Stack 里居中的子图层（`mx-auto`）也照它画出来的位置记，不减这份外边距（按左边、上边定位后它算成 0），和别的子图层一样按左边、上边定位（ticket 97）。
- 解除分组（⌘⇧G）：去掉这个 Stack 或 Frame，子图层放进它原来所在的容器、占它原来的位置，画面不动。Frame 里自由定位、靠 `auto` 外边距居中的子图层，从它画出来的位置算，放进容器后照「拖进另一个 Frame」保留定位方式，仍居中（ticket 97）。
- ⌘C / ⌘X / ⌘V：粘贴到选中的 Stack 或 Frame 中，或放在选中图层之后；复制后粘贴记为复制，剪切后粘贴记为移动，剪切后不粘贴记为删除。剪贴板只在编辑层内有效。
- 右上角贴着属性面板的工具栏：选择（V）、Frame（F）、文字（T）。

### 播放

- 编辑模式中，每个视图标签的右端有全屏按钮（设计师 2026-11-08，取代原来 Design 标题旁的播放按钮）：画布按 100% 单独显示，不显示面板、选中框与工具栏，可以像网页一样滚动；按 Esc 或点右上角的停止按钮回到编辑模式，焦点回到按下的全屏按钮。
- 画布按那个视图的宽度显示（设计师 2026-11-08 定）：手机 390、平板 768，居中，和窗口一样高；桌面视图按窗口宽度，窗口缩放时跟着变。视图比窗口宽时按窗口宽度显示。断点改动按媒体查询在对应宽度下可见（ADR 0008），停止播放后画布回到冻结时的宽度。画布上的脚本已停、动效已跳到结束状态，播放时不能交互。
- 真实页面上不显示还没落地的改动：回到预览模式，页面就是代码现在的样子；落地后，页面显示 Agent 写出的真实结果（ADR 0010）。

### `.03kind/` 目录与状态

- 内容：编辑后的画布副本、改动单、状态文件、历史归档目录，以及不属于任何一轮的画布外图层。
- 状态：编辑中 → 已认领（附已完成编号）→ 归档（一轮结束）。已认领时再运行 `claim`（Agent 停住后设计师让它继续落地，或它丢了改动说明），只给出还没落地的改动（按页面核对算，同下面的进度），开头说已经落地了几条、哪几条；都落地了就只说一句，让它运行 `finish`（ticket 67）。手动解锁（长按切换按钮，或「Agent 好像停了」提示里的 End this round）视为按现状结束：整轮的改动单和结果照常归档（`last` 不变），未完成的改动留到下一轮（见下面「留到下一轮」）。
- 本机服务监听状态文件变化并推送给编辑层：已认领时收起并锁定，进度变化时更新进度环与角标，归档时解锁。编辑层也可以随时问本机服务现在的状态（`GET /status`，当场读状态文件），不必等推送。进度按页面核对算（ADR 0013）：页面显示了的改动算已落地，不论 Agent 是否 `done`；页面看不出来的改动 `done` 后算已落地；`done` 过但页面没显示的不算。

### 编辑中代码在变（ticket 66、78）

- 编辑模式中，这一轮没有被认领，开发服务器给页面送来了热更新：页面等代码停下约 1 秒（`CODE_QUIET_MS`；Agent 连着写好几个文件、一次编辑的 CSS 和模块先后到达，相隔不到 1 秒的算同一次变化，只处理一次），还要等设计师手上没有正在进行的操作（鼠标按着：拖拽、拖数值、改尺寸，ADR 0012；输入框里打了字还没生效、画布上的文字图层正在打字、生成说明正在写），然后按页面实际发生了什么分四种情况（ticket 78，取代 66 的居中暂停窗口；设计师 2026-11-01 定）：
  1. **页面显示出画布上的某条改动**：Agent 没认领就在落地设计师的改动。页面替它认领（`POST /claim`，先把还没存的编辑存好），之后和 Agent 自己 `claim` 完全一样：编辑层收起成切换按钮、锁定，进度环按页面核对走，`done`、`finish`、「Agent 好像停了」、长按结束这一轮都照常。不弹窗。判断用页面窗口宽度上的核对（和 64 的核对同一套，`checkHere`），只看画布上页面能核对的改动；只在其他视图宽度显示的改动不算（不为它建页面副本）。判断前先把还没存的编辑存好，核对的是存下的这一轮，新建图层按这一轮保存的画布上的位置找、扣掉容器原有的图层，和认领后的核对同一份（`placedOnCanvas`，ticket 76；整线审查补修：原来用编辑中的改动、没读画布，画布上有插在中间的新建图层时，页面不变的代码改动也会被当成落地而自动认领）。
  2. **代码变了，页面看起来没变**（重命名、拆函数、加类型等）：热更新前后，元素的增删、属性、文字和样式表内容都没变，就算页面没变，什么都不做，画布也不算过时。源码标记（`data-tk-loc`、`data-tk-usage`）随行号移动不算变；React 把同样的内容重画一遍（元素换了新的，内容一样）也不算。编辑层自己（切换按钮所在的宿主元素）和 Vite 报错时盖上来的提示层不算页面。
  3. **页面变了，画布上还没有改动**：自动按最新代码重新冻结，视图的位置和缩放不变。画布区域左下角弹 toast「Canvas updated to the latest page」，约 3 秒后消失，指针停在上面时不消失。
  4. **页面变了，画布上已有 N 条改动**：画布不动。左下角弹 toast「The page has changed since this canvas was frozen」，带「Update canvas」按钮，停留约 8 秒，指针或焦点在上面时不消失。点了以后在 toast 里确认「Discard your N changes and update?」：Cancel 收起确认、画布不动；Discard and update 放弃全部改动（和改动列表的 Discard all 同一条路径），按最新代码重新冻结，视图的位置和缩放不变。同一次过时只提醒一次：之后代码再变、页面又变，也不再提醒，直到画布重新冻结（情况 3、Update canvas，或没有改动时进入编辑模式）。
- 先不做「保留改动、自动搬到新画布上」（设计师 2026-11-01 定）：在主流程里 Agent 先把页面做完，设计师再精调，编辑时代码变化不常见；为它写一个按每种改动重做画布的模块不值得，结构改动还会对不上。设计师常常在过时的画布上调东西时再回来做，样式改动最容易搬，可以先只做它。
- 这两个 toast 在画布区域左下角：Layers 面板右边，面板收起时（或播放时）贴窗口左边，离边 16px。它们和底部正中的 toast（回应设计师自己的操作，新的顶掉旧的）分开：它是外面发生的事、带按钮、停得久，分开放一眼就能分清，也不会被取整之类的提示顶掉。两个 toast 之间仍是新的顶掉旧的。
- 认领后的代码变化归 ADR 0013 的核对：已认领时编辑模式已经收起（ADR 0005）。Agent 可能认领后马上改代码，热更新比本机服务推送的认领先到，所以页面判断前先问本机服务现在的状态（`GET /status`），已认领就什么都不做。
- 页面替 Agent 认领时，`last` 退回的代码：本机服务在这一轮被编辑、还没认领时，每次代码停下约 1 秒（Vite 的文件监听，`.03kind/` 不算）和第一次保存这一轮时，各记下一次当时的代码（git tree，同 `claim`）；页面认领时带上它看到的这次变化是什么时候开始的，本机服务用这之前最近的一份当作「改前」，所以 Agent 在这次变化里的修改也在 `last` 的 diff 里。没有这样一份时（不在 git 仓库、刚启动），用认领时的代码。
- 页面替 Agent 认领一轮带着上一轮留下的改动（ticket 68）时，不像 `claim` 那样先请页面按代码现状重读这些改动的「改前」和「Currently set by」，它们保留上一轮记下的（整线审查补修时定）。理由：页面认领时，Agent 这次的代码已经在页面上了。留下的改动里页面已经显示的，算已落地，本来也不重读；还没显示的，页面分不出它现在显示的值是这一轮开始前的代码，还是 Agent 改到一半、还没改对的值（留下的改动编号在最前，Agent 多半先改它们），重读可能把 Agent 的值记成改前。`claim` 时 Agent 还没动代码，没有这个问题。代价是：上一轮之后代码又变过（例如设计师在对话里让 Agent 改了别的），这些改动的改前和 Currently set by 是上一轮的样子；Agent 没跑 `claim`，本来也没拿到改动说明，之后跑 `claim` 拿到的是「claim 再跑一次」的说法，那时同样不重读。
- 「Agent 好像停了」（ticket 67，见下一节）只在认领之后、在切换按钮上出现；这两个 toast 只在没认领、编辑模式中出现，两者不会同时出现。
- 只在开发服务器会告诉页面热更新时有效（Vite）。Next.js 维持 66 的现状：开发服务器不告诉页面有热更新，页面自己的变化分不出是不是代码，不做这项检测，既不自动认领，也不提醒、不重新冻结。
- 判断页面有没有变：从热更新开始起看着页面的变化（MutationObserver，只在这次变化期间），停下后比较热更新前后，分片进行（每片约 10ms，`03kind:page-changed`），约 5000 个元素的页面上每次热更新不出现 long task。
- 预览模式中代码变了不提示：页面本来就是代码现在的样子。整页刷新（Vite 找不到能热更新的模块时）会结束编辑模式，回到预览模式，不提示。

### Agent 停住时（ticket 67）

- 认领之后（页面听到认领时起算；已认领时才打开或刷新的页面从打开时起算），页面看得到的三样东西都有一段时间没动，切换按钮上就出现提示「Your Agent seems to have stopped」：页面核对出的进度（进度环的条数变了）、`done` 的问答（`done` 和 `finish` 每问一次页面）、开发服务器给这个页面送了热更新（和上一节同一个信号，一次热更新的开始和结束都算）。任意一样动了，提示马上消失，重新计时。
- 停多久算停住：`STALL_MS` = 551 秒（约 9 分 11 秒），是测量台在最新代码上测到的真实 Agent「没进度、没 `done`、源码也没变」最长一段（Cursor 不加载 Skill，367 秒，从认领到第一次改源码，都在想和读包）的 1.5 倍。这一段从认领算起：Cursor 认领后常常先想一分钟以上才第一次改源码。定法和数据见 ticket 67 的 Comments。
- 提示放在切换按钮旁边（和改动列表同一处，改动列表开着时不显示），不抢焦点：设计师可能正在用页面。两个选择：
  - **Keep waiting**：提示消失，重新等一整段；提示里说，Agent 停了就对它说「Continue applying my design changes」（继续落地），它重新运行 `claim` 只拿到还没落地的改动。
  - **End this round**：和长按切换按钮手动解锁走同一条代码路径（`POST /unlock`），效果相同。长按照旧可用。
- 认领前、一轮结束后都不提示。页面在后台标签页里时计时器可能晚到，页面回到前台时马上再看一次。
- 只在开发服务器会告诉页面热更新时三样都看得到（Vite）；读不到热更新时（Next.js）只看进度和 `done`。

### 改动单内容

每条改动包含：编号；种类（样式、尺寸、合成 Stack、解散 Stack、移动、自由定位、改文字、新建文字、新建 Frame、删除、复制、生成说明、挪出画布、拖回画布）；断点（所有断点，或某个宽度范围及其对应的项目断点）；目标（元素位置、使用链、组件名、实例数量、是否锁定、是否未定位）；作用范围（这一处使用或组件本身）；改前与改后的值（设计语言）、引用的设计变量、参考样式、改前值的来源（设定它的样式规则或内联样式，含所在文件、CSS layer、是否 important、对应的类名）；删除或复制实例时标为"数据改动"，并记下是循环渲染的第几个实例（按页面渲染的顺序，画布上删掉的也算）和它的文字（ticket 65 补修）；新建 Frame 时附生成说明和草图图层的位置尺寸（新建图层在画布上排第几、容器原有图层的样子，页面核对时从这一轮保存的画布上读，不记进改动单，见下面「核对」，ticket 76）；断点上的样式改动，断点范围被项目断点切成几段时，记下每一段和页面在那一段现在显示的值（见下面「改动说明」），还没读的先记为待读（`parts` 为 null）。

### 改动说明（`claim` 的输出）

Markdown 格式，每条改动一节：种类、位置、作用范围、设计意图（含设计变量）、参考样式、当前值的来源；新建 Frame 另附生成说明与草图；已有图层上的生成说明单列一节，写明图层位置与说明原文；断点改动写明宽度范围与对应的项目断点；拖回画布附原来的源码片段与外观。

- 作用范围从事实推出：写出图层的组件不在任何其他组件里时，直接写"在位置处修改"；组件可能被多处使用时，才写"只改这一处使用"。
- 设计变量只按精确相等判断：设计师选用了变量，或自由输入的值恰好等于某个变量时，写明变量名；否则写明"没有对应变量，用精确值"。不让 Agent 判断近似值算不算。
- 新建图层（新建文字、新建 Frame）在容器排版里的位置，写成这一轮所有改动都落地之后它是容器的第几个，Agent 不必自己推算落地前后（ticket 81，设计师 2026-11-02 定）：从新建时记下的位置起，这一轮之后的改动在它前面移出、删除、合成 Stack 带走的图层减去，移入、新建、复制、拖回、合成的 Stack 放在它前面的加上（各按那条改动记下的位置）。这一轮还有别的改动给这个容器的排版加、减或挪动图层（在它之前或之后）时，位置后面加「once all of this round's changes are applied」；没有时照旧只写第几个。Grid 的第几格同样按落地后算；带生成说明的新 Frame 的草图里，画进去的每个图层（新建、复制、移入、拖回）都写落地后的位置：这个 Frame 是这一轮新建的，起初是空的，按改动单的顺序把放进来、拿出去的图层排一遍，就是落地后的顺序，同一张草图里不会有两个图层同一个序数（整线审查补修）。设计师之后自己移动了它、把它合成进 Stack，或解散了它的容器时，照旧写新建时的位置，由那条改动说它去哪。起因：76 之后说明写新文字「as its 3rd layer」，下一条改动删掉了它前面的段落，Cursor 去包里翻代码弄清页面按落地前还是落地后数。页面核对新建图层的做法照旧（按画布现在的样子、允许一个范围，见「核对」）。
- 开头一段说一轮怎么走（ticket 65）：按顺序落地；改完一条或一组相关改动后 `done`（可一次报多条），`finish` 前至少一次；`finish` 结束一轮，并给出报告的格式。没加载 Skill、只跑了 `claim` 的 Agent 也能照着走完。有打开的页面时，还写一句：设计师的页面和开发服务器都已经开着，页面会随代码变化替你核对，不用自己起开发服务器，也不用开浏览器去看（ticket 65 补修）。
- 断点改动按宽度写改前 → 改后（ticket 65 补修）：断点范围里有项目断点时（例如手机视图的 0–767px 里有 Tailwind 的 `sm` 640px），范围被切成几段。改动记下时标为待读，随这一轮保存（设计师停手约半秒后）；编辑层看到保存的这一轮里有待读的改动，就在页面的一份副本上、每段取一个宽度，读出页面现在（代码还没改）在那一段的值，记进改动并马上再保存一次。一条一条地读，每一步（建副本、同步、排版、读值）各占一个任务，约 5000 个元素的页面上也不出现 long task（ticket 65 补修）。设计师已经离开编辑模式、或之后重新打开了页面，也照样读完、保存；`claim` 看到待读的改动、又有打开的页面时，先等页面读完再认领（最多约 5 秒），所以改完马上认领也按段写。各段的值不同时，设计意图逐段写「低于 640px（`max-sm:`），从 1 到 2；640px 到 767px（`sm:max-md:`），从 3 到 2」，断点一行不再写「改前的值是它在这些宽度显示的值」。各段相同时照旧只写一次「从 … 到 …」。读不到时（没有打开的页面、页面 5 秒内没读完、图层在某一段不显示，或已经认领）照旧只写视图里的值。
- 最后一节「How to write them」：这一轮出现的改动种类的写法，每种只出现一次，没出现的不打印（ticket 65）。每轮都有的一条：设计意图是目标，参考样式只用来理解；照项目已有写法；做不到 1:1 时取最接近的或不做，都写进报告；不改第三方依赖。其余按这一轮的改动出现：
  - 有样式改动：从「当前值的来源」改起，类名就换类名；规则管的元素都在作用范围内时才改规则本身，还管着作用范围外的元素时不动它，只为这个图层覆盖（Tailwind 在图层上写类，CSS 文件、CSS Modules 为图层自己的类写一条规则；ticket 65 补修五）；继承来的文字样式设在图层自己身上。
  - 有桌面视图（所有断点）的样式改动：作用于所有宽度；项目里该属性已有的断点写法（`sm:`、`md:`、媒体查询）一并覆盖，例如 `grid-cols-1 sm:grid-cols-3` 改成 2 列是 `grid-cols-2`；本轮在某个断点单独改过的宽度除外（10/31 总调度据 63 的 Grid 列数发现加入）。
  - 有断点改动（含复制带断点值的图层）：照断点一行给出的写法只在那段宽度生效，没有对应断点时用最近的并在报告中说明；不动其他宽度；设计意图逐段给出时，每段现在各有设值的类或规则，都要改到新值；正好覆盖那段宽度（或其中一段）的类就改它，不另加；在断点隐藏只在那里隐藏。断点上改为自由定位时，定位、坐标、尺寸和容器的定位参照都只写在那段宽度。ticket 65 补修起，这一条不再举具体类名（原来的 `grid-cols-1 sm:grid-cols-3` 例子被 Cursor 套到了 768px 的范围上）。ticket 65 补修三起，这一条还说明 Tailwind 里同一属性的几个类在同一宽度都成立时谁生效：样式表里靠后的生效，和 `class` 里的书写顺序无关；样式表的顺序是不带断点变体的、`max-*`（从宽到窄）、`sm:`、`md:` 往上，每个紧跟着从它起的范围（`sm:max-lg:`）。这是在示例项目的 Tailwind 4.3.3 和 3.4.19 上编译出 CSS 核对过的；只举变体，不举具体类名。
  - 当前值来自不在 CSS layer 里的规则：它压过所有 layer 里的类，Tailwind v4 的工具类加上去也不显示，所以为这个图层覆盖它的类用 important 形式（`bg-[#2563EB]!`、`rounded-lg!`）。补修五前写的是改那条规则、收窄它，最后才用 `!`，Cursor 当成先后顺序，先去收窄全局规则。来自 CSS Modules：改组件引入的 `.module.css` 里的本地类名。
  - 只改这一处使用：在使用处改（prop、传入的 className、变体），不改组件；组件内部的类设了值时不在使用处叠一个冲突的类，把它变成使用处能替换的默认值。改组件本身：改组件写这个图层的地方，同一属性同时有组件和某处使用的改动时两个都做。
  - 按右边或下边定位、居中（ticket 75、79，各一条，这一轮有这种改动才打印）：保留原来的定位方式，改 `right` / `bottom` 的值或只改尺寸，不要改成按 `left` / `top` 定位；移动居中的图层只改那一边多出来的 px，保留百分比和 translate（`left: calc(50% + 20px)`，Tailwind 的 `left-[calc(50%+20px)]`），设计意图写明从多少改到多少；拖进别的 Frame、复制时，位置照 `Place.absolute.placed` 写那一边（ticket 79）；这些改动的设计意图或「Placement」一行也写明保留定位方式、改的是哪个值。居中的按图层实际定位的那一边写：`left` / `top` 配 `translate: -50%`，或 `right` / `bottom` 配 `translate: 50%`（整线审查修正）。用 `auto` 外边距居中的另有一条（「Centered by auto margins」，ticket 96，这一轮有这种改动才打印）：保留两边和 `auto` 外边距，移动时两边一个加、一个减同样多（`left: 20px; right: -20px`），不要写成从一边算的 px、另一边 `auto`；设计意图写明中点从哪里移到哪里、两边写成什么。尺寸 `auto`、靠最大值卡住的再加一条（「Held by a maximum」，ticket 97，有这种改动才打印）：改尺寸改最大值、不写宽度，移动也不写宽度；它的「Placement」一行、拖进别的 Frame 的位置写明「its width `auto`, held by its `max-width`」。
  - 移动：移动 JSX 本身（数据改动则移动数据）；自由定位时给容器定位参照。Grid 里换格子：按书写顺序放，不用 `grid-row`、`grid-column`、`order`。Grid 的列数和间距：改 Grid 自己的类或规则，间距用项目的间距刻度，一个值同时设了行列间距时拆开。
  - 合成 Stack、普通流式布局改为真正的 Stack（外边距在 flex 里不再折叠）、解散 Stack、尺寸（Fixed、Hug、Fill 的含义）、带生成说明的新建 Frame、生成说明、改文字、复制带断点值的图层、数据改动：各一条，内容即下面「Skill 规则」原来的对应条目。
  - 新建文字、删除、拖回画布等，改动自己那一节已经写明做法，不另列。
  - 最后一条「How the page checks」（ticket 65 补修，每轮都有，内容只含这一轮出现的种类）：样式改动读浏览器对参考样式里那几个 CSS 属性算出的值（`getComputedStyle`），每个实例都看，只看这个图层，改到作用范围外的元素即使 `done` 说显示了也不行（补修五）；所有断点的改动在页面宽度和每个视图宽度看；断点改动在项目断点切出的每一段各看一个宽度（窗口所在的那段就在窗口宽度，其余在段的下沿，从 0 起的那段在上沿减 1px）；自由定位看画出来的位置（补修三起直说：`left` / `top` 就是给的 X / Y，外边距原样保留、不要扣，页面期望它画在 `left` / `top` 加外边距处）；重排看容器里图层的顺序；删除看图层不在了；同一轮新建的图层（新建 Frame、新建文字）按它那一节给的位置找：容器里的那一个图层（这一轮别的改动落地前后都算，Agent 不用管落地的先后）、容器原来没有的，不论用什么元素写，新建文字还要字对得上，自由定位的在容器里自由定位、在给的 X / Y，对它的样式改动也就照常核对，在源码里好几处都对得上时不核对（ticket 76）；改字看图层读出来的字，加粗、链接等片段的字一并算，空白算一个空格，每个实例都看，只改这一处的改字另说组件其他使用处的字要和原来一样（ticket 90，这一轮有改字才说，说一次）；页面核对不了的种类（在页面找不到的容器里新建、合成或解散 Stack、换容器、在这一轮新建或页面找不到的容器里移动、复制、拖回、生成说明、循环里单个实例的数据改动、上一轮新建的图层上的改动；ticket 90 起不再有「改文字」这一项，核不了的改字归到数据改动、页面找不到的图层、这一轮新建的图层这几项里）点名列出，哪些能核对和页面自己的判断同出一处（`client/checkable.ts`，补修四），`done` 会说没能核对，不是错误，在报告里说明做了什么。有页面能核对的改动时，末尾说没显示时 `done` 会给出页面上的值和宽度，不必再去找它怎么核对。原 Skill 里讲页面怎么核对的那段，65 删了、命令输出里又没补，Cursor 因此去读包里的代码。

### 核对（ADR 0006、0013）

- 认领之后，代码每变一次（Vite 的热更新；读不到热更新时，页面的变化），页面就核对还没显示的改动，把结果交给本机服务。热更新到了，页面可能还没画完（React 稍后才重画），所以每次热更新之后约 3 秒里，页面自身的变化也跟着再看；页面开始核对时（认领、重新读这一轮、认领期间打开页面）也一样，因为 Agent 可能认领后马上改了代码，热更新在页面开始核对之前就到了。页面显示过的改动，也在页面窗口的宽度上再看一遍（之后的改动可能把它弄掉了），看到没有显示时进度环随之减少（页面此刻看不了，例如图层不在当前页面上，不算）；窗口以外的宽度要等 `done` 或 `finish` 问到时再看。核对分片进行，副本的同步和排版各占一个任务，每片不超过约 12ms，大页面上也不出现 long task。
- 位置（自由定位的放置、X、Y）按画出来的位置核对：页面上的 `left` / `top` 加外边距，要等于画布上的 X / Y 加该图层在画布上的外边距（相对于包含块；外边距随改动记下）。所以 Agent 照画布留着外边距、或把外边距并进 `left` / `top`，都算显示了；去掉外边距则不算，`done` 给出页面上的 `left` / `top` 和外边距、画布上的位置和外边距。桌面视图的改动在其他视图宽度上，`left` / `top` 等于 X / Y（外边距照项目在那个宽度的写法留着）、或画出来的位置等于 X / Y 加上记下的外边距，都算显示了：项目的断点可能让外边距在那些宽度不同，而画布只记下了桌面视图里的外边距。
- `right` / `bottom`（ticket 75）照同样的方式按画出来的位置核对：页面上的 `right` / `bottom` 加右边、下边的外边距，等于画布上的值加画布上的外边距。画布在某个视图里不按这条边定位（例如项目的断点让手机上按左边定位）时，这条边在那里不决定位置，那个视图代表的宽度不看，窗口宽度落在里面也一样；看不看按画布（设计师看到的样子）定，不按 Agent 改完后的页面定，所以 Agent 改成按左边定位时，各视图宽度上仍按 `right` 核对，不会报出虚假的「显示了」（整线审查修正）。画布在各视图里是否按这条边定位，在这条改动第一次记下时读一次，只读旁边视图里图层的 `position` 和声明的 `left` / `top`，不让旁边的视图追上、不排版（ADR 0011），记进改动（`placedOtherwiseAt`）。
- 居中图层的移动（ticket 79）按那一边在每个宽度该有的值核对：记下的百分比乘以页面上容器在那个宽度的大小，加上记下的 px，再加外边距，等于页面上那一边的值加外边距。所以 Agent 写成只在窗口宽度对的 px 值时，在其他视图宽度报「没有显示」，`done` 说画布在那个宽度把它居中在哪里，让 Agent 写成百分比。拖进别的 Frame 又拖回原来的 Frame（同一个容器里的移动）、位置记了 `placed` 的，那个方向也按那一边核对。两种都另外看图层在页面上是不是仍居中（自身一半的 translate 还在、没被别的 `transform`、`rotate` 换掉）：不是，就算没显示，`done` 说 translate 没了，不看那一边的值（整线审查修正，否则那一边对、图层却偏半个宽度，会报虚假的 ✓）。用 `auto` 外边距居中的图层（ticket 96）按画出来的位置核对：在每个宽度，图层中点要在记下的百分比乘以页面上容器在那个宽度的大小、加上记下的 px 处（即页面上写的那一边加外边距，等于这个中点减去半个尺寸）；不管页面是靠 `auto` 外边距还是只靠两边摆到那里，画出来对就算显示了。所以 Agent 写成从一边算的 px（另一边 `auto`），在窗口宽度对、在其他视图宽度报「没有显示」；去掉了 `auto` 外边距，图层画在写的那一边，各个宽度都报「没有显示」；`done` 说图层画在哪里、画布在那个宽度把它居中在哪里，让 Agent 保留两边和 `auto` 外边距，照说明写两边。拖进别的 Frame 又拖回、位置记了 `placed` 的，那个方向也这样核对。尺寸靠最大值卡住的（ticket 97）一样按中点核对，尺寸取页面上在那个宽度画出来的大小（撑满的宽度上就是两边之间的空间）；Agent 写成从一边算的 px，图层缩成内容宽，那个宽度报「没有显示」，`done` 另说保持宽度 `auto`、由 `max-width` 卡住。
- X、Y、`right`、`bottom` 的改动，图层在页面上还不是自由定位（`position` 不是 `absolute` 或 `fixed`，例如 Agent 写了 `top`，却没写解散 Stack 那条改动）时，算没显示，页面不读它的 `left` / `top` / `right` / `bottom` 当作实际的值：这时它们不决定图层的位置（ticket 80）。`done` 照「移动到自由定位」的说法说图层还不是自由定位、不在给的位置，让 Agent 检查 `position` 和这个方向的 `left` / `top`（`right` / `bottom`），以及容器是不是它的定位参照，不再说「有别的样式盖住了改动、去查 Currently set by」；`finish` 的原因一行写「图层在页面上不是自由定位」。自由定位那条改动（在断点上改为自由定位）的说法不变。
- X、Y 的改动（在桌面视图改、作用于所有宽度）照 `right` / `bottom` 的做法（ticket 83）：画布在某个视图里图层是 `position: static`（例如图层只写了 `md:absolute`，手机视图里在容器的排版里），`left` / `top` 在那里什么都不摆，X、Y 不决定位置，那个视图代表的宽度不看，窗口宽度落在里面也一样；`relative`、`sticky` 的图层，`left` / `top` 在那里也挪动它，照看（审查后修正：只认 `absolute` / `fixed` 时，`relative md:absolute` 的图层 Agent 只写 `md:left-[…]` 也报「显示了」；怎么看见下一条，ticket 84）。看不看按画布定，不按 Agent 改完后的页面定，所以画布在某个宽度是自由定位、页面上不是时，照旧按上一条报「没有显示」。画布在各视图里是不是 static，在这条改动第一次记下时读一次，只读旁边视图里图层的 `position`，记进同一个 `placedOtherwiseAt`。所有要看的宽度都被跳过时，`done` 说没能核对，原因是「在核对的宽度上，画布上的图层不是自由定位」。
- 画布在某个视图里图层还在容器的排版里、但被 X、Y 或 `right` / `bottom` 挪动（`relative`、`sticky`）时（ticket 84，设计师 2026-11-03 选做法 1），那个视图代表的宽度比对偏移本身，不按自由定位核对：页面上图层在那里也是同样的 `relative`（或 `sticky`），并且这一边的值等于改动的值（不算外边距：`relative` 的偏移从排版里的位置算起），才算显示了；页面上在那里是 static、被改成了自由定位、或换成了另一种（`relative` 换成 `sticky`），都不算。`relative` 按浏览器把它挪了多远比（它给 `left` / `top` 的值；`right` / `bottom` 往反方向挪，但同时写了 `left` / `top` 时浏览器按 `left` / `top` 挪，`right` 就不算数）；`sticky` 按这一边的值比：画布的视图和页面一样高、不滚动，`sticky` 的 `left` / `top` 是贴住的阈值，只在它排在离视图边不到这么远的地方时才把它推进来，大多时候看不出挪动，所以说法也不同。`right` / `bottom` 只在画布上那个视图里没写 `left` / `top`（`relative`）时才算挪动它，写了的照旧记进 `placedOtherwiseAt`、不看；`sticky` 两边的阈值都算数，照看。居中的图层（`centeredOn`）不记这种范围，照旧按自由定位核对。这些范围也在这条改动第一次记下时读一次（ADR 0011），记进改动（`offsetInLayoutAt`，带上画布那里是 `relative` 还是 `sticky`）。没显示时，`done` 说这个宽度画布上把图层挪多少（`relative`：「moves it 60px right of where its container lays it out」）或把它贴在离哪边多远（`sticky`：「keeps it at least 40px from the top of what it scrolls in」），页面上它挪了多少、值是多少，或在那里是怎么排的，让 Agent 在这个宽度也给这一边这个值，不提 `position` 和定位参照；`finish` 的 Why 一行写「the page does not move the layer 60px right of where its container lays it out, as the canvas does」（`sticky`：「does not keep the layer at least 40px from the top of what it scrolls in」）。所有要看的宽度都被跳过的原因不变：跳过的只有画布上 static 的宽度。
- 上面几条里「这一边挪不挪它」「页面上挪了多少」都看哪一边说了算（ticket 89）：图层左右两边都写了值时，跟着图层的 `direction`，按浏览器的定法读它的包含块（`relative` 的是排它的那个块，跳过 `display: contents` 和行内元素；自由定位的是定位参照，或滤镜、变换、`contain` 让它成为定位参照的盒子；由窗口定位的，看 `body` 的方向，`html` 上写的 `dir` 不算）：从左往右按 `left`，从右往左（`direction: rtl`，例如阿拉伯语、希伯来语的网站）按 `right`；自由定位的图层只在宽度定死时才有一边说了算，宽度不定时两边都摆它，照旧按左边处理。上下方向 `top` 总是说了算，不变。页面上自由定位的图层两边都写了值、宽度（高度）定死时，没说了算的那一边写的值不摆它，`done` 按浏览器把它摆在哪里核对，不按写的值（审查后修正）。「定死」按排出来的几何读：边、外边距和尺寸加起来和包含块的空间对不上就是，`max-width` 卡住的、`<canvas>` / `<img>` 自带尺寸的都算。从左往右的 `right`、上下方向的 `bottom` 也照这样核对，所以从左往右的页面上，这种图层的 `right` / `bottom` 改动的 `done` 会变：原来按写的值报 ✓ 的，现在报没显示；原来就没显示的，说的数换成画出来的位置；`right` 过时、但 `left` 已经把它摆在画布那里的，从没显示变成 ✓。上下方向哪一边说了算没变（`top`）。画布那边（旁边视图第一次记下时）照旧按声明的宽度、高度判断定死没有，不排版（ADR 0011）。
- 在桌面视图中做的改动，在页面窗口的宽度和每个视图的宽度（手机、平板等）都要显示，才算显示了；本轮在某个断点单独改过同一图层同一属性的，该断点范围内的宽度不看（ADR 0008）。断点改动在该断点范围内的一个宽度核对；ticket 65 补修起，记下了各段的改动在每一段各核对一个宽度（窗口所在的那段在窗口宽度，其余在段的下沿，从 0 起的那段在上沿减 1px），没显示时给出那个宽度。窗口以外的宽度在页面的一份逐节点副本上看：副本放在那个宽度的隐藏 iframe 里，随页面变化同步，和视图一样只反映 CSS 响应式，不运行页面的脚本。
- `done <编号> …` 可以一次报多条。页面已经核对为显示了的，页面当场再看一眼就回答（没有打开的页面时，用这一轮页面看到的结果）；其余的等页面回答：页面先等 Agent 最后一次改动的代码真的到了页面（`done` 带上 git 看到的最后修改时间，Vite 的热更新告诉页面代码到了哪一次；有热更新在途就一直等，最多约 20 秒；没有热更新可等时最多等 3 秒），再给约 1 秒让新样式显示出来（读不到热更新时等 3 秒），然后下结论。`done` 和 `finish` 每问一次，都带一个只属于这一问的标记，页面的回答带回同一个标记，命令行和本机服务只按这个标记认回答；页面在代码变化时自己看的结果不带标记，即使和问题落在同一毫秒，也不会被当成回答。
- 同一轮新建的图层（新建 Frame、新建文字，ticket 76）：Agent 写进代码之前它不在源码里，画布上没有它的源码标记，页面按新建那条改动记下的位置在活页面上找它。容器：页面原有的按源码标记找，同一轮新建的 Frame 按它自己的位置找，一层层往里；找不到的容器（这一轮复制、拖回、合成的 Stack 里，或没有源码标记）不找，核对说没能核对。在容器的排版里：它是容器的第几个图层，按画布现在的样子算（设计师后来挪过它、在它前面加删过图层，都按现在的位置），它前面有几个图层页面一定有、几个页面可能还有或还没有（这一轮删除、移动、新建的，和移出这个容器的），页面在这个范围里找；自由定位的：容器里自由定位的图层都算位置对。容器原有的图层不算（按它们在画布上的样子：标签加文字，同样子的有几个原有的就扣掉几个），不比标签：画布上新建的 `<div>`、`<p>` 是编辑层的做法，不是设计意图，Agent 把 Frame 写成 `<ul>`、`<section>`，把文字写成 `<h2>`、`<span>` 都算（指挥 2026-11-02 定）；新建文字要字对得上（以最后打的字为准），就是找到了。容器在循环或组件里、页面上渲染了好几份时，每一份里都要找到；找到的元素都出自源码的同一处（源码标记的位置相同），算同一个图层，照常核对；出自好几处，不猜，答没能核对，说找到了几个、写在哪几处源码位置。这些位置信息（前面几个图层、原有图层的样子）是页面核对时从这一轮保存的画布（`.03kind/canvas.html`）上读出来的，不记进改动单：记进 `changeset.json` 时，Cursor 读改动单看到它看不懂，去包里翻代码，测量台测出变慢（ticket 76，指挥 2026-11-02 定）。刷新页面、换浏览器、认领后才打开页面，都从保存的画布读，照样找得到。找到的源码位置不记进改动单，也不写进画布，每次核对都按位置重新找。
  - 新建本身：找到就算显示了；自由定位的还要在容器里自由定位（容器是定位参照）、画在设计师最后给的 X / Y（`left` / `top`）。找不到算没显示，`done` 说它在找什么（新 Frame，或带这些字的新文字，第几个图层）和那个位置上现在是什么。
  - 这一轮对它的样式改动：在找到的元素上照常核对（每一份都看）；找不到时答没能核对，说它不在给的位置上（新建它的改动另有没显示的结果）。对它的结构改动（移动等）照旧不核对。
  - 上一轮新建、已落地的图层（只在一轮没落地完、下一轮回到同一张画布时出现）不找回：设计师 2026-11-01 定，跨轮的情况很少，`claim` 给层级路径和开头标签，Agent 自己去源码里找；核对说它是上一轮新建的、页面找不到它。
- 改字（ticket 90，设计师 2026-11-04 选做法 2）：改现有图层的字，页面按源码标记找到这个图层（不是这一轮新建的、不是数据里来的字、不是一段字里的一截），看它的字是不是设计师最后打的字，比法和新建文字一样（同一段比字的代码）：按读者读到的字比（`textContent`，空白连成一个空格，加粗、链接等片段的字一并算，不管片段用什么元素写）。页面上渲染了好几份（循环里同一个使用处的几个实例、组件同一个使用处）时每一份都要对上，和样式改动一样；字在每个宽度都一样，只在窗口宽度看，不在副本上看。只改这一处的改字（组件被多处使用、设计师只改了一个使用处的字）照下一条 ticket 77、82 的做法看其他使用处：页面开始核对时记下其他使用处每个实例读到的字，随认领存进 `.03kind/other-usages.json`，刷新、认领后才打开页面都按存下的比，页面替 Agent 认领时按代码变化开始时的字；有一处变了，这条改字就算没显示，不报虚假的 ✓。某个使用处这一轮自己也改了同一个图层的字，那个使用处不比；这一轮对某个使用处的实例有数据改动（循环里删除、复制、移动一项，或改它自己的字）的，那个使用处也不比：数据一变，按第几个实例重新找到的元素换成了另一项，会把 Agent 做对的删除报成漏改（ticket 90 整线审查补修）。`<br>` 读作一个空格（设计师用 Shift+Enter 换行、Agent 写 `<br/>` 时字对得上，新建文字的比法一并受益）；`display: none` 的片段照样算进字里，是已知的风险。按源码标记找不到图层、退而按位置最近的找时，不拿同一源码位置、使用处是这一轮保存的画布上组件另一个使用处的元素顶替（那是没动过的另一个使用处，不是这个使用处挪了；画布上的使用处从 `.03kind/canvas.html` 读，不记进改动单；只在真的要分辨时才读（标记挪了、按标记找不到这个使用处、又有元素在同一源码位置），一轮只读一次，开始核对时不读：大页面上整张画布解析一次约 12ms（big.html 的画布 5014 个元素，无头），放在认领那一刻会和开始核对挤进同一个任务，窗口模式下出现 long task（整线审查补修）），所以这个使用处不在页面上时答没能核对，不会因为别的使用处读着新字报虚假的 ✓；使用处画布上没有的（Agent 在使用处上方加了行，组件本身没动），就是这个使用处挪了，照旧找得到、照常核对；组件里图层上方加了行、各使用处的标记一起挪的，也照旧找得到（整线审查补修，对所有改动生效，12 个非改字场景的输出逐字不变）。
  - 没显示时，`done` 照 ticket 80 的口吻说页面上那里现在是什么字、画布上是什么字、该怎么改：「The layer reads “Third Kind Studios” on the page, not “Third Kind Studio” as on the canvas: change its words in the JSX, or where they are given when they come from a prop or a variable, and run `npx 03kind done 1` again.」；`finish` 放 ⚠️，Why 一行先填好「the layer reads “Third Kind Studios” on the page, not “Third Kind Studio”」。漏到别的使用处时用 77 的说法，属性那一段写成「its words from “Freeze” to “Your move”」（`done` 和 `finish` 的 Why 一行都是）。
  - 核不了时各有自己的原因，不再落到结构改动那句（原来改字落在 `uncheckable()` 的兜底那支，`done` 说它是结构改动）：字从数据里来（循环里单个实例的字）——「the words come from the data the loop goes through, and the page cannot tell the loop's instances apart」；一段字里的一截（没有自己的元素）——照旧「the text has no element of its own on the page」；图层没有源码标记——照旧「the layer has no source marker, so the page cannot find it」；这一轮复制、拖回的图层上的改字——照旧「the layer is new this round, so the page has no marker to find it by」，上一轮新建的照旧。这一轮新建文字的字记在新建那条改动里，随它核对（以最后打的字为准）；单独一条改字落在这一轮新建的图层上（编辑层不这样记，改动单里有时）说「the layer is new this round: the page checks its words with the change that makes it (change 1)」。
  - `claim` 的「How the page checks」这一轮有改字时说一次：「new words by the words in the layer, its bold runs, links and other pieces with it, white space as one space, in every instance」，有只改这一处的改字再加「new words for this usage only by the component's other usages too, which are to read as they did」；不能核对的清单里去掉「new words」。没有改字的一轮，`claim`、`done`、`finish` 的输出逐字不变；切换按钮的包逐字节不变（核对代码在编辑层延迟加载的那部分和命令行里）。以上说法由 ticket 90 那条线代定，等设计师确认。
- 结构改动核不了时的原因（ticket 95，设计师 2026-11-04 分诊选做法 1：只把原因改准确，页面不多核对什么）：`uncheckable()` 原来的兜底那句「of the changes to the structure, only reorders, absolute placements in the same container and deletions are checked on the page」只留给它说得对的情况：复制（不在循环里的图层）、拖回画布的图层、合成或解散 Stack、换到别的容器（包括换容器时自由定位）、在同一个容器里从自由定位放回排版。说得不对的各有自己的一句：循环里的一项单独删除、复制、调换顺序、挪动（自由定位、换容器）——「the change is to the data the loop goes through, and the page cannot tell the loop's instances apart」（口吻照 90 的改字那句；代码里改的是循环所用的数据，页面分不清循环里的每一份）；页面要是找得到容器就会核对的移动（同一个容器里自由定位，或容器里没有散字时调换顺序）、容器却找不到——照 76 给新建图层的容器的原因：没有源码标记「its container has no source marker, so the page cannot find it」，这一轮复制、拖回、合成的 Stack「its container is new this round (a copy, a layer put back or a new Stack), so the page has no marker to find it by」，上一轮新建的「its container was made in a round before, and the page cannot find it」，这一轮新建的 Frame（只在留到下一轮的一轮里出现）「its container is new this round, and the page checks no move in it」，这个 Frame 又在页面找不到的容器里时「its container is new this round, in a container the page cannot find」。一个 Frame 唯一的字（按钮里的字，没有自己的元素，`Target.onlyText`）在这个 Frame 里自由定位——照一段字里的一截的说法「the text has no element of its own on the page」（画布给它包了 `<span>` 才挪得动，页面上没有这个元素）。找不到的容器里有散字时调换顺序照旧说「text runs on among the layers of its container, so the page cannot tell their order」，从自由定位放回排版照旧说兜底那句。原因只出现在 `done` 和归档的核对结果里，`finish` 的报告不带原因，照旧。`claim` 的「How the page checks」核不了的名目不变：已有「a change to one of a loop's instances alone」「a move in a container made this round, or one the page cannot find」，和新的原因对得上；按钮里的字原地自由定位改归「a change to a layer the page cannot find」（原来归「a move into another container, or into a layout from a place of its own」，说错了）。没有这几种改动的一轮，`claim`、`done`、`finish` 逐字不变。
- 断点上的改动改到范围外（ticket 104，设计师 2026-11-05 定，发布前修）：断点上的样式改动只在它的范围里生效（ADR 0008），页面除了在范围里各段的宽度看它显示了，还在范围外的宽度（页面窗口的宽度和每个视图的宽度，在范围外的那些）看图层这项属性和认领时一样。做法照 77：页面开始核对这一轮时（先把那些宽度的页面副本备好、样式表载入后），在每个范围外的宽度记下图层每个实例这项属性的值（设计语言），和 77 记的放在一起，随认领存进 `.03kind/other-usages.json`；之后每次核对这条改动、范围里显示了时，再读：有一个实例的值不在记下的值里，这条改动就算没显示，`done` 说「it shows the change, but outside its range too: at 1280px wide, its fill from #FFFFFF to no fill … since the round was claimed」，并说这条改动只在哪个范围生效（有 Tailwind 写法时带上，例如 `max-md:`），让 Agent 只在范围里改、把范围外改回去；`finish` 开头一行单列「Shown outside its breakpoint's range too: 1.」，报告放 ⚠️，Why 先填好宽度和前后的值；进度环不算它。认领后每次热更新的快速复查只比窗口宽度的那一份，`done`、`finish` 问的时候每个宽度都比。不比的：这一轮在那个宽度另有改动改同一图层的同一属性（桌面视图里的改动、别的断点上的改动、组件本身的改动，按同一属性或参考样式有相同 CSS 属性认），那里按那条改动核对；放置类属性（X、Y、右、下、是否自由定位，周围布局一变就跟着变）不看；这一轮新建的图层、页面按源码标记找不到的图层不看；尺寸和文字类属性（宽高及其上下限、字体字号字重、文字颜色等，会随本图层别的属性或外层变）在那个宽度这一轮另有改动改到这个图层或外层（样式改动、结构改动的容器）时不比，免得把这一轮自己的改动当成 Agent 改错。页面替 Agent 认领的一轮（ticket 78）只在窗口宽度记（备副本要时间，代码已在变）。没改到范围外的一轮，`claim`、`done`、`finish` 的输出逐字不变。
- 「只改这一处」的改动漏到组件的其他使用处（ticket 77，设计师 2026-11-01 定，只做简单的版本）：作用范围是这一处使用、写出图层的组件可能被多处使用的样式改动（改动说明写「This usage only」的那些），页面开始核对这一轮时（认领、认领期间打开页面），先记下同一组件在当前页面上其他使用处（同一源码位置、使用链不同的元素，每个实例都记）这条改动那项属性的值，按页面窗口的宽度、和核对一样读设计语言的值（例如间距、填充），不比参考样式带出来的其他属性（例如把普通的流式布局变成 Stack 时的 `display`）。之后每次核对这条改动、页面显示了它时，再读这些元素的值：有一个变了，这条改动就算没显示，`done` 说这一处显示了，但也改到了组件的另一个使用处，给出那个使用处的使用链位置，以及这项属性从多少变成了多少，让 Agent 只改这一处、把那里改回去；`finish` 把它放 ⚠️，原因一行先填好那个使用处和前后的值；进度环不算它。不查的：其他使用处不在当前页面上；某个使用处这一轮自己也改了这项属性（同一属性，或参考样式有相同的 CSS 属性）；组件本身这一轮也改了这项属性（推广过的改动）。推广过的改动本身、写出图层的组件没被别的组件使用的（改动说明写「Change it where it is written」）、循环里同一个使用处的几个实例，照旧。窗口宽度和记下时不同时不比；记下的元素被重新画过（不在页面上了），按使用处和它是第几个实例重新找，找不到就不比。记下的值连同认领一起存进 `.03kind/other-usages.json`（ticket 82，设计师 2026-11-02 定）：页面记下就交给本机服务存，同一条改动以先存下的为准（两个页面都开着时，后记的可能已在漏改之后）；页面听到认领后先重新读这一轮（带上存下的值）再记、再核对，存下的值先于自己记的，所以页面替 Agent 认领时开着的另一个页面也按代码变化之前的值比（整线审查补修）；认领期间刷新页面、或认领之后才打开页面，`GET /round` 带上存下的值，页面接着用，按使用处和第几个实例重新找到那些元素，之前已经漏过去的照样查得出。页面替 Agent 认领的一轮（ticket 78）：改前用这次代码变化开始时（开发服务器刚说要热更新、新代码还没进来）页面上的值，那一刻按画布上这一轮的「只改这一处」的改动记下，随认领一起存；记下之后这个编号换成了别的改动（例如撤销后又新改了一条）的不用。存下的值只属于这一轮：一轮结束（`finish`、长按结束）就删掉，下一轮认领（`claim`、页面认领）时也先清掉；文件带着认领时间，页面交来的值带着记下的时间，认领之前记的（上一轮的页面晚到的，编号已从 1 重新排）不收，别的认领的文件（一轮结束时页面写回来的）和读不出的文件都当作没存（整线审查补修）；「改前取认领时活页面上的值」不变。仍查不出的：认领时没有页面开着（没人记，之后打开的页面按那时的样子记）；只写在某个断点上的漏改（组件里加 `max-md:` 之类）——页面只在窗口宽度记、只在窗口宽度比，窗口不在那个断点范围时查不出（设计师定维持现状：要补就得在三个视图宽度都记、都比，多核对两倍的元素，不划算）；刷新后窗口宽度和记下时不同，不比。`claim` 的「How the page checks」没有改（那句「改到范围外的元素即使 `done` 说显示了也不行」照旧成立），没有漏改的一轮 `claim`、`done`、`finish` 的输出逐字不变。
- 每条输出三种结果之一：页面显示了这条改动；页面没有显示（附实际的值和读的是浏览器算出的哪个 CSS 属性，不在窗口宽度时附宽度，断点改动说明改动在那个宽度也生效，提示去查来源、修好后再运行一次 `done`）；没能核对（没有打开的页面、图层此刻不在页面上、未定位、或页面没法显示到该宽度）。
- 核对结果随本轮归档，`finish` 和手动结束一轮时记下的已落地改动以页面核对为准：页面显示了的改动；页面看不出来、或没能核对的改动，`done` 过的。`finish` 先请页面把能核对的改动按最后一次改动再看一遍（和 `done` 一样等代码到页面），再归档；它列出页面没有显示的改动和页面看不出来又没 `done` 的改动，并按核对结果把这一轮的报告排好（ticket 65 补修，ADR 0013）：已落地的放 ✓；页面没显示的放 ⚠️，原因一行先填好页面上实际的值（和宽度），Agent 补上是什么让它这样；没 `done` 的放 ⚠️，原因留给 Agent 填；页面看不出来、`done` 过的先放 ✓，并说明没有完全照做就挪到 ⚠️ 下、带两行。Agent 只填 `<…>`。手动结束一轮时用页面当时的结果，不再等。

### 留到下一轮（ticket 68）

- 一轮结束时（`finish`，或设计师长按、点「End this round」结束这一轮，同一条路径），按页面核对算出已落地的改动（和进度、`finish` 的报告同源：页面显示了的；页面看不出来的 `done` 过的）。全都落地了，就和以前一样：归档，画布丢弃，下次进入编辑模式按新代码重新冻结。
- 还有没落地的（`finish` 报告里的 ⚠️，或设计师结束时还没做的）：画布不丢。已落地的改动照常归档，从改动单和改动列表里拿掉，但留在画布上当底：撤销（⌘Z）和改动列表都撤不了它们，之后再改同一个值，改前就是它们的值；要退回代码，用 `last`。当底的改动在画布上还在原来的位置：已落地的「只改这一处」仍压在留下的「组件本身」改动之上，放弃留下的那条，显示的就是已落地的值；留下的结构改动（移动等）在容器上加的东西（例如绝对定位的参考 `position: relative`）算那条改动的，放弃它就一起撤掉（审查后补修，2026-11-01）。没落地的留在改动单里，按原来的顺序从 1 重新编号，新改的接在后面；改动列表、`claim`、`done` 用同一套编号。下次进入编辑模式回到同一张画布，样子和结束前一致（断点上的改动、画布外的图层也一样）。
- 两轮之间：切换按钮的角标显示留下了几条，改动列表可以逐条放弃，Discard all 照常可用；⌘Z 只撤这次进入编辑模式之后的编辑。都放弃之后，下次进入编辑模式按新代码重新冻结；都在下一轮落地之后也一样。
- 留下的改动的「改前」是上一轮冻结时的代码，所以下一轮 `claim` 先请打开的页面按代码现状再看一遍（和 `done` 一样带标记问页面，等它回答）：页面已经显示的算已落地；其余的样式改动，改前换成页面现在显示的值（X、Y 是页面上的 `left`、`top`，外边距另算，同 ticket 65 补修；断点范围被项目断点切成几段的，各段的值在认领前由页面重新读，同 ticket 65，各段相同时这个值就是改前），「Currently set by」也换成页面上现在设这个值的地方，和改前在同一次问里一起读（设计师 2026-11-01 定），写回改动单，`claim` 再跑一次和 `last` 都用它。`claim` 的开头照 67「claim 再跑一次」的写法：「This round carries 2 changes over from the round before, not applied then (1 and 2), and none of its 3 changes are applied yet. Left: …」；页面已经显示的，说「1 of its 3 changes is applied already (2), as the designer's page shows it」；都显示了，就只说一句，让它运行 `finish`。没有打开的页面时不问，改前和「Currently set by」照旧。
- 结构改动（移动、合成或解散 Stack、换容器、复制等）的图层不重新找：页面核对照旧，找不到就说没能核对，Agent 照源码位置去改；画布上不另做标记。
- 上一轮 Agent 新建的图层（例如新建 Frame 已落地，对它的样式改动没落地）：画布上还有这个图层，改动照常留下。改动说明的位置一行说它是之前一轮新建、当时已落地、源码里已经有了，但画布上没有它的源码标记，照它在页面上的位置（层级路径和开头标签）去源码里找；「Currently set by」写不知道。改动单里没有新建它的改动就这样写，留下的改动都放弃之后再改它也一样。页面核对说没能核对：它是之前一轮新建的，页面找不到它。这类图层不在页面上找回（ticket 76，设计师 2026-11-01 定：只找同一轮新建的图层，见上面「核对」）。
- 归档里照旧保留整轮的改动单和结果，`last` 不变。

### 撤销上一轮

- `claim` 与 `finish`（或手动解锁）时，在 git 仓库中各记下一次当时的代码（一个 git tree，不改动暂存区与任何文件）。`last` 给出这一轮源码的精确 diff，撤销就是把它反向应用；不在 git 仓库中时退回到对照改动说明改回。

### Skill 规则

ticket 65 起，Skill 只有一轮的流程和报告格式，不到原来的三分之一（146 行 → 40 行）；下面的落地规则都挪进了 `claim` 输出的「How to write them」，只在这一轮出现对应的改动时打印（见「改动说明」一节）。

- 触发：设计师要求落地设计改动或撤销上一轮。
- 流程：`claim` → 落地，改完一条或一组相关改动后执行 `done`（可一次报多条），`finish` 前至少一次 → `finish` → 按固定格式报告（✓ 已落地；⚠️ 无法 1:1 落地的改动、原因、实际处理方式）。
- 读 `done` 的输出：显示了就继续；没显示就查它说的宽度上是什么设了值，修好后再 `done`；没能核对不是错误，继续（`done` 自己也这样说）。
- 报告格式：每条改动只出现一次、只在一个标题下；落地了但和要求不完全一样的只放 ⚠️，不同时放 ✓；⚠️ 下每条都有「原因」和「实际处理」两行。ticket 65 补修起，`finish` 的输出末尾给出这一轮排好的报告（见「核对」一节），后面跟同样的三条规则（和 Skill 里逐字相同，有单测）；Skill 里留通用的格式示例，说照 `finish` 排好的报告填。
- 撤销上一轮、卸载：跑 `last`、`remove`，照输出做。
- 落地规则（在 `claim` 的输出里，ticket 65 之前在 Skill 里）：
  - 跟随项目已有写法（Tailwind 改类名，CSS 文件改 CSS）；
  - 优先引用改动说明中的设计变量；
  - 严格按作用范围修改这一处使用或组件本身；
  - 普通从上到下排列的区域被改了间距或对齐时，改为真正的 Stack；
  - 自由定位的图层，把父容器设为定位参照；
  - 生成说明：新建 Frame 中的，用项目已有组件和风格生成内容，参考草图布局（Frame 里没画东西时不提草图，说在 Frame 的尺寸内按说明排，ticket 65 补修四）；已有图层上的，按说明达成意图，并在报告中写明做了什么；
  - 数据改动：数据写在代码里则修改，来自外部数据源则报告原因；
  - 断点改动：用项目已有的断点写法（如 Tailwind 的 md:、lg: 或已有的媒体查询）只在该宽度范围生效；
  - 挪出画布：从源码中删除；拖回画布：按附带的源码片段放回，必要时按当前代码调整；
  - 永远不修改第三方依赖。
- 撤销上一轮：`last` 取得上一轮改动说明与源码 diff，把 diff 反向应用；没有 diff 时对照改动说明改回。

### 安装

- Guide 只有几行：运行 `init`、启动开发服务器、确认切换按钮出现、运行 `doctor`。
- `init`：识别 Vite / Next.js 与包管理器 → 装为开发依赖 → 构建配置加一行插件 → 根组件挂载编辑层组件 → 复制 Skill 并在 AGENTS.md 中加指向 → 忽略 `.03kind/`；自动修改失败时输出手动步骤。
- `init` 对项目源码的改动不超过 2 处（构建配置一行、挂载一行）；Skill、AGENTS.md 中的一行、`.gitignore` 中的一行不计入源码改动。
- `doctor`：检查各项安装，跑一次正式构建并确认产物中不含编辑层代码。
- `remove`：把 `init` 所做的全部修改逐项撤回（构建配置、挂载、开发依赖、Skill、AGENTS.md 中的一行、`.gitignore` 中的一行），并删除 `.03kind/`（含画布外的图层）；执行后 git diff 为空。有未落地的改动或正在落地的一轮时拒绝执行，并提示先落地或放弃。
- 页面加载时只加载切换按钮（≤ 10KB），编辑层其余部分在第一次进入编辑模式时加载。

### 技术范围

- 框架：React 18 / 19，配 Vite 或 Next.js App Router（Turbopack 与 Webpack）。
- 样式：Tailwind v3 / v4、普通 CSS、CSS Modules。
- 设计变量来源：CSS 变量、Tailwind v4 主题、Tailwind v3 配置。

## Testing Decisions

### 好测试的标准

- 只测外部行为：给定输入页面和设计师操作，断言画布呈现结果、改动单内容和命令行输出；不断言内部数据结构或私有函数。
- 测试应在重构内部实现后依然成立。

### 测试接缝

- **主接缝：示例项目 + 编辑层界面 → `.03kind/` 与命令行输出。** 在浏览器中驱动真实的编辑层操作，断言画布 DOM、改动单与 `claim` 输出。覆盖绝大部分行为，包括冻结、图层翻译、拖拽、Stack 合成与解散、推广、自动保存与恢复、播放、锁定与进度、正式构建零残留。
- **辅接缝 1：编辑命令。** 在固定的画布副本上直接调用编辑命令，断言画布结果与改动记录，用于高密度覆盖合成 Stack 推断、解散定位、合并规则、设计语言到样式的对应等算法分支。
- **辅接缝 2：源码标记转换。** 输入样例源码，断言输出源码（快照比对），覆盖各种 JSX 写法与第三方依赖的排除。
- 「Agent 好像停了」的阈值约 9 分钟：测量台的剧本用 Playwright 的时钟把页面的时间往前拨（编辑层里没有为测试留的开关，设计师看不到），`TK_BENCH_STALL_REAL=1` 时「做到一半退出」按真实时间等满阈值（ticket 67）。

### 示例项目

- Vite + React 19 + Tailwind v4
- Vite + React 18 + Tailwind v3
- Next.js App Router + CSS Modules

### 性能测试

- 按 [docs/goals.md](../../docs/goals.md) 的 Flex 指标：用约 5000 个元素的大页面、三个视图同时显示，测量进入编辑模式耗时（≤ 150ms）、改数值到画面变化（≤ 2 帧；2026-10-30 设计师决定，原为 ≤ 1 帧）、拖拽帧率（60fps）；另测页面加载时切换按钮的体积（≤ 10KB）。按 Robust 指标另测三项，都不能出现 long task：认领期间每次热更新的核对（ticket 64）；在平板视图改动、读页面在各段的值，设计师停手和改完马上回预览模式两种（ticket 65 补修）；编辑模式中没认领时，每次热更新后判断页面有没有变（ticket 78；画布上有「只改这一处」的改动时，含每次代码变化开始时记下其他使用处的值，ticket 82）；认领后刷新页面，按存下的值找回其他使用处（ticket 82）；认领手机断点上的改动后每次热更新的核对，含范围外宽度的值（ticket 104）。

### Agent 验收（发布前手动）

- 一套约 10 个标准场景，每种改动至少出现一次，分别交给 Claude Code、Codex、Cursor 落地，按 [docs/goals.md](../../docs/goals.md) 统计：1:1 落地率（以 `done` 核对为准）、虚假的 ✓、设计变量使用率、每条改动的工具调用次数与全仓搜索次数、报告格式合规情况。
- 安装验收：三家 Agent 各在 10 个全新项目上从 Guide 开始安装，统计成功率与耗时；再运行 `remove`，确认 git diff 为空。

## Out of Scope

- 约束 / 钉住（已承诺，第一版之后）。ticket 75、79 只在改尺寸、移动时保留页面原有的定位方式，不是约束功能（没有设约束的界面，父容器变化时子图层不按约束跟着变）。
- 按断点的结构性改动（换容器、合成 Stack 等只能作用于所有视图）
- 视图中重新运行靠脚本判断宽度的响应式
- 单个实例的覆盖（已承诺）
- 组件沙盒：状态（悬停、按下、聚焦）、props 组合（像 Figma variants）、组件级动效的浏览与调整（第二版核心，ADR 0007；第一版只在选中工具条中预留入口位置，单独立项）
- 插入或替换图片（已承诺）
- 编辑层直接把简单改动写进源码（已承诺）
- 锥形渐变
- 新建 Grid、Stack 与 Grid 互相转换
- 重命名图层
- 改动单附带截图（待评估）
- Vue、Svelte 等其他框架；styled-components、Emotion 等 CSS-in-JS（待评估）
- 中文界面（待评估）
- MCP、发送按钮；在编辑层界面上标出落地结果的不一致（`done` 时的核对只把结果告诉 Agent，见 ADR 0006）
- 线上预览地址或生产环境中运行
- 多人协作、账号、云端、使用数据统计

## Further Notes

- 成功标准以 [docs/goals.md](../../docs/goals.md) 为准（Light、Flex、Faithful、Reversible 四组指标）；此外一轮完整修改（自由拖拽 → 合成 Stack → 属性调整 → 写生成说明）能走通；MIT 许可开源。
- 功能取舍按 goals.md 中的判定题：这个功能，是否帮助设计师和 Agent 一起把界面细节调对？
- 主要风险：
  - 使用链读取依赖 React 内部字段，React 升级可能改变；已隔离在单一模块内。
  - 各 Agent 对 Skill 的遵守程度不同（进度汇报、报告格式），也可能不加载它；Skill 只留流程和报告格式，流程、写法和报告格式也都在命令的输出里（ADR 0013、ticket 65），并在验收中专门检查。
  - 竞品密集（Cursor、v0、Figma Make、Onlook 等），以及各类 Chrome 插件；差异化在于插件结构上做不到的三件事：懂代码（组件、使用处、设计变量）、能活渲染组件（组件沙盒）、闭环可核对（`done` 核对），以及不绑定 Agent、本地运行、一行安装、面向设计师。
- 编辑层界面先仿 Figma 风格实现，具体视觉设计后续再调。
